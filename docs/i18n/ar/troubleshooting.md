# استكشاف الأخطاء وإصلاحها

استخدم هذه الصفحة عندما تنجح عملية الترجمة بشكل غير متوقع، أو تفشل أثناء التكوين، أو تنتج مخرجات تحتاج إلى مراجعة.

## ابدأ هنا

1. شغّل أمرًا مُركزًا أولًا، مثل `translate -l "ko" -md`.
2. أضف `-d` لسجلات التصحيح في وحدة التحكم.
3. أضف `-s` لحفظ سجلات التصحيح تحت `<root-dir>/logs/`.
4. شغّل `co-op-review` بعد الترجمة للتحقق من حداثة المحتوى، والبنية، والروابط المحلية.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## أخطاء التكوين

### لا مزود لنموذج اللغة

خطأ:

```text
No language model configuration found.
```

الإصلاح:

- قم بتكوين Azure OpenAI أو OpenAI أو Anthropic.
- تحقق من وجود المتغيرات في البيئة التي يُشغل فيها الأمر.
- للاستخدام المحلي، ضعها في ملف `.env` في جذر المشروع.

انظر [التكوين](configuration.md).

### ترجمة الصور بدون Azure AI Vision

خطأ:

```text
Image translation requested but Azure AI Service is not configured.
```

الإصلاح:

- أضف `AZURE_AI_SERVICE_API_KEY`.
- أضف `AZURE_AI_SERVICE_ENDPOINT`.
- أو شغّل أمرًا نصيًا فقط مثل `translate -l "ko" -md`.

### مفتاح أو نقطة نهاية غير صالحة

الأعراض قد تشمل `401` أو أخطاء صلاحيات مكتومة، أو أخطاء وصول إلى نقطة النهاية.

الإصلاح:

- تأكد أن المفتاح ينتمي إلى نفس مورد Azure الخاص بنقطة النهاية.
- تأكد أن المورد يدعم Vision عند استخدام `-img`.
- تأكد أن اسم نشر Azure OpenAI وإصدار API يتطابقان مع نشرِك.
- شغّل مع سجلات التصحيح: `translate -l "ko" -md -d -s`.

## لم تُترجم أي ملفات

الأسباب الشائعة:

- الخيارات المحددة لا تتطابق مع ملفاتك.
- توجد بالفعل ملفات مترجمة موجودة.
- ملفات المصدر تحت دلائل مستبعدة.
- يتم تشغيل الأمر من جذر مشروع خاطئ.

التحققات:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

استخدم `--root-dir` عندما يتم تشغيل الأمر خارج جذر المشروع.

## سلوك الروابط غير المتوقع

تعتمد إعادة كتابة الروابط على أنواع المحتوى المختارة:

- `-nb` included: يمكن لروابط الدفاتر أن تشير إلى دفاتر مترجمة.
- `-nb` excluded: يمكن أن تظل روابط الدفاتر تشير إلى الدفاتر الأصلية.
- `-img` included: يمكن أن تشير روابط الصور إلى صور مترجمة.
- `-img` excluded: يمكن أن تظل روابط الصور تشير إلى الصور الأصلية.

قم بتشغيل ترجمة كاملة للمحتوى عندما يجب أن تفضل جميع الروابط الداخلية المخرجات المترجمة:

```bash
translate -l "ko" -md -nb -img
```

قم بمراجعة الروابط بعد الترجمة:

```bash
co-op-review -l "ko"
```

## مشاكل في عرض Markdown

إذا ظهر Markdown المترجم بشكل غير صحيح:

- تحقق من أن frontmatter يبدأ وينتهي بـ `---`.
- تحقق من أن عدد أسوار الشيفرة (code fences) متطابق بين الملفات المصدر والمترجمة.
- شغّل `co-op-review` للوقوف على مشاكل البنية الشائعة.
- أعد ترجمة الملف المحدد إذا كان الناتج قد تَلف.

```bash
co-op-review -l "ko" --format github
```

## تم تشغيل GitHub Action لكن لم يُنشأ طلب سحب

إذا أفاد `peter-evans/create-pull-request` بأن الفرع ليس أمام القاعدة، فإن سير العمل لم يجد ملفات للالتزام.

الأسباب المحتملة:

- تشغيل الترجمة لم يُنتج تغييرات.
- `.gitignore` يستبعد `translations/` أو `translated_images/` أو الدفاتر المترجمة.
- `add-paths` لا يطابق دلائل المخرجات المولدة.
- انتهت خطوة الترجمة مبكرًا.

الإصلاحات:

1. تأكد من وجود الملفات المولدة في `translations/` أو `translated_images/`.
2. تأكد أن `.gitignore` لا يتجاهل المخرجات المولدة.
3. استخدم `add-paths` المطابق:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. أضف مؤقتًا أعلام التصحيح إلى أمر الترجمة:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. تأكد أن أذونات سير العمل تتضمن:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## جودة الترجمة

قد تحتاج الترجمات الآلية إلى مراجعة بشرية. استخدم `evaluate` فقط إذا أردت تقييمًا تجريبيًا للجودة ومسارات إصلاح ذات ثقة منخفضة.

!!! warning "تجريبي"
    يمكن لـ`evaluate` أن يستخدم فحوصات قائمة على القواعد وفحوصات تعتمد على LLM، وقد يتغير نموذج التقييم وسلوك البيانات الوصفية. أبقِه خارج بوابات CI المطلوبة ما لم يكن سير عملك مستعدًا للتغيّرات.

لإجراء فحوصات CI حتمية، استخدم `co-op-review` بدلاً من ذلك.
