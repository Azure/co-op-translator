# Превеждане, редактиране и преглед на малък проект

Започнете с два кратки Markdown файла и един целеви език. Ще видите къде се записват преводите, какво се случва когато източникът се промени и как да проверите резултата.

## Записани резултати

Примерът беше изпълнен на 19 септември 2026 г. с Co-op Translator 0.21.0 и Azure OpenAI (`gpt-5-mini`). Непроменените CLI команди бяха извикани чрез Click's `CliRunner`, използвайки събраната wheel и съществуващите Python зависимости.

| Стъпка | Резултат |
| --- | --- |
| Preview | Exit 0; няма заявка за превод от модел |
| Първоначален превод | Exit 0; 27.36 секунди |
| Първоначален преглед | Exit 0 |
| Редактиране на README и преглед | Exit 1; открит е остарял превод |
| Актуализиране на превода | Exit 0; 22.17 секунди |
| Преглед след актуализация | Exit 0; няма грешки или предупреждения |
| Неизменено ръководство | Идентични байтове преди и след обновяването на README |
| Изпълни отново | Exit 0; идентични хешове за всички файлове с преводи |

Това са измервания от отделни изпълнения, а не гаранции за производителност. Времето за настройка е изключено; таксуването от доставчика не беше измервано. Изпълнение без промени все още може да извърши проверка на здравето на доставчика.

Прегледайте [първоначалния превод](../../assets/demo/before.txt), [актуализирания превод](../../assets/demo/after.txt), [пълен diff на превода](../../assets/demo/update.diff), [остарял преглед](../../assets/demo/review-stale.txt), [окончателен преглед](../../assets/demo/review-after.txt), и [детайли на изпълнението](../../assets/demo/results.json). Пълният превод на файла може да промени други формулировки, както показва заловеният diff. И двата текстови артефакта запазват генерирания отказ от отговорност.

Човешкият преглед все още е важен: the captured update uses `[사용 가이드](guide.md)을`; корейската частица трябва да е `[사용 가이드](guide.md)를`. Текстовите артефакти запазват този изход непроменен, вместо да представят редактиран превод като изход от модела. Структурният преглед преминава въпреки този проблем с формулировката.

## 1. Подгответе малка папка

Използвайте Python 3.11–3.14 и [настройване на виртуална среда](configuration.md#local-runtime-setup). Инсталирайте версията използвана за този пример:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

Изтеглете [README.txt](../../assets/demo/README.txt) и [guide.txt](../../assets/demo/guide.txt) в тази папка, запазвайки ги като `README.md` и `guide.md`. Това са малки фикционални проектни документи; не е необходима инсталация на приложения.

README файлът включва блок с код и връзка към `guide.md`. Последното му изречение е:

```text
Notes are saved locally.
```

Запазете само тези два изходни документа в тази папка. Всички следващи команди се изпълняват в `translation-demo` и работят в Bash и PowerShell.

## 2. Преглед без идентификационни данни

```bash
translate -l "ko" -md --dry-run
```

Прегледът оценява обема преводна работа без извикване на модел или записване на преводи. Оценките за токени не са фактура за таксуване. Първото изпълнение трябва да идентифицира двата Markdown файла като нова работа.

## 3. Изберете доставчик и преведете

Конфигурирайте един доставчик, използвайки [ръководството за конфигурация](configuration.md): Azure OpenAI, OpenAI или Anthropic. Текстовият превод с OpenAI и Anthropic не изисква Azure акаунт. Услугите за изображения не са необходими за този пример.

Ако използвате локален `.env` файл, добавете `.env` към `.gitignore` на тази папка. Обажданията за превод използват вашия акаунт при доставчика и могат да доведат до такси.

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

Отворете `translations/ko/README.md` и `translations/ko/guide.md`. Проверете корейската формулировка, блока с код и връзката от преведения README към преведения guide. Формулировката на изхода варира в зависимост от модела.

`co-op-review` проверява свежестта, структурата и локалните връзки. Успешният резултат не сертифицира лингвистична точност. Разрешете всички докладвани грешки преди да продължите.

Запишете успешния базов статус с Git (конфигурирайте своята Git идентичност първо, ако е необходимо):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. Променете източника

В `README.md` заменете `Notes are saved locally.` с:

```text
Notes are saved locally as Markdown files.
```

Оставете `guide.md` непроменен. След това изпълнете:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

Прегледът трябва да отчете превода на README като остарял и да завърши неуспешно. Това е очакваното междинно състояние. Прегледът трябва да идентифицира работа за променения README.

## 5. Актуализирайте и прегледайте diff

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

Прегледайте реалния diff: по подразбиране CLI повторно превежда променения файл, така че моделът може да преразгледа и други формулировки в този файл. Непромененото ръководство не би трябвало да има diff. Прегледът вече не трябва да отчита README като остарял; разследвайте всички други открития вместо да ги игнорирате.

Запазването на ниво блок на човешки Markdown редакции изисква опционален доставчик на състояние за превод в [Python API](api.md). Това не е активирано от тези CLI команди.

## 6. Стартирайте отново без промени

Комитирайте обновения изход и превода:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

С текущите преводи и непроменена конфигурация, преводачът пропуска файловете. Последната Git команда трябва да не произведе diff и да завърши успешно.
