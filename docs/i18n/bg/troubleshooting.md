# Отстраняване на проблеми

Използвайте тази страница, когато преводът завърши успешно неочаквано, се провали по време на конфигурация или генерира резултат, който изисква преглед.

## Започнете тук

1. Пуснете първо целенасочена команда, например `translate -l "ko" -md`.
2. Добавете `-d` за логове за отстраняване на грешки в конзолата.
3. Добавете `-s`, за да запишете логовете за отстраняване на грешки под `<root-dir>/logs/`.
4. Стартирайте `co-op-review` след превода, за да проверите свежестта, структурата и локалните връзки.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## Грешки при конфигурация

### Няма доставчик на езиков модел

Грешка:

```text
No language model configuration found.
```

Решение:

- Конфигурирайте Azure OpenAI, OpenAI или Anthropic.
- Проверете дали променливите са в средата, където се изпълнява командата.
- За локална употреба ги поставете във `.env` в корена на проекта.

Вижте [Конфигурация](configuration.md).

### Превод на изображения без Azure AI Vision

Грешка:

```text
Image translation requested but Azure AI Service is not configured.
```

Решение:

- Добавете `AZURE_AI_SERVICE_API_KEY`.
- Добавете `AZURE_AI_SERVICE_ENDPOINT`.
- Или стартирайте команда само за текст, като `translate -l "ko" -md`.

### Неправилен ключ или крайна точка

Симптомите могат да включват `401`, скрити грешки за разрешения или грешки при достъп до крайната точка.

Решение:

- Потвърдете, че ключът принадлежи на същия Azure ресурс като крайната точка.
- Потвърдете, че ресурсът поддържа Vision при използване на `-img`.
- Потвърдете, че името на разгръщането в Azure OpenAI и версията на API съответстват на вашето разгръщане.
- Стартирайте с debug логове: `translate -l "ko" -md -d -s`.

## Няма преведени файлове

Чести причини:

- Избраните флагове не съответстват на вашите файлове.
- Вече съществуват преведени файлове.
- Изходните файлове са в изключени директории.
- Командата се изпълнява от грешния корен на проекта.

Проверки:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

Използвайте `--root-dir`, когато командата се изпълнява извън корена на проекта.

## Неочаквано поведение на връзките

Преписването на връзки зависи от избраните типове съдържание:

- `-nb` включен: връзките към тетрадки могат да сочат към преведени тетрадки.
- `-nb` изключен: връзките към тетрадки могат да останат сочещи към изходните тетрадки.
- `-img` включен: връзките към изображения могат да сочат към преведени изображения.
- `-img` изключен: връзките към изображения могат да останат сочещи към изходните изображения.

Извършете пълен превод на съдържанието, когато всички вътрешни връзки трябва да предпочитат преведените изходи:

```bash
translate -l "ko" -md -nb -img
```

Извършете преглед на връзките след превода:

```bash
co-op-review -l "ko"
```

## Проблеми с рендирането на Markdown

Ако преведеният Markdown се визуализира неправилно:

- Проверете дали frontmatter започва и завършва с `---`.
- Проверете дали броят на ограждащите линии за код съвпада между изходните и преведените файлове.
- Стартирайте `co-op-review`, за да откриете често срещани структурни проблеми.
- Преведете отново конкретния файл, ако изходът е бил повреден.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action се изпълни, но не беше създаден Pull Request

Ако `peter-evans/create-pull-request` съобщи, че клонът не е по-напред от базата, workflow-ът не е намерил файлове за комит.

Възможни причини:

- Преводът не е произвел промени.
- `.gitignore` изключва `translations/`, `translated_images/` или преведени тетрадки.
- `add-paths` не съвпада с генерираните директории за изход.
- Стъпката за превод приключи преждевременно.

Поправки:

1. Потвърдете, че генерираните файлове съществуват в `translations/` или `translated_images/`.
2. Потвърдете, че `.gitignore` не игнорира генерираните изходи.
3. Използвайте съответстващи `add-paths`:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. Временно добавете debug флагове към командата translate:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. Потвърдете, че разрешенията на workflow-а включват:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## Качество на превода

Машинните преводи може да изискват човешки преглед. Използвайте `evaluate` само когато искате експериментално оценяване на качеството и работни потоци за поправка при ниско доверие.

!!! warning "Експериментално"
    `evaluate` може да използва проверки, базирани на правила и на големи езикови модели (LLM), а неговият модел за оценяване и поведението на метаданните могат да се променят. Не го включвайте в задължителните CI етапи, освен ако вашият workflow не е подготвен за промени.

За детерминирани CI проверки вместо това използвайте `co-op-review`.
