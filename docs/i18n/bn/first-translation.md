# একটি ছোট প্রকল্প অনুবাদ, সম্পাদনা, এবং পর্যালোচনা করুন

দুইটি ছোট Markdown ফাইল এবং একটি লক্ষ্য ভাষা দিয়ে শুরু করুন। আপনি দেখতে পাবেন অনুবাদগুলি কোথায় লেখা হয়, উৎস পরিবর্তিত হলে কী ঘটে, এবং ফলাফল কীভাবে পরীক্ষা করবেন।

## রেকর্ডকৃত ফলাফল

এই উদাহরণটি 19 সেপ্টেম্বর 2026-এ Co-op Translator 0.21.0 এবং Azure OpenAI (`gpt-5-mini`) ব্যবহার করে চালানো হয়েছিল। অপরিবর্তিত CLI কমান্ডগুলো Click-এর `CliRunner` মাধ্যমে নির্মিত wheel এবং বিদ্যমান Python নির্ভরশীলতা ব্যবহার করে আহ্বান করা হয়েছিল।

| ধাপ | ফলাফল |
| --- | --- |
| প্রিভিউ | Exit 0; কোনো মডেল অনুবাদ অনুরোধ করা হয়নি |
| প্রাথমিক অনুবাদ | Exit 0; 27.36 সেকেন্ড |
| প্রাথমিক পর্যালোচনা | Exit 0 |
| README সম্পাদনা এবং পর্যালোচনা | Exit 1; পুরোনো অনুবাদ শনাক্ত হয়েছে |
| অনুবাদ আপডেট করুন | Exit 0; 22.17 সেকেন্ড |
| আপডেটের পরে পর্যালোচনা | Exit 0; কোনো ত্রুটি বা সতর্কতা নেই |
| পরিবর্তনহীন গাইড | README আপডেটের আগে ও পরে একই বাইট |
| আবার চালান | Exit 0; সমস্ত অনুবাদ ফাইলের হ্যাশ একই |

এগুলো একক রান পরিমাপ, পারফরম্যান্স গ্যারান্টি নয়। সেটআপ সময় অন্তর্ভুক্ত নয়; প্রদানকারীর বিলিং পরিমাপ করা হয়নি। পরিবর্তনহীন একটি রানও প্রদানকারীর স্বাস্থ্য পরীক্ষা করতে পারে।

দেখুন [প্রাথমিক অনুবাদ](../../assets/demo/before.txt), [আপডেট করা অনুবাদ](../../assets/demo/after.txt), [সম্পূর্ণ অনুবাদের ডিফ](../../assets/demo/update.diff), [অপচলিত পর্যালোচনা](../../assets/demo/review-stale.txt), [চূড়ান্ত পর্যালোচনা](../../assets/demo/review-after.txt), এবং [রান বিবরণ](../../assets/demo/results.json)। ক্যাপচার করা ডিফ যেমন দেখায়, পূর্ণ-ফাইল অনুবাদ অন্যান্য শব্দ পরিবর্তন করতে পারে। উভয় টেক্সট আর্টিফ্যাক্ট জেনারেট করা ডিসক্লেইমারটি বজায় রাখে।

মানব পর্যালোচনা এখনও গুরুত্বপূর্ণ: ক্যাপচার করা আপডেটটি `[사용 가이드](guide.md)을` ব্যবহার করেছে; কোরিয়ান পার্টিকেল হওয়া উচিত `[사용 가이드](guide.md)를`। টেক্সট আর্টিফ্যাক্টগুলো এই আউটপুট অপরিবর্তিত রেখে দেয়, মডেল আউটপুট হিসেবে সম্পাদিত অনুবাদ প্রদর্শন করার পরিবর্তে। গঠনগত পর্যালোচনা এই শব্দচয়নের সমস্যার সত্ত্বেও উত্তীর্ণ হয়।

## 1. একটি ছোট ফোল্ডার প্রস্তুত করুন

Python 3.11–3.14 ব্যবহার করুন এবং [ভার্চুয়াল পরিবেশ সেটআপ](configuration.md#local-runtime-setup)। এই উদাহরণের জন্য ব্যবহৃত সংস্করণ ইনস্টল করুন:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

এই ফোল্ডারে [README.txt](../../assets/demo/README.txt) এবং [guide.txt](../../assets/demo/guide.txt) ডাউনলোড করে `README.md` ও `guide.md` নামে সেভ করুন। এগুলি ছোট কাল্পনিক প্রকল্প ডকুমেন্ট; কোনো অ্যাপ্লিকেশন ইনস্টল করা প্রয়োজন নেই।

README-এ একটি কোড ব্লক এবং `guide.md`-এর একটি লিঙ্ক আছে। এর শেষ বাক্যটি হলো:

```text
Notes are saved locally.
```

এই ফোল্ডারে শুধু এই দুটি সোর্স ডকুমেন্ট রাখুন। পরবর্তী সকল কমান্ড `translation-demo`-এর ভিতরে চালানো হবে এবং Bash এবং PowerShell-এ কাজ করবে।

## 2. ক্রেডেনশিয়াল ছাড়াই প্রিভিউ

```bash
translate -l "ko" -md --dry-run
```

প্রিভিউ মডেল কল বা অনুবাদ লেখার ছাড়াই অনুবাদ কাজের পরিমাণ অনুমান করে। টোকেন অনুমানগুলি বিলিং কোটা নয়। প্রথম রানটি উভয় Markdown ফাইলকেই নতুন কাজ হিসেবে শনাক্ত করা উচিত।

## 3. একটি প্রদানকারী নির্বাচন করুন এবং অনুবাদ করুন

একটি প্রদানকারী কনফিগার করুন [কনফিগারেশন গাইড](configuration.md) অনুযায়ী: Azure OpenAI, OpenAI, বা Anthropic। OpenAI এবং Anthropic টেক্সট অনুবাদের জন্য Azure অ্যাকাউন্ট প্রয়োজন হয় না। এই উদাহরণের জন্য ইমেজ সেবা প্রয়োজন নেই।

যদি আপনি একটি লোকাল `.env` ফাইল ব্যবহার করেন, `.env`-কে এই ফোল্ডারের `.gitignore`-এ যোগ করুন। অনুবাদ কলগুলো আপনার প্রদানকারী অ্যাকাউন্ট ব্যবহার করে এবং চার্জ হতে পারে।

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

`translations/ko/README.md` এবং `translations/ko/guide.md` খুলুন। কোরিয়ান শব্দচয়ন, কোড ব্লক, এবং অনুবাদকৃত README থেকে অনুবাদকৃত গাইডে থাকা লিঙ্ক পরীক্ষা করুন। আউটপুটের শব্দচয়ন মডেল অনুযায়ী ভিন্ন হতে পারে।

`co-op-review` তাজা অবস্থা, গঠন, এবং লোকাল লিঙ্কগুলো পরীক্ষা করে। পাস হওয়া ফলাফল ভাষাগত সঠিকতা নিশ্চিত করে না। চলার আগে রিপোর্ট করা যেকোনো ত্রুটি সমাধান করুন।

Git দিয়ে সফল বেসলাইন রেকর্ড করুন (প্রয়োজন হলে আগে আপনার Git পরিচয় কনফিগার করুন):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. উৎস পরিবর্তন করুন

`README.md`-এ, `Notes are saved locally.` এর পরিবর্তে:

```text
Notes are saved locally as Markdown files.
```

`guide.md` অপরিবর্তিত রাখুন। তারপর চালান:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

পর্যালোচনা README অনুবাদকে পুরোনো হিসেবে রিপোর্ট করবে এবং অসফলভাবে বেরিয়ে আসবে। এটি প্রত্যাশিত মধ্যবর্তী অবস্থা। প্রিভিউ পরিবর্তিত README-এর জন্য কাজ সনাক্ত করা উচিত।

## 5. আপডেট করুন এবং ডিফ পরীক্ষা করুন

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

বাস্তব ডিফ পরীক্ষা করুন: ডিফল্ট CLI পরিবর্তিত ফাইলটি পুনরায় অনুবাদ করে, তাই মডেল সেই ফাইলে অন্যান্য শব্দচয়নও সংশোধন করতে পারে। অপরিবর্তিত গাইডে কোনো ডিফ থাকা উচিত নয়। পর্যালোচনা আর README-কে পুরোনো বলে রিপোর্ট করা উচিত নয়; অন্য যে কোনো ফলাফল উপেক্ষা না করে তদন্ত করুন।

ব্লক-স্তরের মানব Markdown সম্পাদনা সংরক্ষণ করতে [Python API](api.md)-এ একটি ঐচ্ছিক অনুবাদ স্টেট প্রদানকারী প্রয়োজন। এটি এই CLI কমান্ডগুলিতে সক্রিয় নয়।

## 6. পরিবর্তন ছাড়া আবার চালান

আপডেটকৃত উৎস এবং অনুবাদ কমিট করুন:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

বর্তমান অনুবাদ এবং অপরিবর্তিত কনফিগারেশনের সাথে, ট্রান্সলেটর ফাইলগুলো স্কিপ করে। চূড়ান্ত Git কমান্ড কোন ডিফ উৎপন্ন করবে না এবং সফলভাবে বেরিয়ে আসবে।
