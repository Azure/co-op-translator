# সমস্যা সমাধান

এই পৃষ্ঠা ব্যবহার করুন যখন অনুবাদ চালান অনাকাঙ্ক্ষিতভাবে সফল হয়, কনফিগারেশনের সময় ব্যর্থ হয়, অথবা এমন আউটপুট তৈরি করে যা পর্যালোচনার প্রয়োজন।

## এখানে শুরু করুন

1. প্রথমে একটি নির্দিষ্ট কমান্ড চালান, যেমন `translate -l "ko" -md`.
2. কনসোল ডিবাগ লগের জন্য `-d` যোগ করুন।
3. ডিবাগ লগগুলো `<root-dir>/logs/`-এ সংরক্ষণের জন্য `-s` যোগ করুন।
4. অনুবাদের পরে সাম্প্রতিকতা, কাঠামো এবং স্থানীয় লিঙ্ক যাচাই করতে `co-op-review` চালান।

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## কনফিগারেশন ত্রুটি

### কোনো ভাষা মডেল প্রদানকারী নেই

ত্রুটি:

```text
No language model configuration found.
```

সমাধান:

- Azure OpenAI, OpenAI, অথবা Anthropic কনফিগার করুন।
- যাচাই করুন যে ভ্যারিয়েবলগুলো সেই পরিবেশে রয়েছে যেখানে কমান্ডটি চালানো হয়।
- লোকাল ব্যবহারের জন্য, এগুলো প্রজেক্ট রুটে `.env`-এ রাখুন।

দেখুন [কনফিগারেশন](configuration.md)।

### Azure AI Vision ছাড়া ইমেজ অনুবাদ

ত্রুটি:

```text
Image translation requested but Azure AI Service is not configured.
```

সমাধান:

- `AZURE_AI_SERVICE_API_KEY` যোগ করুন।
- `AZURE_AI_SERVICE_ENDPOINT` যোগ করুন।
- অথবা `translate -l "ko" -md` এর মতো কেবল টেক্সট-নির্ভর কমান্ড চালান।

### অবৈধ কী বা এন্ডপয়েন্ট

লক্ষণগুলির মধ্যে থাকতে পারে `401`, অনুমতি সম্পর্কিত redacted ত্রুটি, বা এন্ডপয়েন্ট অ্যাক্সেস ত্রুটি।

সমাধান:

- নিশ্চিত করুন কীটি একই Azure রিসোর্সের অন্তর্গত যেখানে এন্ডপয়েন্ট রয়েছে।
- `-img` ব্যবহার করলে রিসোর্সটি Vision সমর্থন করে কি না নিশ্চিত করুন।
- নিশ্চিত করুন Azure OpenAI ডিপ্লয়মেন্টের নাম এবং API সংস্করণ আপনার ডিপ্লয়মেন্টের সাথে মেলে।
- ডিবাগ লগসহ চালান: `translate -l "ko" -md -d -s`.

## কোনো ফাইল অনুবাদ করা হয়নি

সাধারণ কারণসমূহ:

- নির্বাচিত ফ্ল্যাগগুলো আপনার ফাইলগুলোর সঙ্গে মেলে না।
- ইতিমধ্যেই অনুবাদ করা ফাইলগুলি উপস্থিত আছে।
- সোর্স ফাইলগুলো বাদ দেওয়া ডিরেক্টরির অধীনে রয়েছে।
- কমান্ডটি ভুল প্রজেক্ট রুট থেকে চালানো হচ্ছে।

পরীক্ষাসমূহ:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

প্রজেক্ট রুটের বাইরে কমান্ড চালানো হলে `--root-dir` ব্যবহার করুন।

## অপ্রত্যাশিত লিঙ্ক আচরণ

লিঙ্ক পুনর্লিখন নির্বাচিত কনটেন্ট টাইপগুলোর উপর নির্ভর করে:

- `-nb` অন্তর্ভুক্ত: নোটবুক লিংকগুলো অনুবাদে করা নোটবুকের দিকে নির্দেশ করতে পারে।
- `-nb` বাদ: নোটবুক লিঙ্কগুলো সোর্স নোটবুকগুলোর দিকে থেকেই যেতে পারে।
- `-img` অন্তর্ভুক্ত: ইমেজ লিঙ্কগুলো অনুবাদকৃত ইমেজগুলোর দিকে নির্দেশ করতে পারে।
- `-img` বাদ: ইমেজ লিঙ্কগুলো সোর্স ইমেজের দিকে থেকেই থাকতে পারে।

যখন সকল অভ্যন্তরীণ লিঙ্ক অনুবাদকৃত আউটপুটকে অগ্রাধিকার দেওয়া উচিত, তখন একটি পূর্ণ কনটেন্ট অনুবাদ চালান:

```bash
translate -l "ko" -md -nb -img
```

অনুবাদের পরে লিঙ্ক রিভিউ চালান:

```bash
co-op-review -l "ko"
```

## মার্কডাউন রেন্ডারিং সমস্যা

যদি অনুবাদকৃত Markdown ঠিকমতো রেন্ডার না হয়:

- যাচাই করুন যে frontmatter `---` দিয়ে শুরু ও শেষ হচ্ছে।
- যাচাই করুন যে কোড ফেন্সের সংখ্যাগুলি সোর্স এবং অনুবাদকৃত ফাইলগুলিতে মিলছে।
- সাধারণ কাঠামোগত সমস্যাগুলি ধরতে `co-op-review` চালান।
- আউটপুট ক্ষতিগ্রস্ত হলে নির্দিষ্ট ফাইলটি পুনরায় অনুবাদ করুন।

```bash
co-op-review -l "ko" --format github
```

## GitHub Action চালানো হয়েছে কিন্তু কোনো Pull Request তৈরি করা হয়নি

যদি `peter-evans/create-pull-request` রিপোর্ট করে যে শাখাটি base-এর চেয়ে এগিয়ে নেই, তাহলে ওয়ার্কফ্লো কমিট করার জন্য কোনো ফাইল খুঁজে পায়নি।

সম্ভাব্য কারণগুলো:

- অনুবাদ চালান কোন পরিবর্তন তৈরি করেনি।
- `.gitignore` `translations/`, `translated_images/`, অথবা অনুবাদকৃত নোটবুকগুলোকে বাদ দেয়।
- `add-paths` জেনারেট করা আউটপুট ডিরেক্টরিগুলোর সাথে মেলে না।
- অনুবাদ ধাপটি অকালেই শেষ হয়েছে।

সমাধানসমূহ:

1. নিশ্চিত করুন যে `translations/` বা `translated_images/`-এ জেনারেট করা ফাইলগুলো বিদ্যমান আছে।
2. নিশ্চিত করুন `.gitignore` জেনারেট করা আউটপুটগুলোকে ইগনোর করে না।
3. মেলে এমন `add-paths` ব্যবহার করুন:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. অস্থায়ীভাবে translate কমান্ডে ডিবাগ ফ্ল্যাগ যোগ করুন:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. নিশ্চিত করুন ওয়ার্কফ্লো অনুমতিগুলো অন্তর্ভুক্ত করে:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## অনুবাদের গুণমান

মেশিন অনুবাদগুলোতে মানুষের পর্যালোচনা প্রয়োজন হতে পারে। শুধুমাত্র তখনই `evaluate` ব্যবহার করুন যখন আপনি পরীক্ষামূলক মান স্কোরিং এবং কম-নিশ্চিততার রিপেয়ার ওয়ার্কফ্লো চান।

!!! warning "Experimental"
    `evaluate` রুল-ভিত্তিক এবং LLM-ভিত্তিক চেক ব্যবহার করতে পারে, এবং এর স্কোরিং মডেল ও মেটাডাটা আচরণ পরিবর্তিত হতে পারে। পরিবর্তনের জন্য আপনার ওয়ার্কফ্লো প্রস্তুত না হলে এটি প্রয়োজনীয় CI গেটে রাখবেন না।

ডিটারমিনিস্টিক CI চেকগুলোর জন্য `co-op-review` ব্যবহার করুন।
