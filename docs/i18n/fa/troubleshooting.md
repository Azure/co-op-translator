# رفع اشکال

از این صفحه زمانی استفاده کنید که اجرای ترجمه به‌طور غیرمنتظره موفق می‌شود، در طول پیکربندی شکست می‌خورد، یا خروجی‌ای تولید می‌کند که نیاز به بازبینی دارد.

## از اینجا شروع کنید

1. ابتدا یک دستور متمرکز اجرا کنید، مانند `translate -l "ko" -md`.
2. برای لاگ‌های دیباگ کنسول، `-d` را اضافه کنید.
3. برای ذخیره لاگ‌های دیباگ در `<root-dir>/logs/`، `-s` را اضافه کنید.
4. پس از ترجمه `co-op-review` را اجرا کنید تا تازگی، ساختار و لینک‌های محلی بررسی شوند.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## خطاهای پیکربندی

### ارائه‌دهنده مدل زبان وجود ندارد

خطا:

```text
No language model configuration found.
```

رفع:

- Azure OpenAI، OpenAI یا Anthropic را پیکربندی کنید.
- بررسی کنید متغیرها در محیطی که دستور اجرا می‌شود وجود داشته باشند.
- برای استفاده محلی، آن‌ها را در `.env` در ریشه پروژه قرار دهید.

به [پیکربندی](configuration.md) مراجعه کنید.

### ترجمه تصویر بدون Azure AI Vision

خطا:

```text
Image translation requested but Azure AI Service is not configured.
```

رفع:

- متغیر `AZURE_AI_SERVICE_API_KEY` را اضافه کنید.
- متغیر `AZURE_AI_SERVICE_ENDPOINT` را اضافه کنید.
- یا یک دستور فقط متنی اجرا کنید، مانند `translate -l "ko" -md`.

### کلید یا نقطه‌پایان نامعتبر

علائم می‌توانند شامل `401`، خطاهای مجوزی که محو شده‌اند، یا خطاهای دسترسی به نقطه‌پایان باشند.

رفع:

- تأیید کنید کلید به همان منبع Azure که نقطه‌پایان دارد تعلق دارد.
- تأیید کنید منبع هنگام استفاده از `-img` از Vision پشتیبانی می‌کند.
- تأیید کنید نام استقرار Azure OpenAI و نسخه API با استقرار شما مطابقت دارند.
- با لاگ دیباگ اجرا کنید: `translate -l "ko" -md -d -s`.

## هیچ فایلی ترجمه نشد

علل شایع:

- گزینه‌های انتخاب‌شده با فایل‌های شما مطابقت ندارند.
- فایل‌های ترجمه‌شده موجود از قبل حضور دارند.
- فایل‌های منبع در فهرست‌های حذف‌شده قرار دارند.
- دستور از ریشه پروژه اشتباه اجرا می‌شود.

بررسی‌ها:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

هنگامی که دستور خارج از ریشه پروژه اجرا می‌شود از `--root-dir` استفاده کنید.

## رفتار غیرمنتظره لینک‌ها

بازنویسی لینک به نوع محتوای انتخاب‌شده بستگی دارد:

- `-nb` included: لینک‌های نوت‌بوک می‌توانند به نوت‌بوک‌های ترجمه‌شده اشاره کنند.
- `-nb` excluded: لینک‌های نوت‌بوک می‌توانند به نوت‌بوک‌های منبع باقی بمانند.
- `-img` included: لینک‌های تصاویر می‌توانند به تصاویر ترجمه‌شده اشاره کنند.
- `-img` excluded: لینک‌های تصاویر می‌توانند به تصاویر منبع باقی بمانند.

هنگامی که تمام لینک‌های داخلی باید خروجی‌های ترجمه‌شده را ترجیح دهند، یک ترجمه کامل محتوا اجرا کنید:

```bash
translate -l "ko" -md -nb -img
```

پس از ترجمه، بازبینی لینک را اجرا کنید:

```bash
co-op-review -l "ko"
```

## مشکلات رندر کردن Markdown

اگر Markdown ترجمه‌شده به‌درستی رندر نمی‌شود:

- بررسی کنید frontmatter با `---` شروع و پایان یابد.
- بررسی کنید تعداد محدوده‌های کد (code fence) بین فایل منبع و فایل ترجمه‌شده مطابقت داشته باشد.
- برای پیدا کردن مسائل ساختاری رایج `co-op-review` را اجرا کنید.
- اگر خروجی خراب شده بود، آن فایل خاص را دوباره ترجمه کنید.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action اجرا شد اما هیچ درخواست Pull ایجاد نشد

اگر `peter-evans/create-pull-request` گزارش می‌دهد که شاخه جلوتر از base نیست، جریان کاری هیچ فایلی برای commit پیدا نکرده است.

دلایل محتمل:

- اجرای ترجمه هیچ تغییری تولید نکرد.
- فایل `.gitignore` مسیرهای `translations/`، `translated_images/` یا نوت‌بوک‌های ترجمه‌شده را حذف می‌کند.
- `add-paths` با دایرکتوری‌های خروجی تولیدشده مطابقت ندارد.
- مرحله ترجمه زودتر از موعد خاتمه یافته است.

راه‌حل‌ها:

1. تأیید کنید فایل‌های تولیدشده در `translations/` یا `translated_images/` وجود دارند.
2. تأیید کنید `.gitignore` خروجی‌های تولیدشده را نادیده نمی‌گیرد.
3. از `add-paths` منطبق استفاده کنید:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. موقتاً گزینه‌های دیباگ را به دستور translate اضافه کنید:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. تأیید کنید مجوزهای جریان کاری شامل موارد زیر هستند:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## کیفیت ترجمه

ترجمه‌های ماشینی ممکن است نیاز به بازبینی انسانی داشته باشند. از `evaluate` فقط زمانی استفاده کنید که مایل به دریافت امتیازدهی کیفی آزمایشی و جریان‌های کاری تعمیر با اطمینان پایین هستید.

!!! warning "Experimental"
    `evaluate` می‌تواند از بررسی‌های مبتنی بر قوانین و مبتنی بر LLM استفاده کند، و مدل امتیازدهی و رفتار متادیتای آن ممکن است تغییر کند. آن را از دروازه‌های CI اجباری خارج نگه دارید مگر اینکه جریان کاری شما برای تغییرات آماده باشد.

برای بررسی‌های قطعی CI، از `co-op-review` استفاده کنید.
