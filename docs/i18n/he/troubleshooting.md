# פתרון תקלות

השתמש בעמוד זה כשריצת תרגום מצליחה באופן בלתי צפוי, נכשלת במהלך תצורה, או מייצרת פלט שדורש סקירה.

## התחל כאן

1. הרץ קודם פקודה ממוקדת, כגון `translate -l "ko" -md`.
2. הוסף `-d` ליומני דיבוג בקונסול.
3. הוסף `-s` כדי לשמור את יומני הדיבוג תחת `<root-dir>/logs/`.
4. הרץ את `co-op-review` לאחר התרגום כדי לבדוק רעננות, מבנה וקישורים מקומיים.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## שגיאות תצורה

### אין ספק שירות מודל שפה

שגיאה:

```text
No language model configuration found.
```

תיקון:

- הגדר את Azure OpenAI, OpenAI, או Anthropic.
- וודא שהמשתנים נמצאים בסביבה שבה רצה הפקודה.
- לשימוש מקומי, הנח אותם בקובץ `.env` בשורש הפרויקט.

ראה [תצורה](configuration.md).

### תרגום תמונות ללא Azure AI Vision

שגיאה:

```text
Image translation requested but Azure AI Service is not configured.
```

תיקון:

- הוסף את `AZURE_AI_SERVICE_API_KEY`.
- הוסף את `AZURE_AI_SERVICE_ENDPOINT`.
- או הרץ פקודה שמטפלת בטקסט בלבד כגון `translate -l "ko" -md`.

### מפתח או נקודת קצה לא תקינים

התסמינים יכולים לכלול `401`, שגיאות הרשאה מוצנעות, או שגיאות גישה לנקודת הקצה.

תיקון:

- וודא שהמפתח שייך לאותו משאב Azure כמו נקודת הקצה.
- ודא שהמשאב תומך ב-Vision כשמשתמשים ב-`-img`.
- ודא ששם ה-deployment של Azure OpenAI וגרסת ה-API תואמים לפריסה שלך.
- הרץ עם יומני דיבוג: `translate -l "ko" -md -d -s`.

## לא תורגמו קבצים

גורמים נפוצים:

- הדגלים שנבחרו אינם תואמים לקבצים שלך.
- קיימים כבר קבצים מתורגמים.
- קבצי המקור נמצאים בתיקיות שהוחרגו.
- הפקודה מורצת מתוך שורש פרויקט לא נכון.

בדיקות:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

השתמש ב-`--root-dir` כאשר מריצים את הפקודה מחוץ לשורש הפרויקט.

## התנהגות קישורים לא צפויה

שכתוב קישורים תלוי בסוגי התוכן שנבחרו:

- `-nb` כלול: קישורי מחברות יכולים להפנות למחברות מתורגמות.
- `-nb` לא כלול: קישורי מחברות עשויים להישאר מצביעים על מחברות המקור.
- `-img` כלול: קישורי תמונה יכולים להפנות לתמונות מתורגמות.
- `-img` לא כלול: קישורי תמונה יכולים להישאר מפנים לתמונות המקור.

הרץ תרגום תוכן מלא כאשר כל הקישורים פנימיים צריכים להעדיף את הפלטים המתורגמים:

```bash
translate -l "ko" -md -nb -img
```

הרץ בדיקת קישורים לאחר התרגום:

```bash
co-op-review -l "ko"
```

## בעיות בהצגת Markdown

אם Markdown מתורגם מוצג לא נכון:

- בדוק ש-frontmatter מתחיל ומסתיים ב-`---`.
- בדוק שמספר גדרות הקוד (code fence) תואם בין הקובץ המקור לקובץ המתורגם.
- הרץ `co-op-review` כדי לתפוס בעיות מבנה נפוצות.
- תרגם מחדש את הקובץ הספציפי אם הפלט נפגם.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action הופעל אך לא נוצר Pull Request

אם `peter-evans/create-pull-request` מדווח שהסניף אינו מקדים את הבסיס, ה-workflow לא מצא קבצים להתחייב עליהם.

גורמים סבירים:

- ריצת התרגום לא ייצרה שינויים.
- `.gitignore` מחריג את `translations/`, `translated_images/`, או מחברות מתורגמות.
- `add-paths` אינו תואם את תיקיות הפלט שנוצרו.
- שלב התרגום יצא מוקדם.

תיקונים:

1. אשר שקבצים שנוצרו קיימים ב-`translations/` או `translated_images/`.
2. אשר ש-`.gitignore` אינו מתעלם מפלטים שנוצרו.
3. השתמש ב-`add-paths` תואם:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. הוסף זמנית דגלי דיבוג לפקודת התרגום:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. אשר שההרשאות של ה-workflow כוללות:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## איכות התרגום

תרגומים מכונתיים עשויים להזדקק לביקורת אנושית. השתמש ב-`evaluate` רק אם אתה רוצה דירוג איכות ניסיוני ותהליכי תיקון לביצועים בעלי ביטחון נמוך.

!!! warning "נסיוני"
    `evaluate` יכול להשתמש בבדיקות מבוססות חוקים ובבדיקות מבוססות LLM, ודגם הדירוג שלו והתנהגות המטא-נתונים שלו עלולים להשתנות. השאר אותו מחוץ לשערי ה-CI הנדרשים אלא אם תהליך העבודה שלך מוכן לשינויים.

לבדיקות CI דטרמיניסטיות, השתמש ב-`co-op-review` במקום.
