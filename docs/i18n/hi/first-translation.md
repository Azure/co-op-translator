# एक छोटे प्रोजेक्ट का अनुवाद, संपादन और समीक्षा करें

दो छोटी Markdown फ़ाइलों और एक लक्ष्य भाषा के साथ शुरू करें। आप देखेंगे कि अनुवाद कहाँ लिखे जाते हैं, स्रोत बदलने पर क्या होता है, और परिणाम की जाँच कैसे करें।

## रिकॉर्ड किए गए परिणाम

यह उदाहरण 19 सितंबर, 2026 को Co-op Translator 0.21.0 और Azure OpenAI (`gpt-5-mini`) के साथ चलाया गया था। बिना संशोधित CLI कमांड Click के `CliRunner` के माध्यम से निर्मित wheel और मौजूदा Python निर्भरताओं का उपयोग करके बुलाए गए थे।

| चरण | परिणाम |
| --- | --- |
| पूर्वावलोकन | Exit 0; कोई मॉडल अनुवाद का अनुरोध नहीं किया गया |
| प्रारंभिक अनुवाद | Exit 0; 27.36 सेकंड |
| प्रारंभिक समीक्षा | Exit 0 |
| README संपादित करें और समीक्षा करें | Exit 1; पुराना अनुवाद पाया गया |
| अनुवाद अपडेट करें | Exit 0; 22.17 सेकंड |
| अपडेट के बाद समीक्षा | Exit 0; कोई त्रुटि या चेतावनी नहीं |
| बिना बदलाव के गाइड | README अपडेट से पहले और बाद में बाइट्स समान |
| फिर से चलाएँ | Exit 0; सभी अनुवाद फ़ाइलों के लिए समान हैश |

ये व्यक्तिगत रन मापन हैं, प्रदर्शन की गारंटी नहीं। सेटअप समय शामिल नहीं है; प्रदाता बिलिंग को मापा नहीं गया। बिना बदलाव का रन फिर भी प्रदाता स्वास्थ्य जांच कर सकता है।

निरीक्षण करें [प्रारंभिक अनुवाद](../../assets/demo/before.txt), [अपडेट किया गया अनुवाद](../../assets/demo/after.txt), [पूर्ण अनुवाद अंतर](../../assets/demo/update.diff), [अप्रचलित समीक्षा](../../assets/demo/review-stale.txt), [अंतिम समीक्षा](../../assets/demo/review-after.txt), और [रन विवरण](../../assets/demo/results.json)। पूरी फ़ाइल के अनुवाद से अन्य शब्दावली बदल सकती है, जैसा कि कैप्चर किया गया diff दिखाता है। दोनों टेक्स्ट आर्टिफैक्ट उत्पन्न अस्वीकरण बनाए रखते हैं।

मानव समीक्षा अभी भी महत्वपूर्ण है: कैप्चर किए गए अपडेट में `[사용 가이드](guide.md)을` का उपयोग किया गया है; कोरियाई कण `[사용 가이드](guide.md)를` होना चाहिए। टेक्स्ट आर्टिफैक्ट इस आउटपुट को उसी रूप में रखते हैं बजाय इसके कि मॉडल आउटपुट के रूप में संपादित अनुवाद प्रस्तुत करें। इस शब्दावली समस्या के बावजूद संरचनात्मक समीक्षा उत्तीर्ण होती है।

## 1. एक छोटा फ़ोल्डर तैयार करें

Python 3.11–3.14 का उपयोग करें और [वर्चुअल एनवायरनमेंट सेटअप](configuration.md#local-runtime-setup)। इस उदाहरण में उपयोग किए गए संस्करण को इंस्टॉल करें:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

इस फ़ोल्डर में [README.txt](../../assets/demo/README.txt) और [guide.txt](../../assets/demo/guide.txt) डाउनलोड करें, इन्हें `README.md` और `guide.md` के रूप में सेव करें। ये छोटे काल्पनिक प्रोजेक्ट दस्तावेज़ हैं; किसी अनुप्रयोग की स्थापना की आवश्यकता नहीं है।

README में एक कोड ब्लॉक और `guide.md` के लिए एक लिंक शामिल है। इसकी अंतिम वाक्य है:

```text
Notes are saved locally.
```

इस फ़ोल्डर में केवल यही दो स्रोत दस्तावेज़ रखें। सभी अगले कमांड `translation-demo` के अंदर चलाए जाते हैं और Bash तथा PowerShell में काम करते हैं।

## 2. क्रेडेंशियल्स के बिना पूर्वावलोकन

```bash
translate -l "ko" -md --dry-run
```

पूर्वावलोकन मॉडल को कॉल किए बिना या अनुवाद लिखे बिना अनुवाद के काम का अनुमान लगाता है। टोकन अनुमान बिलिंग उद्धरण नहीं हैं। पहली रन को दोनों Markdown फ़ाइलों को नए काम के रूप में पहचानना चाहिए।

## 3. एक प्रदाता चुनें और अनुवाद करें

एक प्रदाता [कॉन्फ़िगरेशन गाइड](configuration.md) का उपयोग करके कॉन्फ़िगर करें: Azure OpenAI, OpenAI, या Anthropic. OpenAI और Anthropic टेक्स्ट अनुवाद के लिए Azure खाता आवश्यक नहीं है। इस उदाहरण के लिए इमेज सेवाएँ आवश्यक नहीं हैं।

यदि आप स्थानीय `.env` फ़ाइल का उपयोग करते हैं, तो `.env` को इस फ़ोल्डर के `.gitignore` में जोड़ें। अनुवाद कॉल आपके प्रदाता खाते का उपयोग करते हैं और चार्ज लग सकते हैं।

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

खोलें `translations/ko/README.md` और `translations/ko/guide.md`। कोरियन शब्दावली, कोड ब्लॉक, और अनुवादित README से अनुवादित गाइड के लिंक की जाँच करें। आउटपुट शब्दावली मॉडल के अनुसार भिन्न हो सकती है।

`co-op-review` ताजगी, संरचना, और स्थानीय लिंक चेक करता है। उत्तीर्ण परिणाम भाषाई सटीकता की पुष्टि नहीं करता। जारी रखने से पहले रिपोर्ट की गई किसी भी त्रुटि को हल करें।

सफल बेसलाइन को Git के साथ रिकॉर्ड करें (यदि आवश्यक हो तो पहले अपनी Git पहचान कॉन्फ़िगर करें):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. स्रोत बदलें

`README.md` में, `Notes are saved locally.` को बदलें:

```text
Notes are saved locally as Markdown files.
```

`guide.md` को अपरिवर्तित रखें। फिर चलाएँ:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

समीक्षा README अनुवाद को पुराना बताकर असफल निकास रिपोर्ट करनी चाहिए। यह अपेक्षित मध्यवर्ती स्थिति है। पूर्वावलोकन बदले README के लिए काम की पहचान करनी चाहिए।

## 5. अपडेट करें और डिफ़ का निरीक्षण करें

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

वास्तविक diff का निरीक्षण करें: डिफ़ॉल्ट CLI बदली गई फ़ाइल को फिर से अनुवाद करता है, इसलिए मॉडल उस फ़ाइल में अन्य शब्दावली भी संशोधित कर सकता है। बिना बदले गाइड में कोई diff नहीं होना चाहिए। समीक्षा अब README को पुराना बता कर रिपोर्ट नहीं करनी चाहिए; किसी भी अन्य निष्कर्ष की जाँच करें बजाय कि उन्हें अनदेखा करने के।

मानव Markdown संपादनों के ब्लॉक-स्तरीय संरक्षण के लिए [Python API](api.md) में एक वैकल्पिक अनुवाद स्थिति प्रदाता आवश्यक है। यह CLI कमांडों द्वारा सक्षम नहीं है।

## 6. बिना बदलाव के फिर से चलाएँ

अपडेट किए गए स्रोत और अनुवाद को कमिट करें:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

वर्तमान अनुवादों और अपरिवर्तित कॉन्फ़िगरेशन के साथ, अनुवादक फ़ाइलों को स्किप कर देता है। अंतिम Git कमांड कोई diff उत्पन्न नहीं करनी चाहिए और सफलतापूर्वक बाहर निकलना चाहिए।
