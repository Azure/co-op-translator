# समस्या निवारण

इस पृष्ठ का उपयोग तब करें जब अनुवाद प्रक्रिया अप्रत्याशित रूप से सफल हो जाए, कॉन्फ़िगरेशन के दौरान विफल हो या ऐसा आउटपुट उत्पन्न हो जो समीक्षा की आवश्यकता हो।

## यहां से शुरू करें

1. पहले एक केंद्रित कमांड चलाएँ, जैसे `translate -l "ko" -md`.
2. कंसोल डिबग लॉग्स के लिए `-d` जोड़ें.
3. डिबग लॉग्स को `<root-dir>/logs/` के अंतर्गत सेव करने के लिए `-s` जोड़ें.
4. ताज़गी, संरचना, और स्थानीय लिंक की जाँच करने के लिए अनुवाद के बाद `co-op-review` चलाएँ.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## कॉन्फ़िगरेशन त्रुटियाँ

### कोई भाषा मॉडल प्रदाता नहीं

त्रुटि:

```text
No language model configuration found.
```

समाधान:

- Azure OpenAI, OpenAI, या Anthropic को कॉन्फ़िगर करें.
- सत्यापित करें कि वेरिएबल्स उस वातावरण में हैं जहाँ कमांड चल रहा है.
- स्थानीय उपयोग के लिए, उन्हें प्रोजेक्ट रुट पर `.env` में रखें.

देखें [कॉन्फ़िगरेशन](configuration.md).

### Azure AI Vision के बिना छवि अनुवाद

त्रुटि:

```text
Image translation requested but Azure AI Service is not configured.
```

समाधान:

- `AZURE_AI_SERVICE_API_KEY` जोड़ें.
- `AZURE_AI_SERVICE_ENDPOINT` जोड़ें.
- या `translate -l "ko" -md` जैसे केवल-टेक्स्ट कमांड चलाएँ.

### अमान्य कुंजी या एंडपॉइंट

लक्षणों में `401`, रिडैक्ट किए गए परमीशन त्रुटियाँ, या एंडपॉइंट एक्सेस त्रुटियाँ शामिल हो सकती हैं.

समाधान:

- पुष्टि करें कि कुंजी उसी Azure संसाधन की है जो एंडपॉइंट से संबंधित है.
- जब `-img` का उपयोग कर रहे हों तो पुष्टि करें कि संसाधन Vision को सपोर्ट करता है.
- पुष्टि करें कि Azure OpenAI deployment नाम और API वर्शन आपकी डिप्लॉयमेंट से मेल खाते हैं.
- डिबग लॉग्स के साथ चलाएँ: `translate -l "ko" -md -d -s`.

## कोई फ़ाइलें अनुवादित नहीं हुईं

सामान्य कारण:

- चयनित फ्लैग आपकी फ़ाइलों से मेल नहीं खाते.
- पहले से अनुवादित फ़ाइलें मौजूद हैं.
- स्रोत फ़ाइलें निष्कासित निर्देशिकाओं के अंतर्गत हैं.
- कमांड गलत प्रोजेक्ट रुट से चल रही है.

जाँचें:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

जब कमांड प्रोजेक्ट रूट के बाहर चल रही हो तो `--root-dir` का उपयोग करें.

## अनपेक्षित लिंक व्यवहार

लिंक री-राइटिंग चयनित कंटेंट प्रकारों पर निर्भर करती है:

- `-nb` शामिल: नोटबुक लिंक अनुवादित नोटबुक की ओर इशारा कर सकते हैं.
- `-nb` बहिष्कृत: नोटबुक लिंक स्रोत नोटबुक की ओर बने रह सकते हैं.
- `-img` शामिल: छवि लिंक अनुवादित छवियों की ओर इशारा कर सकते हैं.
- `-img` बहिष्कृत: छवि लिंक स्रोत छवियों की ओर बने रह सकते हैं.

जब सभी आंतरिक लिंक अनुवादित आउटपुट को प्राथमिकता दें तो पूर्ण सामग्री अनुवाद चलाएँ:

```bash
translate -l "ko" -md -nb -img
```

अनुवाद के बाद लिंक समीक्षा चलाएँ:

```bash
co-op-review -l "ko"
```

## Markdown रेंडरिंग समस्याएँ

यदि अनुवादित Markdown गलत तरीके से रेंडर हो:

- जांचें कि फ्रंटमैटर `---` से शुरू और समाप्त होता है.
- जांचें कि कोड फेंस की गिनती स्रोत और अनुवादित फ़ाइलों के बीच मेल खाती है.
- सामान्य संरचना समस्याओं को पकड़ने के लिये `co-op-review` चलाएँ.
- यदि आउटपुट भ्रष्ट हो गया है तो विशिष्ट फ़ाइल को फिर से अनुवादित करें.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action चला लेकिन कोई Pull Request नहीं बनाया गया

यदि `peter-evans/create-pull-request` रिपोर्ट करता है कि ब्रांच बेस से आगे नहीं है, तो वर्कफ़्लो को कमिट करने के लिए कोई फ़ाइलें नहीं मिलीं.

संभावित कारण:

- अनुवाद प्रक्रिया ने कोई परिवर्तन पैदा नहीं किया.
- `.gitignore` `translations/`, `translated_images/`, या अनुवादित नोटबुक्स को बहिष्कृत करता है.
- `add-paths` जनरेट किए गए आउटपुट डायरेक्टरीज़ से मेल नहीं खाता.
- अनुवाद स्टेप समय से पहले समाप्त हो गया.

समाधान:

1. पुष्टि करें कि `translations/` या `translated_images/` में जनरेट की गई फाइलें मौजूद हैं.
2. पुष्टि करें कि `.gitignore` जनरेट किए गए आउटपुट्स को इग्नोर नहीं कर रहा है.
3. मेल खाते `add-paths` का उपयोग करें:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. अस्थायी रूप से translate कमांड में डिबग फ्लैग जोड़ें:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. पुष्टि करें कि वर्कफ़्लो अनुमतियाँ शामिल हैं:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## अनुवाद गुणवत्ता

मशीन अनुवादों को मानव समीक्षा की आवश्यकता हो सकती है। केवल तब `evaluate` का उपयोग करें जब आप प्रायोगिक गुणवत्ता स्कोरिंग और कम-विश्वास मरम्मत वर्कफ़्लोज़ चाहते हों.

!!! warning "Experimental"
    `evaluate` नियम-आधारित और LLM-आधारित चेक्स का उपयोग कर सकता है, और इसका स्कोरिंग मॉडल और मेटाडेटा व्यवहार बदल सकता है। इसे आवश्यक CI गेट्स से बाहर रखें जब तक कि आपका वर्कफ़्लो बदलावों के लिए तैयार न हो.

निर्धारित CI जांचों के लिए, इसके बजाय `co-op-review` का उपयोग करें.
