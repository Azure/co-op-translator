# トラブルシューティング

このページは、翻訳実行が予期せず成功した場合、構成中に失敗した場合、または出力をレビューする必要がある場合に使用してください。

## ここから始める

1. まず、`translate -l "ko" -md` のような対象を絞ったコマンドを実行してください。
2. コンソールのデバッグログを有効にするには `-d` を追加してください。
3. デバッグログを `<root-dir>/logs/` に保存するには `-s` を追加してください。
4. 翻訳後に `co-op-review` を実行して、新しさ、構造、およびローカルリンクを確認してください。

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## 構成エラー

### 言語モデルプロバイダーがありません

エラー:

```text
No language model configuration found.
```

対処:

- Azure OpenAI、OpenAI、または Anthropic を構成してください。
- コマンドが実行される環境に変数が存在することを確認してください。
- ローカルで使用する場合は、プロジェクトルートの `.env` に配置してください。

詳しくは [構成](configuration.md) を参照してください。

### Azure AI Vision を使用しない画像翻訳

エラー:

```text
Image translation requested but Azure AI Service is not configured.
```

対処:

- `AZURE_AI_SERVICE_API_KEY` を追加してください。
- `AZURE_AI_SERVICE_ENDPOINT` を追加してください。
- または `translate -l "ko" -md` のようなテキストのみのコマンドを実行してください。

### 無効なキーまたはエンドポイント

症状には `401`、権限エラー（マスクされている場合があります）、またはエンドポイントへのアクセスエラーが含まれることがあります。

対処:

- キーがエンドポイントと同じ Azure リソースに属していることを確認してください。
- `-img` を使用する場合、リソースが Vision をサポートしていることを確認してください。
- Azure OpenAI のデプロイメント名と API バージョンがデプロイメントと一致していることを確認してください。
- デバッグログを有効にして実行してください: `translate -l "ko" -md -d -s`.

## 翻訳されたファイルはありませんでした

主な原因:

- 選択したフラグがファイルと一致していない。
- 既に翻訳済みのファイルが存在する。
- ソースファイルが除外されたディレクトリの下にある。
- コマンドが間違ったプロジェクトルートから実行されている。

チェック:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

コマンドがプロジェクトルート外で実行される場合は、`--root-dir` を使用してください。

## 予期しないリンクの動作

リンクの書き換えは選択されたコンテンツタイプに依存します:

- `-nb` を含めると: ノートブックのリンクが翻訳済みノートブックを指す可能性があります。
- `-nb` を除外すると: ノートブックのリンクはソースのノートブックを指したままになる可能性があります。
- `-img` を含めると: 画像リンクが翻訳済みの画像を指すことがあります。
- `-img` を除外すると: 画像リンクはソースの画像を指したままになることがあります。

内部リンクがすべて翻訳済みの出力を優先する必要がある場合は、コンテンツ全体の翻訳を実行してください:

```bash
translate -l "ko" -md -nb -img
```

翻訳後にリンクレビューを実行してください:

```bash
co-op-review -l "ko"
```

## Markdown のレンダリングの問題

翻訳された Markdown が正しくレンダリングされない場合:

- フロントマターが `---` で開始および終了していることを確認してください。
- コードフェンスの数がソースと翻訳ファイルで一致しているか確認してください。
- 一般的な構造の問題を検出するには `co-op-review` を実行してください。
- 出力が破損している場合は、該当ファイルを再翻訳してください。

```bash
co-op-review -l "ko" --format github
```

## GitHub Action は実行されたがプルリクエストは作成されなかった

`peter-evans/create-pull-request` がブランチがベースより進んでいないと報告する場合、ワークフローはコミットするファイルを見つけられませんでした。

考えられる原因:

- 翻訳実行で変更が発生しなかった。
- `.gitignore` が `translations/`、`translated_images/`、または翻訳済みノートブックを除外している。
- `add-paths` が生成された出力ディレクトリと一致していない。
- 翻訳ステップが早期に終了した。

対処方法:

1. 生成されたファイルが `translations/` または `translated_images/` に存在することを確認してください。
2. `.gitignore` が生成された出力を無視していないことを確認してください。
3. 一致する `add-paths` を使用してください:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. 一時的に translate コマンドにデバッグフラグを追加してください:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. ワークフローの権限に以下が含まれていることを確認してください:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## 翻訳品質

機械翻訳は人間のレビューが必要なことがあります。実験的な品質スコアリングや低信頼度の修復ワークフローを望む場合のみ `evaluate` を使用してください。

!!! warning "実験的"
    `evaluate` はルールベースおよび LLM ベースのチェックを使用する可能性があり、そのスコアリングモデルやメタデータの動作は変更されることがあります。ワークフローが変更に対応できる準備ができていない限り、必須の CI ゲートには組み込まないでください。

決定論的な CI チェックには代わりに `co-op-review` を使用してください。
