# ការដោះស្រាយបញ្ហា

ប្រើទំព័រនេះនៅពេលដែលការរត់ការបកប្រែបានជោគជ័យដោយមិនរំពឹងទុក, បរាជ័យអំឡុងពេលកំណត់រចនាសម្ព័ន្ធ, ឬបង្កើតលទ្ធផលដែលត្រូវការត្រួតពិនិត្យ។

## ចាប់ផ្តើមនៅទីនេះ

1. រត់ពាក្យបញ្ជាមួយដែលផ្តោតចិត្តជាមុន ដូចជា `translate -l "ko" -md`.
2. បន្ថែម `-d` សម្រាប់កំណត់ហេតុដែបនៅក្នុងកុងសូល។
3. បន្ថែម `-s` ដើម្បីរក្សាកំណត់ហេតុដែបនៅក្រោម `<root-dir>/logs/`។
4. រត់ `co-op-review` បន្ទាប់ពីការបកប្រែ ដើម្បីពិនិត្យភាពទាន់សម័យ រចនាសម្ព័ន្ធ និងតំណភ្ជាប់ក្នុងស្រុក។

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## កំហុសកំណត់រចនាសម្ព័ន្ធ

### គ្មានអ្នកផ្តល់ម៉ូឌែលភាសា

កំហុស:

```text
No language model configuration found.
```

ដោះស្រាយ:

- កំណត់រចនាសម្ព័ន្ធ Azure OpenAI, OpenAI, ឬ Anthropic.
- ផ្ទៀងផ្ទាត់ថាអថេរទាំងនេះមាននៅក្នុងបរិស្ថានដែលពាក្យបញ្ជារត្រូវបានរត់។
- សម្រាប់ការប្រើប្រាស់ក្នុងស្រុក ដាក់ពួកវា​នៅក្នុង `.env` នៅគោលដើមគម្រោង។

មើល [ការកំណត់រចនាសម្ព័ន្ធ](configuration.md)។

### ការបកប្រែរូបភាពដោយគ្មាន Azure AI Vision

កំហុស:

```text
Image translation requested but Azure AI Service is not configured.
```

ដោះស្រាយ:

- បន្ថែម `AZURE_AI_SERVICE_API_KEY`.
- បន្ថែម `AZURE_AI_SERVICE_ENDPOINT`.
- ឬរត់ពាក្យបញ្ជាតែអត្ថបទ ដូចជា `translate -l "ko" -md`.

### កូនសោ ឬ ចំណុចបញ្ចប់មិនត្រឹមត្រូវ

រោគសញ្ញាអាចរួមមាន `401`, កំហុសសិទ្ធិដែលត្រូវបានលាក់, ឬកំហុសការចូលដំណើរការចំណុចបញ្ចប់។

ដោះស្រាយ:

- ប្រាកដថាកូនសោស្ថិតនៅលើធនធាន Azure ដូចគ្នានឹងចំណុចបញ្ចប់។
- ប្រាកដថាធនធានគាំទ្រ Vision ពេលប្រើ `-img`។
- ផ្ទៀងផ្ទាត់ឈ្មោះការកំណត់ Azure OpenAI និងកំណែ API ថាកំពុងត្រូវនឹងការកំណត់របស់អ្នក។
- រត់ជាមួយកំណត់ហេតុដែប: `translate -l "ko" -md -d -s`.

## គ្មានឯកសារត្រូវបានបកប្រែ

ហេតុផលទូទៅ:

- ជម្រើសដែលបានជ្រើសមិនសមរម្យជាមួយឯកសាររបស់អ្នក។
- មានឯកសារបកប្រែដែលមានរួចហើយ។
- ឯកសារដើមស្ថិតនៅក្រោមថតដែលត្រូវបានដកចេញពីការពិនិត្យ។
- ពាក្យបញ្ជាកំពុងរត់ពីគោលដើមគម្រោងខុស।

ការត្រួតពិនិត្យ:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

ប្រើ `--root-dir` ពេលពាក្យបញ្ជារត្រូវបានរត់នៅខាងក្រៅគោលដើមគម្រោង។

## អាកប្បកិរិយាតំណដែលមិនរំពឹងទុក

ការផ្លាស់ប្តូរតំណអាស្រ័យលើប្រភេទមាតិកាដែលបានជ្រើស៖

- ប្រសិនបើរាប់បញ្ចូល `-nb`: តំណទៅកាន់ notebook អាចចេញទៅកាន់ notebook ដែលបានបកប្រែ។
- ប្រសិនបើមិនរាប់បញ្ចូល `-nb`: តំណទៅកាន់ notebook អាចនៅតែបង្ខំទៅកាន់ notebook ដើម។
- ប្រសិនបើរាប់បញ្ចូល `-img`: តំណរូបភាពអាចចេញទៅកាន់រូបភាពដែលបានបកប្រែ।
- ប្រសិនបើមិនរាប់បញ្ចូល `-img`: តំណរូបភាពអាចនៅតែបង្ខំទៅកាន់រូបភាពដើម។

ដំណើរការបកប្រែមាតិកាទាំងមូលនៅពេលដែលតំណខាងក្នុងគ្រប់យ៉ាងគួរជ្រើសលទ្ធផលបកប្រែ៖

```bash
translate -l "ko" -md -nb -img
```

រត់ការពិនិត្យតំណបន្ទាប់ពីការបកប្រែ៖

```bash
co-op-review -l "ko"
```

## បញ្ហាក្នុងការបង្ហាញ Markdown

បើ Markdown បកប្រែបង្ហាញមិនត្រឹមត្រូវ៖

- ពិនិត្យថា frontmatter ចាប់ផ្តើម និងបញ្ចប់ជាមួយ `---`។
- ពិនិត្យថាចំនួនរារាំងកូដ (code fence) ត្រូវគ្នារវាងឯកសារដើម និងឯកសារបកប្រែ។
- រត់ `co-op-review` ដើម្បីចាប់បញ្ហារចនាសម្ព័ន្ធទូទៅ។
- បកប្រែឡើងវិញឯកសារពិសេសនោះ ប្រសិនបើលទ្ធផលខូចខាត។

```bash
co-op-review -l "ko" --format github
```

## GitHub Action បានរត់ ប៉ុន្តែមិនបានបង្កើត Pull Request

ប្រសិនបើ `peter-evans/create-pull-request` របាយការណ៍ថា branch មិនលើស base នោះ workflow មិនបានរកឃើញឯកសារណាមួយសម្រាប់ commit។

ហេតុផលដែលអាចកើតមាន:

- ការរត់ការបកប្រែមិនបង្កើតការផ្លាស់ប្តូរណាមួយ។
- `.gitignore` លុចចោល `translations/`, `translated_images/`, ឬ notebook ដែលបានបកប្រែ។
- `add-paths` មិនត្រូវគ្នាជាមួយថតផលិតផលដែលបានបង្កើត។
- ជំហានការបកប្រែបានបញ្ចប់ជាមុន។

ដំណោះស្រាយ:

1. ផ្ទៀងផ្ទាត់ថា​ឯកសារផលិតបានមាននៅក្នុង `translations/` ឬ `translated_images/`។
2. ផ្ទៀងផ្ទាត់ថា `.gitignore` មិនបដិសេធផលិតផលដែលបានបង្កើត។
3. ប្រើ `add-paths` ដែលសមរម្យ៖

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. បន្ថែមប៉ារ៉ាម៉ែត្រដែបពេលខ្លីទៅពាក្យបញ្ជា translate៖

   ```bash
   translate -l "ko" -md -d -s
   ```

5. ផ្ទៀងផ្ទាត់ថា សិទិ្ធនៃ workflow រួមបញ្ចូល៖

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## គុណភាពបកប្រែ

ការបកប្រែដោយម៉ាស៊ីនអាចត្រូវការការត្រួតពិនិត្យដោយមនុស្ស។ ប្រើ `evaluate` តែប៉ុណ្ណោះពេលដែលអ្នកចង់បានការវាយតម្លៃគុណភាពប្រភេទសាកល្បង និងចរន្តការជួសជុលដែលមានទំនុកចិត្តទាប។

!!! warning "Experimental"
    `evaluate` អាចប្រើការត្រួតពិនិត្យដោយច្បាប់កំណត់ និងដោយ LLM ហើយម៉ូដែលការវាយតម្លៃនិងរបៀបធ្វើកម្មវិធីមេតាអាចផ្លាស់ប្តូរ។ កុំដាក់វាចូលជាកំហែកาย CI ទាមទារ លើកលែង workflow របស់អ្នកត្រៀមខ្លួនសម្រាប់ការផ្លាស់ប្តូរ។

សម្រាប់ការត្រួតពិនិត្យ CI ដែលកំណត់លទ្ធផលបានជាក់លាក់ ប្រើ `co-op-review` ជំនួស។
