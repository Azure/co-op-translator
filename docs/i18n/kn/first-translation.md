# ಒಂದು ಸಣ್ಣ ಯೋಜನೆಯನ್ನು ಅನುವಾದಿಸಿ, ಸಂಪಾದಿಸಿ ಮತ್ತು ವಿಮರ್ಶೆ ಮಾಡಿ

ಎರಡು ಚುಕ್ಕಾಣಿ Markdown ಕಡತಗಳು ಮತ್ತು ಒಂದು ಗುರಿ ಭಾಷೆಯಿಂದ ಶುರುಮಾಡಿ. ಅನುವಾದಗಳು ಎಲ್ಲಿಗೆ ಬರೆಯಲಾಗುತ್ತವೆ, ಮೂಲ ಬದಲಾದಾಗ ಏನು ಸಂಭವಿಸುತ್ತದೆ ಮತ್ತು ಫಲಿತಾಂಶವನ್ನು ಹೇಗೆ ಪರಿಶೀಲಿಸುವುದು ಎಂಬುದನ್ನು ನೀವು ನೋಡುತ್ತೀರಿ.

## ದಾಖಲಾಗಿರುವ ಫಲಿತಾಂಶಗಳು

ಉದಾಹರಣೆಯನ್ನು 19 ಸೆಪ್ಟೆಂಬರ್, 2026 ರಂದು Co-op Translator 0.21.0 ಮತ್ತು Azure OpenAI (`gpt-5-mini`) ಬಳಸಿ ನಡೆಸಲಾಯಿತು. ಬದಲಾಯಿಸದ CLI ಕಮಾಂಡ್‌ಗಳು ನಿರ್ಮಿಸಿದ ವ್ಹೀಲ್ ಮತ್ತು ಇರುವ Python ನಿರ್ಭರತೆಗಳನ್ನು ಬಳಸಿ Click ನ `CliRunner` ಮೂಲಕ ಕರೆ ಮಾಡಲಾಯಿತು.

| ಹಂತ | ಫಲಿತಾಂಶ |
| --- | --- |
| ಪೂರ್ವದೃಶ್ಯ | Exit 0; ಯಾವುದೇ ಮಾದರಿ ಅನುವಾದದ ವಿನಂತಿ ಇಲ್ಲ |
| ಪ್ರಾಥಮಿಕ ಅನುವಾದ | Exit 0; 27.36 ಸೆಕೆಂಡುಗಳು |
| ಪ್ರಾಥಮಿಕ ವಿಮರ್ಶೆ | Exit 0 |
| README ಅನ್ನು ಸಂಪಾದಿಸಿ ಮತ್ತು ವಿಮರ್ಶೆ ಮಾಡಿ | Exit 1; ಅಪ್ರಚಲಿತ ಅನುವಾದ ಪತ್ತೆಯಾಯಿತು |
| ಅನುವಾದ ನವೀಕರಣ | Exit 0; 22.17 ಸೆಕೆಂಡುಗಳು |
| ನವೀಕರಣದ ನಂತರ ವಿಮರ್ಶೆ | Exit 0; ಯಾವುದೇ ದೋಷಗಳು ಅಥವಾ ಎಚ್ಚರಿಕೆಗಳಿಲ್ಲ |
| ಬದಲಾಗದ ಮಾರ್ಗದರ್ಶಿ | README ನ ನವೀಕರಣದ ಮೊದಲು ಮತ್ತು ನಂತರ ಬೈಟ್ಗಳು ಸಮತೂಲ್ಯವಾಗಿದವು |
| ಮತ್ತೆ ಚಲಾಯಿಸಿ | Exit 0; ಎಲ್ಲಾ ಅನುವಾದ ಕಡತಗಳಿಗೆ ಸಮಾನ ಹ್ಯಾಷ್‌ಗಳು ಇದ್ದವು |

ಇವು ಪ್ರತ್ಯೇಕ ಚಾಲನೆಯ ಅಳತೆಗಳಾಗಿವೆ, ಕಾರ್ಯಕ್ಷಮತೆ ಖಾತ್ರಿ ನೀಡುವುದಿಲ್ಲ. ಸ್ಥಾಪನೆ ಸಮಯವನ್ನು ಹೊರತುಪಡಿಸಲಾಗಿದೆ; ಒದಗಿಸುವವರ ಬಿಲ್ಲಿಂಗ್ ಅಳೆಯಲಿಲ್ಲ. ಬದಲಾಗದ ಚಲನೆಯು ಸಹ ಒದಗಿಸುವವರ ಆರೋಗ್ಯ ಪರಿಶೀಲನೆ ನಡೆಸಬಹುದು.

ದಯವಿಟ್ಟು [ಪ್ರಾಥಮಿಕ ಅನುವಾದ](../../assets/demo/before.txt), [ನವೀಕರಿಸಿದ ಅನುವಾದ](../../assets/demo/after.txt), [ಸಂಪೂರ್ಣ ಅನುವಾದ ವ್ಯತ್ಯಾಸ](../../assets/demo/update.diff), [ಅಪ್ರಚಲಿತ ವಿಮರ್ಶೆ](../../assets/demo/review-stale.txt), [ಅಂತಿಮ ವಿಮರ್ಶೆ](../../assets/demo/review-after.txt), ಮತ್ತು [ಚಲನೆಯ ವಿವರಗಳು](../../assets/demo/results.json) ಅನ್ನು ಪರಿಶೀಲಿಸಿ. ಕಡತ-ಮಟ್ಟದ ಅನುವಾದವು ಹಿಡಿದಿಟ್ಟುಕೊಂಡ ವ್ಯತ್ಯಾಸವು ತೋರಿಸುವಂತೆ ಮತ್ತಷ್ಟು ಪದಬದ್ಧತೆಯನ್ನು ಬದಲಾಯಿಸಬಹುದು. ಎರಡೂ ಪಠ್ಯ ವಸ್ತುಗಳು ಉತ್ಪಾದಿಸಲಾದ ನಿರಾಕರಣೆಯನ್ನು ಸಂರಕ್ಷಿಸುತ್ತವೆ.

ಮಾನವ ವಿಮರ್ಶೆ ಇನ್ನೂ ಮಹತ್ವದ್ದು: ಹಿಡಿದಿಟ್ಟುಕೊಂಡ ನವೀಕರಣವು `[사용 가이드](guide.md)을` ಅನ್ನು ಬಳಸಿದೆ; ಕೊರಿಯನ್ ಪಕ್ಷವೇಶಕವು `[사용 가이드](guide.md)를` ಆಗಿರಬೇಕಾಗಿತ್ತು. ಪಠ್ಯ ವಸ್ತುಗಳು ಈ ಔಟ್‌ಪುಟ್ ಅನ್ನು ಸಂಪಾದಿತ ಅನುವಾದವಾಗಿಸದೆ ಅಕ್ಷೇಪವಾಗಿ ಉಳಿಸಿಕೊಂಡಿವೆ. ರೂಪಾತ್ಮಕ ವಿಮರ್ಶೆ ಈ ಪದಬಣ್ಣದ ಸಮಸ್ಯೆಯಿದ್ದರೂ ಪಾಸ್ ಆಗುತ್ತದೆ.

## 1. ಒಂದು ಸಣ್ಣ ಫೋಲ್ಡರ್ ತಯಾರಿಸಿ

Python 3.11–3.14 ಅನ್ನು ಮತ್ತು [ವರ್ಚುಯಲ್ ಪರಿಸರ ಸೆಟ್ಟಪ್](configuration.md#local-runtime-setup) ಅನ್ನು ಬಳಸಿರಿ. ಈ ಉದಾಹರಣೆಗೆ ಬಳಸಿದ ಆವೃತ್ತಿಯನ್ನು ಇನ್‌ಸ್ಟಾಲ್ ಮಾಡಿ:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

ಈ ಫೋಲ್ಡರ್‌ಗೆ [README.txt](../../assets/demo/README.txt) ಮತ್ತು [guide.txt](../../assets/demo/guide.txt) ಅನ್ನು ಡೌನ್‌ಲೋಡ್ ಮಾಡಿ ಮತ್ತು ಅವುಗಳನ್ನು `README.md` ಮತ್ತು `guide.md` ಎಂದು ಉಳಿಸಿ. ಇವು ಕನೆಪ್ಟುಲ ಇಲ್ಲದ (fictional) ಸಣ್ಣ ಯೋಜನೆ ದಾಖಲೆಗಳಾಗಿವೆ; ಯಾವುದೇ ಅಪ್ಲಿಕೇಶನ್ ಸ್ಥಾಪನೆ ಬೇಕಾಗಿಲ್ಲ.

README ನಲ್ಲಿ ಒಂದು ಕೋಡ್ ಬ್ಲಾಕ್ ಮತ್ತು `guide.md` ಗೆ ಒಂದು ಲಿಂಕ್ ಇದೆ. ಅದರ ಅಂತಿಮ ವಾಕ್ಯವು:

```text
Notes are saved locally.
```

ಈ ಫೋಲ್ಡರ್‌ನಲ್ಲಿ ಕೇವಲ ಈ ಎರಡು ಮೂಲ ದಾಖಲೆಗಳನ್ನು ಇರಿಸಿಕೊಳ್ಳಿ. ನಂತರದ ಎಲ್ಲಾ ಕಮಾಂಡ್‌ಗಳು `translation-demo` ಒಳಗೆ ನಡೆಸಲಾಗುತ್ತವೆ ಮತ್ತು Bash ಮತ್ತು PowerShell ಎರಡರಲ್ಲಿಯೂ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ.

## 2. ಪ್ರಮಾಣಪತ್ರಗಳಿಲ್ಲದೆ ಪೂರ್ವದೃಶ್ಯ

```bash
translate -l "ko" -md --dry-run
```

ಪೂರ್ವದೃಶ್ಯವು ಮಾದರಿಯನ್ನು ಕರೆಮಾಡದೆ ಅಥವಾ ಅನುವಾದಗಳನ್ನು ಬರೆಯದೆ ಅನುವಾದ ಕಾರ್ಯದ ಅಂದಾಜುಗಳನ್ನು ನೀಡುತ್ತದೆ. ಟೋಕೆನ್ ಅಂದಾಜುಗಳು ಬಿಲ್ಲಿಂಗ್ ಉಲ್ಲೇಖವಲ್ಲ. ಮೊದಲ ಚಾಲನೆ ಎರಡೂ Markdown ಕಡತಗಳನ್ನು ಹೊಸ ಕೆಲಸವೆಂದು ಗುರುತಿಸಬೇಕು.

## 3. ಒದಗಿಸುವವರನ್ನು ಆರಿಸಿ ಮತ್ತು ಅನುವಾದಿಸಿ

ಒದಗಿಸುವವರಲ್ಲಿ ಒಂದನ್ನು [ಕನ್ಫಿಗರೇಶನ್ ಮಾರ್ಗದರ್ಶಿ](configuration.md) ಅನುಸರಿಸಿ ಸಂರಚಿಸಿ: Azure OpenAI, OpenAI, ಅಥವಾ Anthropic. OpenAI ಮತ್ತು Anthropic ಪಠ್ಯ ಅನುವಾದಕ್ಕೆ Azure ಖಾತೆ ಅಗತ್ಯವಿಲ್ಲ. ಈ ಉದಾಹರಣೆಗೆ ಚಿತ್ರ ಸೇವೆಗಳು ಬೇಕಾಗಿಲ್ಲ.

ನೀವು ಸ್ಥಳೀಯ `.env` ಫೈಲ್ ಬಳಸಿದರೆ, `.env` ಅನ್ನು ಈ ಫೋಲ್ಡರ್‌ನ `.gitignore` ಗೆ ಸೇರಿಸಿ. ಅನುವಾದ ಕರೆಗಳು ನಿಮ್ಮ ಒದಗಿಸುವವರ ಖಾತೆಯನ್ನು ಬಳಸುತ್ತವೆ ಮತ್ತು ಶುಲ್ಕವಾಗಬಹುದು.

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

`translations/ko/README.md` ಮತ್ತು `translations/ko/guide.md` ಅನ್ನು ತೆರೆಯಿರಿ. ಕೊರಿಯನ್ ಪದಪ್ರಯೋಗ, ಕೋಡ್ ಬ್ಲಾಕ್ ಮತ್ತು ಅನುವಾದಿತ README ನಿಂದ ಅನುವಾದಿತ ಮಾರ್ಗದರ್ಶನಕ್ಕೆ ಇರುವ ಲಿಂಕ್ ಅನ್ನು ಪರಿಶೀಲಿಸಿ. ಔಟ್‌ಪುಟ್ ಪದಪ್ರಯೋಗ ಮಾದರಿಯ ಮೇಲೆ ಅವಲಂಬಿತವಾಗಿದೆ.

`co-op-review` ತಾಜಾತನ, ರಚನೆ ಮತ್ತು ಸ್ಥಳೀಯ ಲಿಂಕ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಪಾಸಾದ ಫಲಿತಾಂಶವು ಭಾಷಾತ್ಮಕ ಖಚಿತತೆಯನ್ನು ದೃಢೀಕರಿಸುವುದಿಲ್ಲ. ಮುಂದುವರಿಯುವುದಕ್ಕೆ ಮುನ್ನ ವರದಿಯಾದ ಯಾವುದೇ ದೋಷಗಳನ್ನು ಪರಿಹರಿಸಿ.

ಯಶಸ್ವಿ ಬೇಸ್‌ಲೈನ್ ಅನ್ನು Git ನಲ್ಲಿ ದಾಖಲಿಸಿ (ಅವಶ್ಯಕವಾದರೆ ಮೊದಲು ನಿಮ್ಮ Git ಗುರುತನ್ನು ಸಂರಚಿಸಿ):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. ಮೂಲವನ್ನು ಬದಲಾಯಿಸಿ

`README.md` ನಲ್ಲಿ, `Notes are saved locally.` ಅನ್ನು ಹೀಗೆ ಬದಲಿಸಿ:

```text
Notes are saved locally as Markdown files.
```

`guide.md` ಅನ್ನು ಬದಲಾಗದಂತೆ ಇರಿಸಿ. ನಂತರ ಈ ಕಮಾಂಡ್ ಅನ್ನು ಚಲಾಯಿಸಿ:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

ವಿಮರ್ಶೆ README ಅನುವಾದವನ್ನು ಅಪ್ರಚಲಿತವೆಂದು ವರದಿ ಮಾಡಿ ಮತ್ತು ಯಶಸ್ವಿಯಾಗಿ ನಿರ್ಗಮಿಸಬಾರದು. ಇದು ನಿರೀಕ್ಷಿತ ಮಧ್ಯಮ ಸ್ಥಿತಿಯಾಗಿದೆ. ಪೂರ್ವದೃಶ್ಯ ಬದಲಾಯಿಸಲಾದ README ಗೆ ಕೆಲಸವನ್ನು ಗುರುತಿಸಬೇಕು.

## 5. ನವೀಕರಿಸಿ ಮತ್ತು ವ್ಯತ್ಯಾಸವನ್ನು ಪರಿಶೀಲಿಸಿ

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

ನಿಜವಾದ ವ್ಯತ್ಯಾಸವನ್ನು ಪರಿಶೀಲಿಸಿ: ಡೀಫಾಲ್ಟ್ CLI ಬದಲಾಯಿಸಿದ ಕಡತವನ್ನು ಮರುಅನುವಾದಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಮಾದರಿ ಆ ಕಡತದಲ್ಲಿನ ಇನ್ನೂ ಇತರ ಪದಪ್ರಯೋಗಗಳನ್ನು ಸಹ ಪರಿಷ್ಕರಿಸಬಹುದು. ಬದಲಾಗದ ಮಾರ್ಗದರ್ಶನಕ್ಕೆ ಯಾವುದೇ ವ್ಯತ್ಯಾಸದಿಲ್ಲ. ವಿಮರ್ಶೆ README ಅನ್ನು ಇನ್ನೂ ಅಪ್ರಚಲಿತವೆಂದು ವರದಿ ಮಾಡಬಾರದು; ಇನ್ನಿತರ ಕಂಡುಬಂದ ವಿಷಯಗಳನ್ನು ನಿರ್ಲಕ್ಷಿಸದೆ ಪರಿಶೀಲಿಸಿ.

ಮಾನವ Markdown ಸಂಪಾದನೆಗಳ ಬ್ಲಾಕ್-ಮಟ್ಟದ ಸಂರಕ್ಷಣೆಗೆ [Python API](api.md) ಯಲ್ಲಿ ಐಚ್ಛಿಕ ಅನುವಾದ ಸ್ಥಿತಿ ಒದಗಿಸುವವರ ಅಗತ್ಯವಿದೆ. ಈ CLI ಕಮಾಂಡ್‌ಗಳು ಅದನ್ನು ಸಕ್ರಿಯಗೊಳಿಸುವುದಿಲ್ಲ.

## 6. ಬದಲಾವಣೆಗಳಿಲ್ಲದೆ ಮತ್ತೆ ಚಾಲನೆ ಮಾಡಿ

ನವೀಕರಿಸಿದ ಮೂಲ ಮತ್ತು ಅನುವಾದವನ್ನು commit ಮಾಡಿ:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

ಪ್ರಸ್ತುತ ಅನುವಾದಗಳು ಮತ್ತು ಬದಲಾಗದ ಸಂರಚನೆಯ ಜೊತೆಗೆ, ಅನುವಾದಕವು ಕಡತಗಳನ್ನು ಓವರ್‌ಸ್ಕಿಪ್ ಮಾಡುತ್ತದೆ. ಅಂತಿಮ Git ಕಮಾಂಡ್ ಯಾವುದೇ ವ್ಯತ್ಯಾಸವನ್ನು ಉತ್ಪಾದಿಸಬಾರದು ಮತ್ತು ಯಶಸ್ವಿಯಾಗಿ ನಿರ್ಗಮಿಸಬೇಕು.
