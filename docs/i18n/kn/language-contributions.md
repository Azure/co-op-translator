# ಭಾಷಾ ಸುಧಾರಣೆಗಳಿಗೆ ಕೊಡುಗೆ

ನಿಮ್ಮ ಭಾಷಾ ಜ್ಞಾನವು Co-op Translator ಅನ್ನು ಸುಧಾರಿಸಲು ಸಹಾಯ ಮಾಡಬಹುದು. ಉದಾಹರಣೆ, ಪ್ರಸ್ತಾವಿತ ತಿದ್ದುಪಡಿ ಮತ್ತು ವಿವರವನ್ನು [ಅನುವಾದ ಪ್ರತಿಕ್ರಿಯೆ ಫಾರ್ಮ್](https://github.com/Azure/co-op-translator/issues/new?template=translation_feedback.yml) ಬಳಸಿ ಪ್ರಾರಂಭಿಸಿ. ನಿಮಗೆ ಕೋಡ್ ಬರೆಯಬೇಕಾಗಿಲ್ಲ ಅಥವಾ ಮಾದರಿ ರನ್‌ಗೆ ಹಣ ಪಾವತಿಸುವ ಅಗತ್ಯವಿಲ್ಲ.

## ವರದಿಯಿಂದ ಹಂಚಿಕೊಂಡ ಸುಧಾರಣೆಗೆ

1. ಕೊಡುಗಿದಾರನು ಮೂಲ ಉಲ್ಲೇಖ, ಅದರ ಅನುವಾದ ಮತ್ತು ಸ೦ದರ್ಭವನ್ನು ಒದಗಿಸುತ್ತಾನೆ.
2. ಭಾಷಾ ವಿಮರ್ಶಕರು ಅರ್ಥ, ಸ್ವಾಭಾವಿಕತೆ ಮತ್ತು ಸಲಹೆ ನಿರ್ದಿಷ್ಟ ಸ್ಥಳ ಅಥವಾ ಕೋರ್ಸ್ ಮೇಲೆ ಆಧಾರಿತವೋ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸುತ್ತಾರೆ.
3. ನಿರ್ವಹಕನು ತಿದ್ದುಪು ಮೂಲ ಕೋರ್ಸ್‌ನಲ್ಲಿ ಇರಬೇಕೆಂದು, ಹಂಚಿಕೊಂಡ ಭಾಷಾ ಸೂಚನೆ, ಪರಿಭಾಷಾ ಸಂರಚನೆ, ಅಥವಾ ಅನುವಾದ ಕೋಡ್‌ನಲ್ಲಿ ಇರಬೇಕೆಂದು ನಿರ್ಧರಿಸುತ್ತಾನೆ.
4. ಹಂಚಿಕೊಂಡ ನಿಯಮಕ್ಕಾಗಿ, ನಿರ್ವಹಕನು ವರದಿಯಾದ ಉದಾಹರಣೆಯ ಮೇಲೆ ಮತ್ತು ಸಂಬಂಧಿಸದ ಉದಾಹರಣೆಗಳ ಮೇಲೆ ಬದಲಾವಣೆಯ ಮುಂಚಿನ ಮತ್ತು ನಂತರದ ಔಟ್‌ಪುಟ್‌ಗಳನ್ನು ಹೋಲಿಸುತ್ತಾನೆ. ಕೊಡುಗಿದಾರರು ಈ ಔಟ್‌ಪುಟ್‌ಗಳನ್ನು ಸಾಧನವನ್ನು ಸ್ವತಃ ಚಾಲನೆ ಮಾಡದೆ ಪರಿಶೀಲಿಸಬಹುದು.
5. ಫಲಿತಾಂಶದ PR ವರದಿಗೆ ಲಿಂಕ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಉದಾಹರಣೆಗಳು ಮತ್ತು ವಿಮರ್ಶೆ ಒದಗಿಸಿದವರಿಗೆ ಕ್ರೆಡಿಟ್ ನೀಡುತ್ತದೆ. ಬಳಸುವ ರೆಪೊಗಳಲ್ಲಿ ನಿಯೋಜನೆ ಅಥವಾ ಮರುಉತ್ಪಾದನೆ ಒಂದು ವಿಭಿನ್ನ ಹಂತವಾಗಿದೆ.

ವರದಿ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಪ್ರಾಂಪ್ಟ್‌ಗಳನ್ನು ಬದಲಾಯಿಸದು ಅಥವಾ ಕೋರ್ಸ್ ಅನುವಾದಗಳನ್ನು ಮರುಉತ್ಪಾದನೆ ಮಾಡದು. ಕೋರ್ಸ್-ನಿರ್ದಿಷ್ಟ ತಿದ್ದುಪಡಿಗಳು ಕೋರ್ಸ್ ರೆಪೊಸಿಟರಿಯೊಂದಿಗೆ ಸಂಪರ್ಕದಲ್ಲೇ ಇರುವಂತೆ ಇರಬೇಕು. ಕೈಯಿಂದ ಮಾಡಲಾದ ಸಂಪಾದನೆ ಮುಂದೆ ಮರುಅನುವಾದದಲ್ಲಿ ಉಳಿಯುತ್ತದೆ ಎಂದು ಊಹಿಸಬೇಡಿ; ಆ ಕಾರ್ಯಪ್ರವಾಹದ ವರ್ತನೆಯನ್ನು ದೃಢೀಕರಿಸಿ.

## ಇರುವ ಉದಾಹರಣೆ: ಜಪಾನೀಸ್ Markdown ಲಿಂಕ್‌ಗಳು

The [ಜಪಾನೀಸ್ ಸೂಚನಾ ಫೈಲ್](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/templates/language/ja.md) ಮಾದರಿಯನ್ನು Markdown ಸಿಂಟ್ಯಾಕ್ಸ್ ಮತ್ತು ಲಿಂಕ್ ಗುರಿಯನ್ನು ಕಾಯ್ದುಕೊಳ್ಳುತ್ತಾ ಲಿಂಕ್ ಪಠ್ಯವನ್ನು ಅನುವಾದಿಸಲು ಸೂಚಿಸುತ್ತದೆ. ಉದಾಹರಣೆಗೆ, `[text](URL)` ಎಂದು ಬರೆದ ಲಿಂಕ್ `「text」（URL）` ಆಗಬಾರದು.

ಇದು ಸರಿಯಾದ ಮತ್ತು ತಪ್ಪು ಔಟ್‌ಪುಟ್‌ನ ಚಿತ್ರಣದಿಂದ ಬೆಂಬಲಿತ ಭಾಷಾ ನಿಯಮದ ಕೇಂದ್ರೀಕೃತ ಉದಾಹರಣೆ. ಇದು ಪ್ರಾಂಪ್ಟ್ ಸೂಚನೆಗಳು ಮಾತ್ರದಿಂದಲೇ ಸರಿಯಾದ Markdown ಅನ್ನು ಖಚಿತಪಡಿಸುತ್ತದೆ ಎಂಬ ಸಾಕ್ಷ್ಯವಲ್ಲ.

The [Markdown ಪ್ರಾಂಪ್ಟ್ ಬಿಲ್ಡರ್](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/utils/markdown/prompts.py) `templates/language/<language_code>.md` ಅನ್ನು ಸಣ್ಣಕ್ಷರಗೊಳಿಸಿದ ಮತ್ತು ಅತಿರಿಕ್ತ ಸ್ಥಳಗಳಿಲ್ಲದ ಭಾಷಾ ಕೋಡ್ ಬಳಸಿಕೊಂಡು ಲೋಡ್ ಮಾಡುತ್ತದೆ. ಯಾವುದೇ ಫೈಲ್ ಇರುವ نہیںದಿದ್ದರೆ, ಅದು ಸಾಮಾನ್ಯ ಸೂಚನೆಗಳನ್ನು ಬಳಸುತ್ತದೆ. ಇದು Markdown ಪ್ರಾಂಪ್ಟ್ ಮಾರ್ಗವನ್ನ ವಿವರಿಸುತ್ತದೆ; ಪ್ರತಿ ಚಿತ್ರ ಅಥವಾ ಇತರ ಅನುವಾದ ಮಾರ್ಗವೂ ಅದೇ ಸೂಚನೆಗಳನ್ನು ಬಳಸುತ್ತವೆ ಎಂದು ಊಹಿಸಬೇಡಿ.

The [ಪ್ರಾಂಪ್ಟ್ ಪರೀಕ್ಷೆಗಳು](https://github.com/Azure/co-op-translator/blob/main/tests/co_op_translator/utils/markdown/test_prompts.py) ಜಪಾನೀಸ್ ಸೂಚನೆಗಳಿರುವುದನ್ನು ಪರಿಶೀಲಿಸುತ್ತವೆ. ಅದು ಪ್ರಾಂಪ್ಟ್ ಸಂಯೋಜನೆಯನ್ನು ಮಾನ್ಯಗೊಳಿಸುತ್ತದೆ, ಅನುವಾದ ಗುಣಮಟ್ಟವನ್ನು ಅಲ್ಲ.

## ಭಾಷಾ ನಿಯಮದಲ್ಲಿ ಏನು ಇರಬೇಕು?

ತೊಂದರೆಯಾಗದ, ಪುನರಾವರ್ತಿಸಬಹುದಾದ ತಿದ್ದುಪಡಿಯನ್ನು ಮೂಲ ಉದಾಹರಣೆ, ನಿರೀಕ್ಷಿತ ವರ್ತನೆ ಮತ್ತು ನಿಯಮ ಅನ್ವಯಿಸಬಾರದೆ ಎಂಬ ಪ್ರತಿದೃಷ್ಟಿಯಿಂದ ಪ್ರಸ್ತಾವಿಸಿ. ಅರ್ಥ, ಪ್ಲೇಸ್ಹೋಲ್ಡರ್‌ಗಳು, ಕೋಡ್, URL ಗಳು ಮತ್ತು ದಸ್ತಾವೇಜಿನ ರಚನೆಯನ್ನು ಉಳಿಸಿಕೊಂಡಿರಿಸಿ. ಒಬ್ಬ ವ್ಯಕ್ತಿಯ ಶೈಲಿ ಅಭಿರುಚಿ ಅಥವಾ ಒಂದು ಕೋರ್ಸ್‌ನ ಪರಿಭಾಷೆಯನ್ನು ವಿಶ್ವಸ್ಪಷ್ಟ ನಿಯಮವನ್ನಾಗಿ ಮಾಡಬೇಡಿ.

The current [ಗ್ಲಾಸರಿ ಅನುಷ್ಠಾನ](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/glossary.py) ಪದಗಳನ್ನು ಅನುವಾದದಿಂದ ರಕ್ಷಿಸುತ್ತದೆ. ಇದು ಮೂಲ-ಗುರಿ ಪರಿಭಾಷಾ ನಿಘಂಟು ಅಲ್ಲ. ಹೊಸ ಪರಿಭಾಷಾ ವರ್ತನೆಯ ಬಗ್ಗೆ ಕೊಡುಗಿದಾರರಿಗೆ ಭರವಸೆ ನೀಡುವ ಮೊದಲು ಚರ್ಚಿಸಿರಿ.

## ಸಮುದಾಯ ಉದಾಹರಣೆ: ಜಪಾನಿ ಉತ್ಪನ್ನ-ಹೆಸರು ವರದಿ

In [ವರದಿ #527](https://github.com/Azure/co-op-translator/issues/527), @hyoshioka0128 ಒಂದು ಜಪಾನೀಸ್ ಅನುವಾದವನ್ನು ಗುರುತಿಸಿದರು, ಇದು ಉತ್ಪನ್ನ ಹೆಸರನ್ನು `Co-op Translator` ನಿಂದ `Co-op 翻訳` ಆಗಿ ಬದಲಾಯಿಸಿತ್ತು. ವರದಿಯಲ್ಲಿ ಪ್ರಭಾವಿತ ದಾಖಲೆಕ್ಕೆ ಲಿಂಕ್ ಮತ್ತು ಸ್ಕ್ರೀನ್‌ಶಾಟ್ ಸೇರಿತ್ತು, ಇದರಿಂದ ಸಮಸ್ಯೆಯನ್ನು ಸುಲಭವಾಗಿ ಕಂಡುಹಿಡಿಯಬಹುದು.

ಕೊಡುಗಿದಾರನು ಸಂಬಂಧಿತ [ಕೋರ್ಸ್ PR](https://github.com/microsoft/AZD-for-beginners/pull/109) ನ್ನು ಸಹ ಲಿಂಕ್ ಮಾಡಿದ್ದರು. ವಿಷಯದ ಚರ್ಚೆಯಲ್ಲಿ, ನಿರ್ವಹಕನು ವರದಿಯನ್ನು ಅಂಗೀಕರಿಸಿ ಹೆಸರಿನ ಬದಲಾವಣೆ ಯಾಕೆ ಸಂಭವಿಸಿತೆಂದು ತಪಾಸಣೆ ಮಾಡಬೇಕೆಂದು ಪ್ರಸ್ತಾಪಿಸಿದರು; ಇದರಲ್ಲಿ ಪರಿಭಾಷಾ ರಕ್ಷಣೆ, ಗ್ಲಾಸರಿ ವರ್ತನೆ ಮತ್ತು ಅನುವಾದ ಮಾರ್ಗವನ್ನು ಸೇರಿಸಲಾಗಿತ್ತು.

ಇದು ಹೇಗೆ ಒಂದು ಸಣ್ಣ ವರದಿ ವೈಯುಕ್ತিক ಪದಬದಲಾವಣೆಯನ್ನು ಮೀರಿದ ತನಿಖೆಯನ್ನು ಬೆಂಬಲಿಸಬಹುದು ಎಂಬುದನ್ನು ತೋರಿಸುತ್ತದೆ. ಇದು ದೃಢೀಕೃತ ಮೊದಲು/ನಂತರ ಫಲಿತಾಂಶವಲ್ಲ ಅಥವಾ ಮೇಲಿನ ಜಪಾನೀಸ್ Markdown-ಲಿಂಕ್ ಸೂಚನೆಗಳು ಈ ಉತ್ಪನ್ನ-ಹೆಸರು ಸಮಸ್ಯೆಯನ್ನು ಪರಿಹರಿಸಿವೆ ಎಂಬ ಸಾಕ್ಷ್ಯವಲ್ಲ.

ನೀವು ಅದೇ ರೀತಿಯಲ್ಲಿ ಕೊಡುಗೆ ನೀಡಬಹುದು: ಮೂಲ ಪಠ್ಯ, ಪ್ರಸ್ತುತ ಅನುವಾದ, ಸೂಚಿಸಲಾದ ತಿದ್ದುಪು ಮತ್ತು ಅದು ಏಕೆ ಪ್ರಮುಖೋ ಹಂಚಿಕೊಳ್ಳಿ. ಅಗತ್ಯವಿದ್ದರೆ ದಸ್ತಾವೇಜಿನ ಲಿಂಕ್ ಅಥವಾ ಸ್ಕ್ರೀನ್‌ಶಾಟ್ ಸೇರಿಸಿ. ವರದಿ ಮಾಡುವ ಮೊದಲು ಕಾರಣವನ್ನು ನಿರ್ಣಯಿಸಬೇಕಾಗಿಲ್ಲ ಅಥವಾ ಪ್ರಾಂಪ್ಟ್ ಬರೆಯಬೇಕಾಗಿಲ್ಲ.

## ನಿಯಮವನ್ನು ಅಂಗೀಕರಿಸುವ ಮೊದಲು ಪರಿಶೀಲನೆ

ಬೇಸ್‌ಲೈನ್ ಮತ್ತು ಅಭ್ಯರ್ಥಿ ರನ್‌ಗಳಿಗಾಗಿ ಒಂದೇ ಮೂಲ ಉದಾಹರಣೆಗಳು, ಅನುವಾದಕ ಪರಿಷ್ಕರಣೆ, ಒದಗಿಸುವವ/ಮಾದರಿ ಮತ್ತು ಜನರೇಷನ್ ಸೆಟ್ಟಿಂಗ್‌ಗಳನ್ನು ಬಳಸಿ; ಬದಲಾವಣೆ ಮಾಡುವದೇ ಪ್ರಸ್ತಾವಿತ ಸೂಚನೆ ಮಾತ್ರವಾಗಿರಲಿ. ವಾಸ್ತವಿಕ ಪ್ರಾಂಪ್ಟ್ ಬದಲಾವಣೆಯನ್ನು ಮತ್ತು ಔಟ್‌ಪುಟ್‌ಗಳನ್ನು ದಾಖಲಿಸಿ; ಔಟ್‌ಪುಟ್ ವೈವಿಧ್ಯದಿಂದ ಬೇರ್ಪಡಿಸುವಂತೆ ನಿರಂತರ ಪರಿಣಾಮವಿದೆಯೋ ಎಂದು ಕಂಡುಹಿಡಿಯಲು ಅಗತ್ಯವಿದ್ದರೆ ಉದಾಹರಣೆಗಳನ್ನು ಪುನರಾವರ್ತಿಸಿ. ವರದಿಯಾದ ವೈಫಲ್ಯ, ವಿರುದ್ಧ ಸೂಕ್ಷ್ಮತೆಯ ಸಂದರ್ಭಗಳು ಮತ್ತು ಈಗಾಗಲೆ ಸರಿಯಾಗಿ ಅನುವಾದವಾಗುತ್ತಿರುವ ಉದಾಹರಣೆಗಳನ್ನು ಸೇರಿಸಿ.

ರಚನಾತ್ಮಕ ಅಚಲಾಂಶಗಳನ್ನು ಭಾಷಿಕ ವಿನ್ಯಾಸಗಳಿಂದ ಪ್ರತ್ಯೇಕವಾಗಿ ಪರಿಶೀಲಿಸಿ. ಪ್ರಾಂಪ್ಟ್-ಲೋಡ್ ಪರೀಕ್ಷೆಯ ಯಶಸ್ಸು ಗುಣಮಟ್ಟದ ಮೌಲ್ಯಮಾಪನವಲ್ಲ, ಮತ್ತು ಒಂದೇ ನಿಖರ ನಿರೀಕ್ಷಿತ ವಾಕ್ಯವೇ ಏಕೈಕ ಮಾನ್ಯ ಅನುವಾದವಲ್ಲ. ಸಂದರ್ಭ, ಮಾದರಿ ರನ್‌ಗಳು ಅಥವಾ ಭಾಷಾ ವಿಮರ್ಶೆ ಕೊರತೆಯಿದ್ದರೆ, ಸಮಸ್ಯೆ ಪರಿಹಾರಗೊಂಡಿದೆ ಎಂದು ಹೇಳುವುದರ ಬದಲು ಪ್ರಸ್ತಾವನೆಯನ್ನು ಬಾಕಿಯಾಗಿಡಿ.
