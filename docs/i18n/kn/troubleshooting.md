# ಸಮಸ್ಯೆಗಳ ಪರಿಹಾರ

ಅನುವಾದ ರನ್ ಅನಿರೀಕ್ಷಿತವಾಗಿ ಯಶಸ್ವಿಯಾದಾಗ, ಸಂರಚನೆ دوران ವಿಫಲವಾದಾಗ, ಅಥವಾ ಪರಿಶೀಲನೆಗೆ ಅಗತ್ಯವಿರುವ ಔಟ್‌ಪುಟ್ ಅನ್ನು ಉತ್ಪನ್ನ ಮಾಡಿದಾಗ ಈ ಪುಟವನ್ನು ಬಳಸಿ.

## ಇಲ್ಲಿಂದ ಪ್ರಾರಂಭಿಸಿ

1. ಮೊದಲು ನಿಗದಿತ ಕಮಾಂಡ್ ಓಡಿಸಿ, ಉದಾಹರಣೆಗೆ `translate -l "ko" -md`.
2. ಕൺಸೋಲ್ ಡಿಬಗ್ಗಿಂಗ್ ಲಾಗ್‌ಗಳಿಗಾಗಿ `-d` ಅನ್ನು ಸೇರಿಸಿ.
3. ಡಿಬಗ್ ಲಾಗ್‌ಗಳನ್ನು `<root-dir>/logs/` ಅಡಿಯಲ್ಲಿ ಉಳಿಸಲು `-s` ಅನ್ನು ಸೇರಿಸಿ.
4. ಹೊಸತನ, ರಚನೆ ಮತ್ತು ಸ್ಥಳೀಯ ಲಿಂಕ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸಲು ಅನುವಾದದ ನಂತರ `co-op-review` ಅನ್ನು ಓಡಿಸಿ.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## ಸಂರಚನಾ ದೋಷಗಳು

### ಭಾಷಾ ಮಾದರಿ ಒದಗಿಸುವವರು ಇಲ್ಲ

ದೋಷ:

```text
No language model configuration found.
```

ಪರಿಹಾರ:

- Azure OpenAI, OpenAI, ಅಥವಾ Anthropic ಅನ್ನು ಸಂರಚಿಸಿ.
- ಆ ಕಮಾಂಡ್ ನಡೆಯುವ ಪರಿಸರದಲ್ಲೇ ಚರಗಳು (variables) ಇರುವುದನ್ನು ಪರಿಶೀಲಿಸಿ.
- ಸ್ಥಳೀಯ ಬಳಕೆಗೆ, ಅವುಗಳನ್ನು ಪ್ರಾಜೆಕ್ಟ್ ರೂಟ್‌ನಲ್ಲಿ `.env` ಗೆ ಇಟ್ಟುಕೊಳ್ಳಿ.

[ಸಂರಚನೆ](configuration.md) ನೋಡಿ.

### Azure AI Vision ಇಲ್ಲದೆ ಚಿತ್ರ ಅನುವಾದ

ದೋಷ:

```text
Image translation requested but Azure AI Service is not configured.
```

ಪರಿಹಾರ:

- `AZURE_AI_SERVICE_API_KEY` ಅನ್ನು ಸೇರಿಸಿ.
- `AZURE_AI_SERVICE_ENDPOINT` ಅನ್ನು ಸೇರಿಸಿ.
- ಅಥವಾ `translate -l "ko" -md` ಎಂಬ ಪಠ್ಯ ಮಾತ್ರ ಆಜ್ಞೆಯನ್ನು ಓಡಿಸಿ.

### ಅಮಾನ್ಯ ಕೀ ಅಥವಾ ಎಂಡ್ಪಾಯಿಂಟ್

ಲಕ್ಷಣಗಳು: `401`, ರಿಡ್ಯಾಕ್ಟೆಡ್ ಅನುಮತಿ ದೋಷಗಳು, ಅಥವಾ ಎಂಡ್ಪಾಯಿಂಟ್ ಪ್ರವೇಶ ದೋಷಗಳು ಇರಬಹುದು.

ಪರಿಹಾರ:

- ಕೀ ಎಂಡ್ಪಾಯಿಂಟ್ ಇದ್ದಿರುವ ಅದೇ Azure ಸಂಪನ್ಮೂಲಕ್ಕೆ ಸೇರಿದದ್ದೇ ಎಂದು ದೃಢಪಡಿಸಿ.
- `-img` ಬಳಕೆ ಸಮಯದಲ್ಲಿ ಆ ಸಂಪನ್ಮೂಲ Vision ಅನ್ನು ಬೆಂಬಲಿಸುತ್ತದೇ ಎಂದು ದೃಢಪಡಿಸಿ.
- Azure OpenAI deployment ಹೆಸರೂ ಮತ್ತು API ಆವೃತ್ತಿ ನಿಮ್ಮ ನಿಯೋಜನೆಗೆ ಹೊಂದಿದೆಯೇ ಎಂದು ದೃಢಪಡಿಸಿ.
- ಡಿಬಗ್ ಲಾಗ್‌ಗಳೊಂದಿಗೆ ಓಡಿಸಿ: `translate -l "ko" -md -d -s`.

## ಯಾವುದೂ ಫೈಲ್‌ಗಳು ಅನುವಾದಿಸಲ್ಪಟ್ಟಿಲ್ಲ

ಸಾಮಾನ್ಯ ಕಾರಣಗಳು:

- ಆಯ್ಕೆಯಾಗಿರುವ ಫ್ಲ್ಯಾಗ್‌ಗಳು ನಿಮ್ಮ ಫೈಲ್‌ಗಳಿಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತಿಲ್ಲ.
- ಈಗಾಗಲೇ ಅನುವಾದಿತ ಫೈಲ್‌ಗಳು ಇದ್ದಿರಬಹುದು.
- ಮೂಲ ಫೈಲ್‌ಗಳು ಹೊರತಾಗಿರುವ ಡೈರೆಕ್ಟರಿಯ ಒಳಗೆ ಇರಬಹುದು.
- ಆಜ್ಞೆ ತಪ್ಪಾದ ಪ್ರಾಜೆಕ್ಟ್ ರೂಟ್‌ನಿಂದ ನಡುತ್ತಿದೆ.

ಪರಿಶೀಲನೆಗಳು:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

ಆಜ್ಞೆಯನ್ನು ಪ್ರಾಜೆಕ್ಟ್ ರೂಟ್ ಹೊರಗಡೆ ಓಡಿಸಿದಾಗ `--root-dir` ಬಳಸಿ.

## ಅಪ್ರತೀಕ್ಷಿತ ಲಿಂಕ್ ವರ್ತನೆ

ಲಿಂಕ್ ಮರುಬರೀಕರಣವು ಆಯ್ದ ವಿಷಯ ಪ್ರಕಾರಗಳ ಮೇಲೆ ಅವಲಂಬಿಸಿರುತ್ತದೆ:

- `-nb` ಸೇರಿಸಲಾಗಿದೆ: ನೋಟ್‌ಬುಕ್ ಲಿಂಕ್‌ಗಳು ಅನುವಾದಿತ ನೋಟ್ಬುಕ್‌ಗಳನ್ನು ಸೂಚಿಸಬಹುದು.
- `-nb` ತೆರವುಗೊಳಿಸಲಾಗಿದೆ: ನೋಟ್ಬುಕ್ ಲಿಂಕ್‌ಗಳು ಮೂಲ ನೋಟ್ಬುಕ್‌ಗಳತ್ತಲೇ ಇರುತ್ತವೆ.
- `-img` ಸೇರಿಸಲಾಗಿದೆ: ಚಿತ್ರ ಲಿಂಕ್‌ಗಳು ಅನುವಾದಿತ ಚಿತ್ರಗಳನ್ನು ಸೂಚಿಸಬಹುದು.
- `-img` ತೆರವುಗೊಳಿಸಲಾಗಿದೆ: ಚಿತ್ರ ಲಿಂಕ್‌ები ಮೂಲ ಚಿತ್ರಗಳತ್ತಲೇ ಇರುತ್ತವೆ.

ಎಲ್ಲಾ ಒಳಗಿನ ಲಿಂಕ್‌ಗಳು ಅನುವಾದಿತ ಔಟ್‌ಪುಟ್‌ಗಳನ್ನು ಆದ್ಯತೆಯಾಗಿ ಸೂಚಿಸುವಾಗ ಸಂಪೂರ್ಣ ವಿಷಯ ಅನುವಾದವನ್ನು ಓಡಿಸಿ:

```bash
translate -l "ko" -md -nb -img
```

ಅನುವಾದದ ನಂತರ ಲಿಂಕ್ ಪರಿಶೀಲನೆಯನ್ನು ಓಡಿಸಿ:

```bash
co-op-review -l "ko"
```

## ಮಾರ್ಕ್‌ಡೌನ್ ರೆಂಡರಿಂಗ್ ಸಮಸ್ಯೆಗಳು

ಅನುವಾದಿತ ಮಾರ್ಕ್‌ಡೌನ್ ತಪ್ಪಾಗಿ ರೆಂಡರ್ ಆಗಿದ್ದರೆ:

- ಫ್ರಂಟ್‌ಮ್ಯಾಟರ್ `---` ಮೂಲಕ ಪ್ರಾರಂಭವಾಗಿ ಅಂತ್ಯವಾಗುತ್ತದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ.
- ಮೂಲ ಮತ್ತು ಅನುವಾದಿತ ಫೈಲ್‌ಗಳಲ್ಲಿನ ಕೋಡ್ ಫೆನ್ಸ್‌ಗಳ ಸಂಖ್ಯೆಗಳು ಹೊಂದಿಹರುತ್ತವೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ.
- ಸಾಮಾನ್ಯ ರಚನಾ ಸಮಸ್ಯೆಗಳನ್ನು ಹಿಡಿಯಲು `co-op-review` ಅನ್ನು ಓಡಿಸಿ.
- ಔಟ್‌ಪುಟ್ ಹಾಳಾಗಿ ಇದ್ದರೆ ಆ ನಿರ್ದಿಷ್ಟ ಫೈಲ್ ಅನ್ನು ಮರುಅನುವಾದಿಸಿ.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action ಓಡಿತು ಆದರೆ ಯಾವುದೇ ಪುಲ್ ರಿಕ್ವೆಸ್ಟ್ ರಚಿಸಲ್ಪಟ್ಟಿಲ್ಲ

`peter-evans/create-pull-request` ವರದಿ ಮಾಡಿದರೆ ಶಾಖೆ ಬೇಸ್‌ಗಿಂತ ಮುಂದೆ ಇಲ್ಲವೆಂದು, ವರ್ಕ್‌ಫ್ಲೋ ಕಮಿಟ್ ಮಾಡಲು ಯಾವುದೇ ಫೈಲ್‌ಗಳನ್ನು ಕಂಡುಹಿಡಿಯಲಿಲ್ಲ.

ಸಾಧ್ಯವಾದ ಕಾರಣಗಳು:

- ಅನುವಾದ ರನ್ ಯಾವುದೇ ಬದಲಾವಣೆಗಳನ್ನು ಉತ್ಪನ್ನ ಮಾಡಲಿಲ್ಲ.
- `.gitignore` `translations/`, `translated_images/`, ಅಥವಾ ಅನುವಾದಿತ ನೋಟ್ಬುಕ್‌ಗಳನ್ನು ನಿರಾಕರಿಸುತ್ತಿದೆ.
- `add-paths` ರಚಿಸಿದ ಔಟ್‌ಪುಟ್ ಡೈರೆಕ್ಟರಿಗಳಿಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತಿಲ್ಲ.
- ಅನುವಾದ ಹಂತವು ಬೇಗನೆ ನಿಂತಿದೆ.

ಪರಿಹಾರಗಳು:

1. `translations/` ಅಥವಾ `translated_images/` ನಲ್ಲಿ ರಚಿಸಲ್ಪಟ್ಟ ಫೈಲ್‌ಗಳು ಇದ್ದವೆ ಎಂಬುದನ್ನು ದೃಢಪಡಿಸಿ.
2. `.gitignore` ರಚಿಸಲ್ಪಟ್ಟ ಔಟ್‌ಪುಟ್‌ಗಳನ್ನು ನಿರಾಕರಿಸದಂತಿರುತ್ತದೆ ಎಂದು ದೃಢಪಡಿಸಿ.
3. ಹೊಂದಿಕೆಯಾಗುವ `add-paths` ಅನ್ನು ಬಳಸಿ:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. ತಾತ್ಕಾಲಿಕವಾಗಿ ಅನುವಾದ ಕಮಾಂಡ್‌ಗೆ ಡಿಬಗ್ ಫ್ಲ್ಯಾಗ್‌ಗಳನ್ನು ಸೇರಿಸಿ:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. ವರ್ಕ್‌ಫ್ಲೋ ಅನುಮತಿಗಳಲ್ಲಿ ಇವುಗಳಿರುವುದನ್ನು ದೃಢಪಡಿಸಿ:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## ಅನುವಾದ ಗುಣಮಟ್ಟ

ಯಂತ್ರ ಅನುವಾದಗಳಿಗೆ ಮಾನವ ಪರಿಶೀಲನೆ ಅಗತ್ಯವಿರಬಹುದು. ಪ್ರಯೋಗಾತ್ಮಕ ಗುಣಮಟ್ಟ ಅಂಕೆಮಾಪನ ಮತ್ತು ಕಡಿಮೆ ವಿಶ್ವಾಸದ ಮರುಮರಮ್ಮತ್ತು ವರ್ಕ್‌ಫ್ಲೋಗಳನ್ನು ಮಾತ್ರ ಬೇಕಾದಾಗ `evaluate` ಅನ್ನು ಬಳಸಿ.

!!! warning "Experimental"
    `evaluate` ನಿಯಮಾಧಾರಿತ ಮತ್ತು LLM ಆಧಾರಿತ ಪರಿಶೀಲನೆಗಳನ್ನು ಬಳಸಬಹುದು, ಮತ್ತು ಇದರ ಸ್ಕೋರಿಂಗ್ ಮಾದರಿ ಮತ್ತು ಮೆಟಾಡೇಟಾ ವರ್ತನೆ ಬದಲಾಗಬಹುದು. ನಿಮ್ಮ ವರ್ಕ್‌ಫ್ಲೋ ಬದಲಾವಣೆಗಳಿಗೆ ಸಿದ್ಧವಿರುವವರೆಂದಾಗ ಮಾತ್ರ ಅದನ್ನು ಅಗತ್ಯ CI ಗೇಟ್ಗಳಲ್ಲಿ ಸೇರಿಸಿ.

ನಿಖರವಾದ CI ಪರಿಶೀಲನೆಗಳಿಗೆ ಬದಲಿಗೆ `co-op-review` ಅನ್ನು ಬಳಸಿ.
