# ചെറിയ ഒരു പ്രോജക്റ്റ് വിവർത്തനം ചെയ്യുക, തിരുത്തുക, അവലോകനം ചെയ്യുക

രണ്ടു ചെറു Markdown ഫയലുകളുമായി ഒരു ലക്ഷ്യഭാഷയെ തിരഞ്ഞെടുത്ത് തുടങ്ങുക. നിങ്ങൾ വിവർത്തനങ്ങൾ എവിടെ എഴുതപ്പെടുന്നത്, ഉറവിടം മാറ്റിയാൽ എന്താണ് സംഭവിക്കുന്നത്, ഫലം എങ്ങനെ പരിശോധിക്കാമെന്ന് കാണാം.

## രേഖപ്പെടുത്തിയ ഫലങ്ങൾ

ഈ ഉദാഹരണം 2026 സെപ്റ്റംബർ 19-ന് Co-op Translator 0.21.0 மற்றும் Azure OpenAI (`gpt-5-mini`) ഉപയോഗിച്ച് പ്രവർത്തിപ്പിച്ചു. മാറ്റം ചെയ്യാത്ത CLI കമാൻഡുകൾ built വീൽയും നിലവിലുള്ള Python ആശ്രിതങ്ങളും ഉപയോഗിച്ച് Click ന്റെ `CliRunner` വഴി വിളിക്കപ്പെട്ടു.

| ഘട്ടം | ഫലം |
| --- | --- |
| Preview | Exit 0; മോഡൽ വിവർത്തനം അഭ്യർത്ഥിച്ചിട്ടില്ല |
| Initial translation | Exit 0; 27.36 സെക്കന്റ് |
| Initial review | Exit 0 |
| Edit README and review | Exit 1; കാലഹരണപ്പെട്ട വിവർത്തനം കണ്ടെത്തി |
| Update translation | Exit 0; 22.17 സെക്കന്റ് |
| Review after update | Exit 0; തെറ്റ് അല്ലെങ്കിൽ മുന്നറിയിപ്പുകൾ ഇല്ല |
| Unchanged guide | README പുതുക്കുന്നതിന് മുൻപും ശേഷവും ബൈറ്റുകൾ സമാനമാണ് |
| Run again | Exit 0; എല്ലാ വിവർത്തന ഫയലുകൾക്കും സമാനമായ ഹാഷുകൾ |

ഇവ വ്യക്തിഗത റൺ അളവുകളാണ്, പ്രകടനനാമങ്ങളെയോ ഉറപ്പുകളെയോ സൂചിപ്പിക്കുന്നതല്ല. സെറ്റപ് സമയം ഉൾപ്പെടുത്തിയിട്ടില്ല; പ്രൊവൈഡറുടെ ബില്ലിംഗ് അളക്കപ്പെട്ടിട്ടില്ല. മാറ്റമില്ലാത്ത റൺ പോലും പ്രൊവൈഡർ ഹെൽത്ത് പരിശോധന നടത്ത võib.

[ആദ്യ പരിഭാഷ](../../assets/demo/before.txt), [നവീകരിച്ച പരിഭാഷ](../../assets/demo/after.txt), [സമ്പൂര്‍ണ്ണ പരിഭാഷയിലെ വ്യത്യാസം](../../assets/demo/update.diff), [കാലഹരണപ്പെട്ട അവലോകനം](../../assets/demo/review-stale.txt), [അവസാന അവലോകനം](../../assets/demo/review-after.txt), കൂടാതെ [റൺ വിശദാംശങ്ങൾ](../../assets/demo/results.json) പരിശോധിക്കുക. ക്യാപ്ചർ ചെയ്ത വ്യത്യാസം കാണിക്കുന്നതുപോലെ, മുഴുവൻ ഫയൽ പരിഭാഷ മറ്റ് വാക്കുപയോഗത്തിൽ മാറ്റം വരുത്താൻ സാധ്യതയുണ്ട്. രണ്ടും ടെക്സ്റ്റ് ആർട്ടിഫാക്ടുകളും സൃഷ്ടിച്ച ഡിസ്ക്ലെയിമർ നിലനിർത്തുന്നു.

മനുഷ്യൻ നടത്തിയ അവലോകനം ഇനിയും അത്രമേൽ പ്രധാനമാണ്: പിടിച്ചെടുത്ത അപ്ഡേറ്റ് `[사용 가이드](guide.md)을` എന്ന് ഉപയോഗിക്കുന്നു; കൊറിയൻ പാർട്ടിക്കിള്‍ ശരിയായി `[사용 가이드](guide.md)를` ആകണം. ടെക്സ്റ്റ് ആർട്ടിഫാക്ടുകൾ ഈ ഔട്ട്‌പുട്ട് തിരുത്താതെ അതേ പോലെ സൂക്ഷിക്കുന്നു, മോഡൽ ഔട്ട്‌പുട്ടിന്റെ ഒരു തിരുത്തിയ വിവർത്തനമായി അവതരിപ്പിക്കില്ല. ഘടനാത്മക അവലോകനം ഈ വാചകപ്രശ്നത്തിനും അനുയോജ്യമായി കടന്നുപോകുന്നു.

## 1. ഒരു ചെറു ഫോൾഡർ തയ്യാറാക്കുക

Python 3.11–3.14 ഉപയോഗിക്കുകയും [വർച്വൽ എൻവയർൺമെന്റ് സജ്ജീകരണം](configuration.md#local-runtime-setup) അനുസരിച്ച് ക്രമീകരിക്കുകയും ചെയ്യുക. ഈ ഉദാഹരണത്തിന് ഉപയോഗിച്ച പതിപ്പ് ഇൻസ്റ്റാൾ ചെയ്യുക:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

ഈ ഫോൾഡറിലേക്ക് [README.txt](../../assets/demo/README.txt)യും [guide.txt](../../assets/demo/guide.txt)യും ഡൗൺലോഡ് ചെയ്ത് അവ `README.md` மற்றும் `guide.md` ആയി സേവ് ചെയ്യുക. ഇവ ചെറിയ കാൽപനിക പ്രോജക്റ്റ് രേഖകളാണ്; യാതൊരു അപ്ലിക്കേഷൻ ഇൻസ്റ്റാളേഷനും ആവശ്യമില്ല.

README-ൽ ഒരു കോഡ് ബ്ലോക്കും `guide.md` എന്നതിനുള്ള ഒരു ലിങ്കും ഉൾപ്പെടുന്നു. അതിന്റെ അവസാന വാക്യം:

```text
Notes are saved locally.
```

ഈ ഫോൾഡറിൽ ഈ രണ്ട് സോഴ്‌സ് ഡോക്യുമെന്റുകൾ മാത്രമേ സൂക്ഷിക്കേണ്ടതുള്ളൂ. താഴെ കൊടുത്തിരിക്കുന്ന എല്ലാ കമാൻഡുകളും `translation-demo` എന്ന ഡയറക്ടറിയിൽ പ്രവർത്തിപ്പിക്കുമ്പോഴാണ് ശരി; Bash-ഉം PowerShell-ഉം രണ്ടിലും ഇത് പ്രവർത്തിക്കും.

## 2. ക്രെഡൻഷ്യൽ ഇല്ലാതെ പ്രിവ്യൂ

```bash
translate -l "ko" -md --dry-run
```

പ്രിവ്യൂ മോഡൽ വിളിക്കാതെ അല്ലെങ്കിൽ വിവർത്തനങ്ങൾ എഴുതാതെ ട്രാൻസ്ലേഷൻ പ്രവർത്തിയുടെ ഒരു കണക്കുകൂട്ടൽ നൽകുന്നു. ടോക്കൺ കണക്കുകൾ ബില്ലിംഗിന്റെ ഒരു ഉദ്ധരണമല്ല. ആദ്യ റൺ ഇരുവരും Markdown ഫയലുകളും പുതിയ ജോലി എന്നാവശ്യമായി തിരിച്ചറിയണം.

## 3. ഒരു സേവനദാതാവിനെ തിരഞ്ഞെടുത്ത് വിവർത്തനം చేయുക

ഒരു സേവനദാതാവിനെ ക്രമീകരിക്കാൻ [configuration guide](configuration.md) ഉപയോഗിക്കുക: Azure OpenAI, OpenAI, അല്ലെങ്കിൽ Anthropic. OpenAI-ക്കും Anthropic-ക്കും ടেক্স്റ്റ് വിവർത്തനത്തിന് Azure അക്കൗണ്ട് ആവശ്യമില്ല. ഈ ഉദാഹരണത്തിന് ഇമേജ് സേവനങ്ങൾ ആവശ്യമില്ല.

ലൊക്കൽ `.env` ഫയൽ ഉപയോഗിക്കുന്നുവെങ്കിൽ, `.env` ഈ ഫോൾഡറിന്റെ `.gitignore` ലിസ്റ്റിലേക്ക് ചേർക്കുക. വിവർത്തനക്കാൾസ് നിങ്ങളുടെ പ്രൊവൈഡറിന്റെ അക്കൗണ്ട് ഉപയോഗിച്ച് നടക്കും, ചിലവുണ്ടാകാം.

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

`translations/ko/README.md`യും `translations/ko/guide.md`യും തുറന്ന് നോക്കുക. കൊറിയൻ വാചകരൂപം, കോഡ് ബ്ലോക്ക്, വിവർത്തിക്കപ്പെട്ട README-യിൽ നിന്നും വിവർത്തിക്കപ്പെട്ട ഗൈഡിലേക്ക് പോകുന്ന ലിങ്ക് എന്നിവ പരിശോധിക്കുക. മോഡലുകൾക്കിടയിൽ ഔട്ട്പുട്ട് വ്യത്യാസപ്പെടുന്നുണ്ട്.

`co-op-review` പുതുതായ്മ, ഘടന, ലോക്കൽ ലിങ്കുകൾ എന്നിവ പരിശോധിക്കുന്നു. പാസ്സായെന്നത് ഭാഷാപരമായ കൃത്യതയ്ക്ക് ഗ്യാരന്റി നൽകുന്നില്ല. തുടരുന്നതിന് മുമ്പ് റിപ്പോർട്ട് ചെയ്ത ഏതെങ്കിലും പിശകുകളെ പരിഹരിക്കുക.

വിജയം നേടിയ ബേസ്ലൈൻ Git-ൽ രേഖപ്പെടുത്തുക (ആവശ്യമെങ്കിൽ ആദ്യം നിങ്ങളുടെ Git ഐഡന്റിറ്റി ക്രമീകരിക്കുക):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. ഉറവിടം മാറ്റുക

`README.md`-ൽ `Notes are saved locally.` എന്നത് ഇതോടെ മാറ്റുക:

```text
Notes are saved locally as Markdown files.
```

`guide.md` മാറ്റമില്ലാതെ വയ്ക്കുക. തുടർന്ന് ഈ കമാൻഡ് നടത്തുക:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

അവലോകനം README വിവർത്തനം കാലഹരണപ്പെട്ടതായി റിപ്പോർട്ട് ചെയ്ത് ഫേൽയറിൽ നിന്നും പുറത്താകണം. ഇത് പ്രതീക്ഷിച്ച ഇടനിലാവസ്ഥയാണ്. പ്രിവ്യൂ മാറ്റപ്പെട്ട README-ക്കുള്ള ജോബ് തിരിച്ചറിയണം.

## 5. പുതുക്കി ഡിഫ് പരിശോധിക്കുക

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

യഥാർത്ഥ ഡിഫ് പരിശോധിക്കുക: ഡിഫോൾട്ട് CLI മാറ്റപ്പെട്ട ഫയൽ വീണ്ടും വിവർത്തനം ചെയ്യുന്നതിനാൽ മോഡൽ ആ ഫയലിലെ മറ്റ് വാചകങ്ങളും അതിനനുസരിച്ച് പരിഷ്‌കരിക്കാൻ കഴിയും. മാറ്റമില്ലാത്ത ഗൈഡിന് ഡിഫ് ഉണ്ടാകരുത്. അവലോകനം README-യെ ഇനി കാലഹരണപ്പെട്ടതായി റിപ്പോർട്ട് ചെയ്യരുത്; മറ്റ് കണ്ടെത്തലുകൾതിരെ അന്വേഷിക്കുക, അവ നിർഽക്ഷിക്കരുത്.

മനുഷ്യൻ ചെയ്ത Markdown എഡിറ്റുകളുടെ ബ്ലോക്ക്-തല സംരക്ഷണത്തിന് [Python API](api.md)യിൽ ഒരു ഐച്ഛിക translation state provider ആവശ്യമാണ്. ഈ CLI കമാൻഡുകൾ അത് സജീവമാക്കുന്നില്ല.

## 6. മാറ്റങ്ങൾ ഇല്ലാതെ വീണ്ടും പ്രവർത്തിപ്പിക്കുക

പുതുക്കിയ സോഴ്‌സും വിവർത്തനവും commit ചെയ്യുക:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

നിലവിലുള്ള വിവർത്തനങ്ങളും മാറ്റമില്ലാത്ത കോൺഫിഗറേഷനും ഉള്ളപ്പോൾ, ട്രാൻസ്ലേറ്റർ ഫയലുകൾ അവഗണിക്കും. അന്തിമ Git കമാൻഡ് ഡിഫ് ഉണ്ടാക്കിയില്ലാതെ വിജയത്തോടെ പുറപ്പെടണം.
