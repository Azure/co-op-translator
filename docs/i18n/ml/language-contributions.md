# ഭാഷാ മെച്ചപ്പെടുത്തലുകൾക്ക് സംഭാവന

നിങ്ങളുടെ ഭാഷാ അറിവ് Co-op Translator മെച്ചപ്പെടുത്താൻ സഹായിക്കാം. ഒരു ഉദാഹരണം, ഒരു ശിപാർശചെയ്ത തിരുത്തൽ, ഒരു വിശദീകരണം എന്നിവ [വിവർത്തന പ്രതികരണ ഫോം](https://github.com/Azure/co-op-translator/issues/new?template=translation_feedback.yml) ഉപയോഗിച്ച് ആരംഭിക്കുക. നിങ്ങൾക്ക് കോഡ് എഴുതാനോ മോഡൽ റൺക്കായി പണം ചെലവഴിക്കാനോ ആവശ്യമില്ല.

## ഒരു റിപ്പോർട്ടിൽ നിന്ന് പങ്കുവെക്കപ്പെട്ട മെച്ചപ്പെടുത്തലിലേക്ക്

1. ഒരു സംഭാവനദാതാവ് ഉറവിട ഉദ്‌ദ്ധരണം, അതിന്റെ വിവർത്തനം, കൂടാതെ സമീപകാല സന്ദർഭം നൽകിയിടത്താണ്.
2. ഒരു ഭാഷാ റിവ്യൂവർ അർത്ഥം, സ്വാഭാവികത, നിർദ്ദേശം പ്രത്യേക ലൊക്കൽ അല്ലെങ്കിൽ കോഴ്‌സ് ആശ്രിതമാണോ ഇല്ലയോ എന്ന് പരിശോധിക്കുന്നു.
3. ഒരു മേൽനോട്ടക്കാരൻ പരിഹാരം സോഴ്‌സ് കോഴ്‌സിൽ ഉൾപ്പെടണമോ, പങ്കിടപ്പെട്ട ഭാഷാ നിർദ്ദേശത്തിൽ ചേർക്കണമോ, പദാവലി ക്രമീകരണത്തിലോ വിവർത്തന കോഡിലോ വേണമോ എന്നതിനെക്കുറിച്ച് തീരുമാനിക്കുന്നു.
4. ഒരു പങ്കിട്ട ചട്ടത്തിന്, റിപ്പോര്ട്ടുചെയ്ത ഉദാഹരണത്തിലും ബന്ധപ്പെട്ടിട്ടില്ലാത്ത ഉദാഹരണങ്ങളിലും മാറ്റം വരുത്തുന്നതിന് മുമ്പിലും ശേഷവും ഔട്ട്പുട്ടുകൾ താരതമ്യപ്പെടുത്താൻ മേൽനോട്ടക്കാരൻ ചെയ്യുന്നു. സംഭാവനക്കാർക്ക് ടൂൾ സ്വന്തം സൈഡിൽ ഓടിക്കേണ്ടതില്ലാതെയും ഈ ഔട്ട്പുട്ടുകൾ അവലോകനം ചെയ്യാം.
5. ഫലമായി സൃഷ്ടിച്ച PR റിപ്പോർട്ടിനെ ലിങ്കുചെയ്യുകയും ഉദാഹരണങ്ങളും റിവ്യൂയും നൽകിയ ആളുകളെ ക്രെഡിറ്റ് ചെയ്യുകയും ചെയ്യും. ഉപഭോഗ വിലാസങ്ങളിലുള്ള ഡിപ്ലോയ്‌മെന്റ് അല്ലെങ്കിൽ പുനഃസൃഷ്ടി വേർതിരിച്ച ഘട്ടമാണ്.

ഒരു റിപ്പോർട്ട് സ്വയംപ്രേരിതമായി പ്രോംപ്റ്റുകൾ മാറ്റുകയോ കോഴ്‌സ് വിവർത്തനങ്ങൾ പുനഃജനിപ്പിക്കുകയോ ചെയ്യില്ല. കോഴ്‌സ്-നിർദ്ദിഷ്ട തിരുത്തലുകൾ കോഴ്‌സ് റെപ്പോസിറ്ററിക്കൊപ്പം ബന്ധിപ്പിച്ചിരിക്കണം. കൈമാറ്റിച്ചിട്ടുള്ള ഒരു മാനുവൽ എഡിറ്റ് പിന്നീട് വീണ്ടും വിവർത്തനം ചെയ്യുമ്പോൾ നിലനിൽക്കുമെന്നും കരുതരുത്; ആ പ്രവൃത്തിപ്രവാഹത്തിന്റെ പെരുമാറ്റം സ്ഥിരീകരിക്കുക.

## നിലവിലുള്ള ഉദാഹരണം: ജാപ്പനീസ് Markdown ലിങ്കുകൾ

[ജാപ്പനീസ് നിർദ്ദേശ ഫയൽ](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/templates/language/ja.md) മോഡലിനോട് Markdown സെന്റാക്‌സ് സംരക്ഷിച്ചുകൊണ്ട് ലിങ്ക് ടെക്സ്റ്റ് വിവർത്തനം ചെയ്യാൻ നിർദ്ദേശിക്കുന്നു, കൂടാതെ ലിങ്ക് ലക്ഷ്യം മാറ്റരുത്. ഉദാഹരണത്തിന്, `[text](URL)` എന്ന രൂപത്തിലുള്ള ഒരു ലിങ്ക് `「text」（URL）` എന്നാക്കരുത്.

ഇത് ശരിയും തെറ്റായ ഔട്ട്പുട്ടിന്റെയും ഒരു ദൃശ്യമായ് ഉദാഹരണത്തോടെ പിന്തുണയുള്ള ഒരു ലക്ഷ്യബദ്ധമായ ഭാഷാ ചട്ടത്തിന്റെ ഉദാഹരണമാണ്. ഇത് പ്രോംപ്റ്റ് നിർദ്ദേശങ്ങൾ മാത്രം ശരിയായി Markdown ഉറപ്പുനൽകുന്നുവെന്ന തെളിവല്ല.

[Markdown prompt builder](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/utils/markdown/prompts.py) `templates/language/<language_code>.md` ലോഡ് ചെയ്യുമ്പോൾ ലെറ്റർകേസിൽാക്കിയ, തുണച്ച language code ഉപയോഗിക്കുന്നു. ഫയൽ ഇല്ലാത്ത പക്ഷം, സാധാരണ നിർദ്ദേശങ്ങൾ ഉപയോഗിക്കുന്നു. ഇത് Markdown പ്രോംപ്റ്റ് പാഥ് വിവരണം മാത്രമാണ്; എല്ലാ ചിത്രത്തിന്റെയും മറ്റുള്ള വിവർത്തന പാതകൾക്കും նույն നിർദ്ദേശങ്ങൾ ഉപയോഗിക്കുമെന്ന് കരുതരുത്.

[prompt tests](https://github.com/Azure/co-op-translator/blob/main/tests/co_op_translator/utils/markdown/test_prompts.py) ജാപ്പനീസ് നിർദ്ദേശങ്ങൾ ഉൾപ്പെടുന്നുവെന്ന് പരിശോധിക്കുന്നു. അതിൽ പ്രോംപ്റ്റ് അസംബ്ലിക്ക് സ്ഥിരീകരണം ലഭിക്കുന്നു, വിവർത്തന ഗുണമേന്മയേക്ക് അല്ല.

## ഒരു ഭാഷാ ചട്ടത്തിൽ എന്ത് ഉൾപ്പെടണം?

ഒരു ഉറവിട ഉദാഹരണം, പ്രതീക്ഷിച്ച പെരുമാറ്റം, ചട്ടം ബാധകമാകരുതാത്ത ഒരു എതിരെ-ഉദാഹരണം എന്നിവയോടുകൂടിയ ഒരു സൂക്ഷ്മം, ആവർത്തനയോഗ്യമായ തിരുത്തൽ നിർദേശിക്കുക. അർത്ഥം, പ്ലേസ്ഹോൾഡറുകൾ, കോഡ്, URLs, ഡോക്ക്യുമെന്റ് ഘടന എന്നിവ സംരക്ഷിക്കുക. ഒരാളുടെ ശൈലി.Preferences അല്ലെങ്കിൽ ഒരു കോഴ്‌സിന്റെ പദശേഖരത്തെ പൊതുവായ ചട്ടമാക്കുന്നതിൽ നിന്ന് ഒഴിവാകുക.

നിലവിലുള്ള [glossary implementation](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/glossary.py) പദങ്ങളെ വിവർത്തനത്തിൽ നിന്ന് സംരക്ഷിക്കുന്നു. ഇത് ഉറവിടം മുതൽ ലക്ഷ്യത്തിലേക്ക് പദാവലി നിഘണ്ടുവല്ല. സംഭാവനക്കാർക്ക് വാഗ്ദാനം ചെയ്യുന്നതിന് മുമ്പ് പുതിയ പദശൈലി പെരുമാറ്റം ചർച്ച ചെയ്യുക.

## സമൂഹ ഉദാഹരണം: ജാപ്പനീസ് ഉൽപ്പന്നനാമം സംബന്ധിച്ച റിപ്പോർട്ട്

[report #527](https://github.com/Azure/co-op-translator/issues/527)യില്‍, @hyoshioka0128 ജാപ്പനീസ് വിവർത്തനത്തിൽ ഉൽപ്പന്നനാമം `Co-op Translator` എന്നതിൽ നിന്ന് `Co-op 翻訳` ആയി മാറിയതായി കണ്ടെത്തി. റിപ്പോർട്ടിൽ ബാധിക്കപ്പെട്ട ഡോക്യുമെന്റിലേക്കുള്ള ലിങ്കും സ്‌ക്രീൻഷോട്ടും ഉൾപ്പെടുത്തിയതോടെ പ്രശ്നം എളുപ്പത്തിൽ കണ്ടെത്താനാകുകയും ചെയ്‍തു.

സംഭാവനദാതാവ് [സംബന്ധിച്ച കോഴ്‌സ് PR](https://github.com/microsoft/AZD-for-beginners/pull/109) എന്നതും ലിങ്ക് ചെയ്തു. ഇഷ്യു ചര്‍ച്ചയിൽ, മേൽനോട്ടക്കാരൻ റിപ്പോർട്ട് അംഗീകരിക്കുകയും നാമം എന്തുകൊണ്ട് മാറിയതായി അന്വേഷിക്കുന്നതിനെക്കുറിച്ച്, പദസംരക്ഷണം, ഗ്ലോസറി പെരുമാറ്റം, വിവർത്തന പാത എന്നിവ പരിശോധിക്കാമെന്ന് നിർദ്ദേശിക്കുകയും ചെയ്തു.

ഇത് ഒരു ചെറിയ റിപ്പോർട്ട് എങ്ങനെയാണ് വ്യക്തിഗത വാക്കൊടിച്ചുക്കോ തിരുത്തലിനപ്പുറം അന്വേഷണത്തിന് സഹായകമാവാൻ കഴിയുന്നതെന്ന് കാണിക്കുന്നു. ഇത് സ്ഥിരീകരിക്കപ്പെട്ട മുന്‍പ്/ശേഷം ഫലമോ അല്ലെങ്കിൽ മുകളിൽ ജാപ്പനീസ് Markdown-ലിങ്ക് നിർദ്ദേശങ്ങൾ ഈ ഉൽപ്പന്നനാമ വിഷയത്തിന് പരിഹാരം എത്തിച്ചപ്പോൾനെന്നും തെളിവല്ല.

നിങ്ങൾക്ക് സമാനമായി സംഭാവന ചെയ്യാം: Original ടെക്സ്റ്റ്, നിലവിലെ വിവർത്തനം, ശിപാർശചെയ്ത തിരുത്തൽ, അതിന്റെ പ്രാധാന്യം എന്നിവ പങ്കുവെക്കുക. ആവശ്യമുള്ളപ്പോൾ ഡോക്യുമെന്റ് ലിങ്കോ സ്‌ക്രീൻഷോട്ടോ ചേർക്കുക. കാരണത്തെ പരിശോധന നടത്താനോ റിപ്പോര്ട്ടുചെയ്യുന്നതിന് മുമ്പ് പ്രോംപ്റ്റ് എഴുതാനോ നിങ്ങൾ സാദ്ധ്യതയില്ല.

## ഒരു ചട്ടം സ്വീകരിക്കുന്നതിന് മുമ്പുള്ള സ്ഥിരീകരണ നടപടികൾ

ബെസ്‌ലൈനിനും പ്രതിനിധി റൺസിനും ഒരേ ഉറവിട സാമ്പിളുകളും, ട്രാൻസിലേറ്റർ റിവിഷനും, പ്രൊവൈഡർ/മോഡലും, ജനറേഷൻ ക്രമീകരണങ്ങളും ഉപയോഗിക്കുക — നിർദേശിച്ച ഏക ചിട്ട മാത്രം മാറ്റം വരുത്തുക. യഥാർത്ഥ പ്രോംപ്റ്റ് മാറ്റവും ഔട്ട്പുട്ടുകളും രേഖപ്പെടുത്തി; ഔട്ട്പുട്ട് വ്യത്യാസാന്തരതയിൽ നിന്നുള്ള സ്ഥിരമായ പ്രതിഫലനമെന്ന് തിരിച്ചറിഞ്ഞു വേണമെങ്കിൽ ഉദാഹരണങ്ങൾ ആവർത്തിക്കുക. റിപ്പോര്ട്ടുചെയ്ത പരാജയം, മായ്ച്ചുപോയ സന്ദർഭങ്ങൾ, ഇതിനകം ശരിയായി വിവർത്തനം ചെയ്യുന്ന ഉദാഹരണങ്ങൾ എന്നിവ ഉൾപ്പെടുത്തുക.

ഘടനാപരമായ സ്ഥിരതകളെ ലിംഗ്വിസ്റ്റിക് വിധികളിൽ നിന്ന് വേർതിരിച്ച് പരിശോധിക്കുക. പ്രോംപ്റ്റ് ലോഡിംഗ് പരീക്ഷണം വിജയമെന്നത് ഗുണനിലവാരം മൂല്യനിർണയമല്ല, ഒറ്റപ്പേർ ഓർമ്മിച്ചിരിക്കുന്ന ഒരു വ്യാകുല്യവാക്യം മാത്രം സാധുവായ ഒരു വിവർത്തനമല്ല. സന്ദർഭം, മോഡൽ റൺസ്, അല്ലെങ്കിൽ ഭാഷാ റിവ്യൂ ഇല്ലെങ്കിൽ, പ്രശ്നം നന്നാക്കിയതായി അവകാശപ്പെടുകയ്ക്കു പകരം നിർദേശം പെൻഡിംഗിൽ സൂക്ഷിക്കുക.
