# പരിപാലകരുടെ ഗൈഡ്

ഈ പേജ് API, CLI, மற்றும் ഡോക്യുമെന്റേഷൻ സൈറ്റ് എങ്ങനെ സംയോജിപ്പിച്ചിട്ടുള്ളുവെന്ന് സംക്ഷേപത്തില്‍ വിവരിക്കുന്നു.

## പൊതു API പരിധി

സ്ഥിരമായ Python API താഴെ നിന്നും എക്‌സ്പോർട്ട് ചെയ്യപ്പെടുന്നു:

```python
co_op_translator.api
```

പൊതു API ഉള്ളടക്കം തർജ്ജമചെയ്യുന്ന സഹായികൾ, പാത പുനഃരചന സഹായികൾ, പ്രോജക്റ്റ് ഓർക്കസ്ട്രേഷൻ, റിവ്യൂ എന്നീ ഭാഗങ്ങളായി ക്രമീകരിച്ചിരിക്കുന്നു:

```python
from co_op_translator.api import (
    ImageTranslationOptions,
    MarkdownTranslationOptions,
    NotebookTranslationOptions,
    TranslationBaseline,
    TranslationStateProvider,
    TranslationUpdate,
    run_review,
    run_translation,
    rewrite_markdown_paths,
    rewrite_notebook_paths,
    translate_image_content,
    translate_markdown_content,
    translate_notebook_content,
    translate_project,
)
```

`TranslationStateProvider` ഹോസ്റ്റുചെയ്ത ഇന്റഗ്രേഷനുകൾക്കുള്ള സ്ഥിരതയുടെ പരിധിയാണ്.
ജനനമായ സ്ഥാനാർഥികളെ അംഗീകരിച്ച ബേസ്ലൈനുകളിൽ നിന്ന് വേർതിരിച്ചിരിക്കാൻ ഇത് നിർബന്ധമാണ്, അതിനാൽ ഒരു
മാർജ് ചെയ്തിട്ടില്ലാത്ത തർജ്ജമ യഥാർത്ഥ സത്യത്തിന്റെ ഉറവിടമാകരുത്.

പുതിയ പൊതുവായ APIകൾ ചേർക്കുമ്പോൾ, അപ്ഡേറ്റ് ചെയ്യുക:

- `src/co_op_translator/api/__init__.py`
- `docs/api.md`
- `tests/co_op_translator/` കീഴിലുള്ള ബന്ധപ്പെട്ട API ടെസ്റ്റുകൾ, ഉദാഹരണത്തിന് `test_api.py` അല്ലെങ്കിൽ `test_review_api.py`

പ്രോജക്റ്റ് നേരിട്ട് അവ പിന്തുണയ്ക്കണമെന്ന് ഉദ്ദേശിച്ചിട്ടില്ലെങ്കിൽ താഴ്ന്നതലത്തിലുള്ള `core` മോഡ്യൂളുകൾ സ്ഥിര API ആയി രേഖപ്പെടുത്താൻ ഒഴിവാക്കുക.

## CLI എൻട്രി പോയിന്റുകൾ

പാക്കേജ് ഈ Poetry സ്ക്രിപ്റ്റുകൾ നിർവ്വചിക്കുന്നു:

```toml
[tool.poetry.scripts]
translate = "co_op_translator.__main__:main"
evaluate = "co_op_translator.__main__:main"
migrate-links = "co_op_translator.__main__:main"
co-op-review = "co_op_translator.__main__:main"
co-op-translator-mcp = "co_op_translator.mcp.server:main"
```

`src/co_op_translator/__main__.py` സ്ക്രിപ്റ്റ് പേരിന്റെ അടിസ്ഥാനത്തിൽ ഡിസ്‌പാച്ച് ചെയ്യുന്നു:

- `translate` വിളിക്കുന്നത് `co_op_translator.cli.translate.translate_command` ആണ്
- `evaluate` വിളിക്കുന്നത് `co_op_translator.cli.evaluate.evaluate_command` ആണ്
- `migrate-links` വിളിക്കുന്നത് `co_op_translator.cli.migrate_links.migrate_links_command` ആണ്
- `co-op-review` വിളിക്കുന്നത് `co_op_translator.cli.review.review_command` ആണ്

`co-op-translator-mcp` `__main__.py` നെ മറികടന്ന് നേരെ `co_op_translator.mcp.server:main` നെ വിളിക്കുന്നു.

CLI ഓപ്ഷനുകൾ ചേർക്കുകയോ മാറ്റുകയോ ചെയ്യുമ്പോൾ, അപ്ഡേറ്റ് ചെയ്യുക:

- ബന്ധപ്പെട്ട `src/co_op_translator/cli/*.py` കമാൻഡ്
- `docs/cli.md`
- CLI-സംബന്ധിച്ച ടെസ്റ്റുകൾ, പെരുമാറ്റം മാറുന്നെങ്കിൽ

## MCP server

MCP സെർവർ നടപ്പിലപ്പെടുത്തിയിരിക്കുന്നത്:

```python
co_op_translator.mcp.server
```

സർവർ ഉദ്ദേശപൂർവമായി താഴ്ന്നതലത്തിലുള്ള `core` മോഡ്യൂളുകൾ നേരിട്ട് വിളിക്കാതെ പൊതു Python API നെ റാപ്പ് ചെയ്യുന്നു. ഈ പരിധി അക്ഷുണ്ണമായി നിലനിർത്തുക, അതോടെ MCP ക്ലയന്റുകൾ, Python കോളറുകൾ, CLI എന്നിവ ഒരേ പെരുമാറ്റം പങ്കിടും.

MCP ടൂളുകൾ ചേർക്കുകയോ മാറ്റുകയോ ചെയ്യുമ്പോൾ, അപ്ഡേറ്റ് ചെയ്യുക:

- `src/co_op_translator/mcp/server.py`
- `tests/co_op_translator/test_mcp_server.py`
- `docs/mcp.md`
- `docs/api.md`, പൊതു API ഉപരിതലം മാറ്റം സംഭവിച്ചാൽ

റീപോസിറ്ററി തർജ്ജമ ടൂളുകൾ MCP മുഖേന മോഡൽ-കോളബിളായി പ്രവർത്തിച്ചേക്കാം, പല ഫയലുകളും എഴുതാനും കഴിയും. ഡീഫോൾട്ടായി `dry_run=True` ആണ് നിലനിര്‍ത്തേണ്ടത്, non-dry-run പ്രോജക്റ്റ് തർജ്ജമയ്ക്ക് മുമ്പ് `confirm_write=True` ആവശ്യമാണ്.

## തർജ്ജമ പ്രവാഹം

ഉയർന്ന തലത്തിലുള്ള പ്രോജക്റ്റ് തർജ്ജമ പ്രവാഹം ഇപ്രകാരം ആണ്:

1. CLI ആർഗ്യുമെൻറുകൾ അല്ലെങ്കിൽ API പാരാമീറ്ററുകൾ പാർസ് ചെയ്യുക.
2. `LLMConfig` ഉപയോഗിച്ച് LLM കോൺഫിഗറേഷൻ സാധുവാണെന്ന് പരിശോധിക്കുക.
3. ചിത്രം തർജ്ജമ തിരഞ്ഞെടുക്കപ്പെട്ടാൽ Azure AI Vision സാധുവാണോ എന്ന് പരിശോധിക്കുക.
4. ഭാഷാ കോഡുകൾ സാധാരണ രൂപത്തിലാക്കുക.
5. പാരമ്പര്യ ഭാഷാ ഫോൾഡർ ഉപനാമങ്ങൾ കണ്ടെത്തുക.
6. തർജ്ജമയുടെ വോള്യം വിലയിരുത്തുക.
7. ആവശ്യമായ എല്ലാ സാഹചര്യങ്ങളിലും README ലെ ഭാഷ/കോർസ് വിഭാഗങ്ങൾ അപ്ഡേറ്റ് ചെയ്യുക.
8. പ്രോജക്റ്റ് തർജ്ജമ `ProjectTranslator`-ന് ചുമതല നൽകുക.
9. `ProjectTranslator` ഫയൽ പ്രോസസ്സിംഗ് `TranslationManager`-ന് ചുമതലപ്പെടുത്തുന്നു.

`TranslationManager` പ്രത്യേക ഫയൽ തരം മിക്‌സിനുകൾകൊണ്ടാണ് രൂപം കൊണ്ടത്:

- `ProjectMarkdownTranslationMixin` Markdown ഫയലുകളുടെ വായന, ഉള്ളടക്ക തർജ്ജമ, പാത പുനഃരചന, മെറ്റാഡേറ്റ, ഡിസ്ക്ലെയിമറുകൾ, എഴുതലുകൾ എന്നിവ കൈകാര്യം ചെയ്യുന്നു.
- `ProjectNotebookTranslationMixin` നോട്ട്‌ബുക്ക് ഫയൽ വായന, Markdown-സെൽ തർജ്ജമ, പാത പുനഃരചന, മെറ്റാഡേറ്റ, ഡിസ്ക്ലെയിമറുകൾ, എഴുതലുകൾ എന്നിവ കൈകാര്യം ചെയ്യുന്നു.
- `ProjectImageTranslationMixin` ചിത്രം കണ്ടെത്തൽ, ടെക്സ്റ്റ് എക്സ്ട്രാക്ഷൻ/തർജ്ജമ, റെൻഡർ ചെയ്ത ചിത്രം എഴുതൽ, മെറ്റാഡേറ്റ എന്നിവ കൈകാര്യം ചെയ്യുന്നു.

താഴ്ന്നതല ഉള്ളടക്ക APIകൾ പ്രോജക്റ്റ് വർക്‌ഫ്ലോ ഒഴിവാക്കുന്നു:

1. `translate_markdown_content` and `translate_notebook_content` മെമ്മറിയിലുള്ള ഉള്ളടക്കമാത്രമേ തർജ്ജമ നടത്തുകയുള്ളൂ.
2. `translate_image_content` ഒരു ഒറ്റ ചിത്രത്തിലുള്ള ടെക്സ്റ്റ് തർജ്ജമ ചെയ്ത് റെൻഡർ ചെയ്ത ചിത്രം ഒബ്ജക്ട് മടക്കുന്നു.
3. `rewrite_markdown_paths` and `rewrite_notebook_paths` വ്യക്തമായ പോസ്റ്റ്-പ്രോസസ്സിംഗ് സഹായികളാണ്. അവ തർജ്ജമ ചെയ്യുകയോ പ്രോജക്റ്റ് എഴുതലുകൾ നടത്തുകയോ ചെയ്യില്ല.

## അവലോകന പ്രവാഹം

നിശ്ചിതനായ അവലോകന പ്രവാഹം ഇപ്രകാരം ആണ്:

1. CLI ആർഗ്യുമെൻറുകൾ അല്ലെങ്കിൽ API പാരാമീറ്ററുകൾ പാർസ് ചെയ്യുക.
2. അഭ്യർത്ഥിച്ച ഭാഷാ കോഡുകൾ സാധാരണമാക്കുക.
3. `root_dir`, `root_dirs`, അല്ലെങ്കിൽ `groups` എന്നിവയിൽ നിന്ന് ഒന്ന് അല്ലെങ്കിൽ അതിലധികം റിവ്യൂ ലക്ഷ്യങ്ങൾ നിർമ്മിക്കുക.
4. ഐച്ഛികമായി സോഴ്‌സ് ഫയലുകൾ `--changed-from` ഉപയോഗിച്ച് പരിധീകരിക്കുക.
5. ഘടന, തർജ്ജമയുടെ നവീകരണ നില, Markdown സമഗ്രത, കൂടാതെ ലോക്കൽ ലിങ്ക്/ഇമേജ് പാതകൾ എന്നിവയ്ക്ക് നിർണായക പരിശോധനകൾ നടത്തുക.
6. ടെക്സ്റ്റ് ഔട്ട്പുട്ടോ GitHub-ശൈലി Markdown ഔട്ട്പുട്ടോ പ്രിന്റ് ചെയ്യുക.
7. അവലോകനത്തിൽ പിശകുകൾ കണ്ടെത്തിയാൽ പരാജയാവസ്ഥയോടെ പുറത്തുവരിക.

അവലോകന പ്രവാഹത്തിന് API കീകൾ ആവശ്യമായില്ല; ഇത് ലോക്കൽ ചെക്കുകൾക്കോ ഓപ്-ഇൻ ഉപഭോക്തൃ CI-ക്കോ ലഭ്യമാണ്. ഈ റീപ്പോസ്‌റ്ററി എല്ലാ പുൾ റിക്വസ്റ്റ്-കളിലും സ്വയം `co-op-review` ഓട്ടോമാറ്റിക്കായി റൺ ചെയ്യരുത്.

## ഡോക്യുമെന്റേഷൻ സൈറ്റ്

ഡോക്സൈറ്റ് താഴെ പറയുന്നവ വഴി കോൺഫിഗർ ചെയ്യപ്പെട്ടിരിക്കുന്നു:

```text
mkdocs.yml
requirements-docs.txt
docs/
```

`docs/` ഡയറക്ടറി ആണ് ഔദ്യോഗിക ഡോക്യുമെന്റേഷൻ ഉറവിടം. പ്രോജക്റ്റ് നിശ്ചയപൂർവം മറ്റൊരു പ്രസിദ്ധീകരിച്ച ഡോക്യുമെന്റേഷൻ ഉപരിതലം അവതരിപ്പിക്കാത്തയുടെ വരെ ഈ ഡയറക്ടറിയിന് പുറത്ത് പുതിയ end-user ഗൈഡുകൾ ചേർക്കരുത്.

Build locally:

```bash
python -m pip install -r requirements-docs.txt
python -m mkdocs build --strict
```

Preview locally:

```bash
python -m mkdocs serve
```

തയാറാക്കിയ സൈറ്റ് `site/`-ലേക്ക് എഴുതപ്പെടുന്നു, അത് git tarafından-ignore ചെയ്യപ്പെട്ടിരിക്കുന്നു.

## GitHub Pages വർക്‌ഫ്ലോ

`.github/workflows/docs.yml` pull request-കളിൽ സൈറ്റ് നിർമ്മിക്കുകയും `main`-ലേക്കുള്ള pushes-ൽ ഡിപ്ലോയ് ചെയ്യുകയും ചെയ്യുന്നു.

വർക്‌ഫ്ലോ ഇൻസ്റ്റാൾ ചെയ്യുന്നത്:

```bash
pip install -r requirements-docs.txt
```

ഡോക്‌സ് വർക്‌ഫ്ലോ ഡോക്യുമെന്റേഷൻ ടൂൾചെയിൻ മാത്രം ഇൻസ്റ്റാൾ ചെയ്യുന്നു. `mkdocs.yml` `mkdocstrings` നെ `src/`-യെ കാണിച്ചുകൊടുക്കുന്നു, അതുകൊണ്ട് പൊതു API പേജുകൾ മുഴുവൻ റൺടൈം ഡെപന്റൻസി സെറ്റ് ഇൻസ്റ്റാൾ ചെയ്യാതെ തന്നെ സോഴ്‌സ് ട്രീയിൽ നിന്ന് റെൻഡർ ചെയ്യാൻ സാധിക്കും. ഭാവിയിലെ API ഡോക്‌സ് ബിൽഡ് സമയത്ത് ഐച്ഛിക റൺടൈം പ്രൊവൈഡറുകൾ ഇമ്പോർട്ട് ചെയ്യേണ്ടതുണ്ടെങ്കിൽ, `.github/workflows/docs.yml`യും ഈ ഗൈഡും ഒരുമിച്ച് അപ്ഡേറ്റ് ചെയ്യുക.
