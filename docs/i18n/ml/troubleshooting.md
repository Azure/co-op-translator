# പ്രശ്നപരിഹാരം

ഈ പേജ് വിവർത്തന റൺ അനपेേക്ഷിതമായി വിജയം പ്രാപിച്ചപ്പോൾ, കോൺഫിഗറേഷനിൽ പരാജയപ്പെടുമ്പോൾ, അല്ലെങ്കിൽ അവലോകനത്തിനായി ഔട്ട്പുട്ട് ഉണ്ടായിരിക്കുന്നപ്പോൾ ഉപയോഗിക്കുക.

## ഇവിടെ ആരംഭിക്കുക

1. ആദ്യം കേന്ദ്രീകൃതമായ ഒരു കമാൻഡ് നടത്തുക, ഉദാഹരണത്തിന് `translate -l "ko" -md`.
2. Add `-d` for console debug logs.
3. Add `-s` to save debug logs under `<root-dir>/logs/`.
4. പരിഭാഷ കഴിഞ്ഞ ശേഷം പുതുതായ്മ, ഘടന, പ്രാദേശിക ലിങ്കുകൾ പരിശോധിക്കാൻ `co-op-review` ഓടിക്കുക.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## കോൺഫിഗറേഷൻ പിശകുകൾ

### ഭാഷാ മോഡൽ ദാതാവ് ഇല്ല

പിശക്:

```text
No language model configuration found.
```

പരിഹാരം:

- Azure OpenAI, OpenAI, അല്ലെങ്കിൽ Anthropic ക്രമീകരിക്കുക.
- കമാൻഡ് പ്രവർത്തിക്കുന്ന പരിസ്ഥിതിയിൽ വേരിയബിളുകൾ ഉണ്ടെന്ന് സ്ഥിരീകരിക്കുക.
- പ്രാദേശിക ഉപയോഗത്തിന്, അവ പ്രോജക്ടിന്റെ റൂട്ടിലുള്ള `.env`-ൽ വെക്കുക.

See [ക്രമീകരണം](configuration.md).

### Azure AI Vision ഇല്ലാതെ ഇമേജ് വിവർത്തനം

പിശക്:

```text
Image translation requested but Azure AI Service is not configured.
```

പരിഹാരം:

- `AZURE_AI_SERVICE_API_KEY` ചേർക്കുക.
- `AZURE_AI_SERVICE_ENDPOINT` ചേർക്കുക.
- അല്ലെങ്കിൽ `translate -l "ko" -md` പോലെയുള്ള ടെക്‌സ്‌റ്റ്-ഓൺലി കമാൻഡ് പ്രവർത്തിപ്പിക്കുക.

### അസാധുവായ കീ അല്ലെങ്കിൽ എൻഡ്പോയിന്റ്

ലക്ഷണങ്ങളായി `401`, പരിമിതപ്പെടുത്തിയ അനുമതി പിശകുകൾ, അല്ലെങ്കിൽ എൻഡ്പോയിന്റ് ആക്‌സസ് പിശകുകൾ കാണപ്പെട്ടേക്കാം.

പരിഹാരം:

- കീ എൻഡ്പോയിന്റ് ഉള്ള അതേ Azure റിസോഴ്സിന് ചേർന്നതാണെന്ന് സ്ഥിരീകരിക്കുക.
- `-img` ഉപയോഗിക്കുമ്പോൾ ആ റിസോഴ്സ് Vision പിന്തുണയ്ക്കുന്നതായി സ്ഥിരീകരിക്കുക.
- Azure OpenAI ഡిప്ലോയ്മെന്റ് പേര് மற்றும் API വേർഷൻ നിങ്ങളുടെ ഡിപ്ലോയ്മെന്റുമായി പൊരുത്തപ്പെടുന്നുണ്ടെന്ന് സ്ഥിരീകരിക്കുക.
- ഡീബഗ് ലോഗുകളോടെ പ്രവർത്തിപ്പിക്കുക: `translate -l "ko" -md -d -s`.

## യാതൊരു ഫയലും വിവർത്തനം ചെയ്തില്ല

സാധാരണ കാരണങ്ങൾ:

- തിരഞ്ഞെടുക്കപ്പെട്ട ഫ്ലാഗുകൾ നിങ്ങളുടെ ഫയലുകളുമായി പൊരുത്തപ്പെടുന്നില്ല.
- ഇതിനകം വിവർത്തനമാക്കിയ ഫയലുകൾ നിലവിലുണ്ട്.
- മൂല ഫയലുകൾ ഒഴിവാക്കിയ ഡയറക്ടറികളിൽ ഉണ്ട്.
- കമാൻഡ് തെറ്റായ പ്രോജക്ട് റൂട്ടിൽ നിന്നാണ് പ്രവർത്തിക്കുന്നത്.

പരിശോധനകൾ:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

കമാൻഡ് പ്രോജക്ട് റൂട്ടിന് പുറത്താണ് പ്രവർത്തിക്കുന്നത് എങ്കിൽ `--root-dir` ഉപയോഗിക്കുക.

## പ്രതീക്ഷിക്കാത്ത ലിങ്ക് പെരുമാറ്റം

ലിങ്ക് പുനഃരചയനം (rewriting) തിരഞ്ഞെടുക്കപ്പെട്ട ഉള്ളടക്ക തരം അനുസരിച്ചാണ്.

- `-nb` ഉൾപ്പെട്ടാൽ: നോട്ട്ബുക്ക് ലിങ്കുകൾ വിവർത്തന നോട്ട്ബുക്കുകളിലേക്കാണ് സൂചിപ്പിക്കാനിടയായിരിക്കുന്നത്.
- `-nb` ഒഴിവാക്കിയാൽ: നോട്ട്ബുക്ക് ലിങ്കുകൾ ഉറവിലെ നോട്ട്ബുക്കുകളിലേയ്ക്കേയും സൂചിപ്പിച്ചിരിക്കാം.
- `-img` ഉൾപ്പെട്ടാൽ: ഇമേജ് ലിങ്കുകൾ വിവർത്തന ഇമേജുകളിലേക്കോ സൂചിപ്പിക്കാവുന്നതാണ്.
- `-img` ഒഴിവാക്കിയാൽ: ഇമേജ് ലിങ്കുകൾ സോഴ്‌സ് ഇമേജുകളിലായിരിക്കും സൂചിപ്പിക്കുന്നത്.

എല്ലാ ആഭ്യന്തര ലിങ്കുകളും വിവർത്തന ഔട്ട്പുട്ടുകളെ പ്രാധാന്യം നൽകണമെന്ന് ഉണ്ടായാൽ മുഴുവൻ ഉള്ളടക്ക വിവർത്തനം നടത്തുക:

```bash
translate -l "ko" -md -nb -img
```

വിവർത്തനത്തിന് ശേഷം ലിങ്ക് അവലോകനം നടത്തുക:

```bash
co-op-review -l "ko"
```

## മാർക്ക്ഡൗൺ റെൻഡറിംഗ് പ്രശ്നങ്ങൾ

വിവർത്തനം ചെയ്ത Markdown തെറ്റായി റെൻഡർ ചെയ്യുകയാണെങ്കിൽ:

- ഫ്രണ്ട്‌മാറ്റർ `---` ഉപയോഗിച്ച് തുടങ്ങുകയും അവസാനിക്കുകയാണെന്ന് പരിശോധിക്കുക.
- സോഴ്‌സ് ഫയലിനും വിവർത്തന ഫയലിനും കോഡ് ഫെൻസ് എണ്ണങ്ങൾ പൊരുത്തപ്പെടുന്നുണ്ടെന്ന് പരിശോധിക്കുക.
- സാധാരണ ഘടനാ പ്രശ്നങ്ങൾ പിടിക്കാൻ `co-op-review` പ്രവർത്തിപ്പിക്കുക.
- ഔട്ട്പുട്ട് തകരാറിലായിരുന്നെങ്കിൽ പ്രത്യേക ഫയൽ വീണ്ടും വിവർത്തനം ചെയ്യുക.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action പ്രവർത്തിച്ചെങ്കിലും യാതൊരു പുൾ റിക്വസ്റ്റും സൃഷ്ടിക്കപ്പെട്ടില്ല

`peter-evans/create-pull-request` ബ്രാഞ്ച് ബേസ്-നെ അപേക്ഷിച്ച് മുന്നിൽ ഇല്ലെന്ന് റിപ്പോർട്ട് ചെയ്താൽ, വർക്ക്‌ഫ്ലോയ്ക്ക് കമ്മിറ്റ് ചെയ്യാനുള്ള ഫയലുകൾ കണ്ടെത്തിയില്ല.

സാധ്യതയുള്ള കാരണംകൾ:

- വിവർത്തന റൺ യാതൊരു മാറ്റവും ഉള്പാദിപ്പിച്ചില്ല.
- `.gitignore` `translations/`, `translated_images/`, അല്ലെങ്കിൽ വിവർത്തനം ചെയ്ത നോട്ട്ബുക്കുകൾ ഒഴിവാക്കിയിട്ടുണ്ടാവാം.
- `add-paths` ജനറേറ്റുചെയ്‌ത ഔട്ട്പുട്ട് ഡയറക്ടറികളുമായി പൊരുത്തപ്പെടുന്നില്ല.
- വിവർത്തന ഘട്ടം മുന്‍കോടി മുമ്പേ അവസാനിച്ചു.

പരിഹാരങ്ങൾ:

1. `translations/` അല്ലെങ്കിൽ `translated_images/`-ൽ ജനറേറ്റുചെയ്‍ത ഫയലുകൾ നിലനിന്നിരിക്കുമെന്ന് নিশ্চিতിക്കുക.
2. `.gitignore` ജനറേറ്റുചെയ്‌ത ഔട്ട്പുട്ടുകൾ അവഗണിക്കുന്നില്ലെന്ന് സ്ഥിരീകരിക്കുക.
3. ഒത്തുചേരുന്ന `add-paths` ഉപയോഗിക്കുക:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. താൽക്കാലികമായി translate കമാൻഡിൽ ഡീബഗ് ഫ്ലാഗുകൾ ചേർക്കുക:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. workflow അനുമതികളിൽ താഴെ ഉൾപ്പെടുന്നുവെന്ന് സ്ഥിരീകരിക്കുക:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## വിവർത്തന ഗുണമേൻമ

മെഷീൻ വിവർത്തനങ്ങൾക്ക് മനുഷ്യപരിശോധന ആവശ്യമുണ്ടാകാം. പരീക്ഷണാത്മക നിലവാര സ്കോറിംഗ് અને കുറഞ്ഞ ആത്മവിശ്വാസമുള്ള റീപെയർ വർക്‌ഫ്ലോകളുടെ ആവശ്യമായപ്പോൾ മാത്രം `evaluate` ഉപയോഗിക്കുക.

!!! warning "പരീക്ഷണാത്മക"
    `evaluate` നിയമാധിഷ്ഠിതവും LLM-ആധാരിതവും ആയ ചെക്കുകൾ ഉപയോഗിക്കാം, അതിന്റെ സ്കോറിംഗ് മോഡൽയും മെറ്റാഡേറ്റാ പെരുമാറ്റവും മാറിയേക്കാം. നിങ്ങളുടെ വർക്‌ഫ്ലോ മാറ്റങ്ങൾ കൈകാര്യം ചെയ്യാൻ തയ്യാറല്ലാത്തപ്പോൾ അതിനെ ആവശ്യമായ CI ഗേറ്റുകളിൽ ഉൾപ്പെടുത്തരുത്.

deterministic CI പരിശോധങ്ങൾക്ക് ബദലായി `co-op-review` ഉപയോഗിക്കുക.
