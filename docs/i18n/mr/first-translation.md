# एका लहान प्रकल्पाचा अनुवाद, संपादन आणि पुनरावलोकन करा

दोन छोटे Markdown फाइल्स आणि एक लक्ष्य भाषा वापरून प्रारंभ करा. तुम्हाला अनुवाद कुठे लिहिले जातात, स्त्रोत बदलल्यावर काय होते, आणि निकाल कसा तपासायचा हे दिसेल.

## नोंदवलेले निकाल

हे उदाहरण 19 सप्टेंबर 2026 रोजी Co-op Translator 0.21.0 आणि Azure OpenAI (`gpt-5-mini`) सह चालवले गेले. बदलेले न झालेले CLI कमांड्स Click च्या `CliRunner` मार्फत निर्मित व्हील आणि विद्यमान Python अवलंबनांसह कॉल केले गेले.

| पाऊल | निकाल |
| --- | --- |
| पूर्वावलोकन | Exit 0; मॉडेल अनुवादाची विनंती नाही |
| प्रारंभिक अनुवाद | Exit 0; 27.36 सेकंद |
| प्रारंभिक पुनरावलोकन | Exit 0 |
| README संपादित करा आणि पुनरावलोकन करा | Exit 1; जुना अनुवाद आढळला |
| अनुवाद अद्यतनित करा | Exit 0; 22.17 सेकंद |
| अद्यतनानंतर पुनरावलोकन | Exit 0; त्रुटी किंवा चेतावणी नाहीत |
| न बदललेले मार्गदर्शक | README अद्यतनापूर्वी आणि नंतर बाइट्स समान आहेत |
| पुन्हा चालवा | Exit 0; सर्व अनुवाद फाइल्ससाठी हॅशेस समान आहेत |

हे वैयक्तिक रन मोजमाप आहेत, कार्यक्षमतेच्या हमी नाहीत. सेटअप वेळ वगळले गेले आहे; प्रदाता बिलिंग मोजले गेले नाही. न बदललेला रन अद्याप प्रदाता हेल्थ चेक करु शकतो.

खालील तपासा: [प्रारंभिक अनुवाद](../../assets/demo/before.txt), [अद्यतनित अनुवाद](../../assets/demo/after.txt), [पूर्ण अनुवाद तफावत](../../assets/demo/update.diff), [जुने पुनरावलोकन](../../assets/demo/review-stale.txt), [अंतिम पुनरावलोकन](../../assets/demo/review-after.txt), आणि [रन तपशील](../../assets/demo/results.json). संपूर्ण फाइलचा अनुवाद शब्दरचनेत इतर बदल करू शकतो, जसे कैद केलेली तफावत दाखवते. दोन्ही मजकूर आर्टिफॅक्ट्स तयार झालेली सूचना जपून ठेवतात.

मानवी पुनरावलोकन अद्याप महत्त्वाचे आहे: कैद केलेल्या अद्यतनात `[사용 가이드](guide.md)을` वापरले गेले आहे; कोरियन कण `[사용 가이드](guide.md)를` असायला हवे. मजकूर आर्टिफॅक्ट्स हे आउटपुट तंतोतंत ठेवतात, संपादित केलेला अनुवाद मॉडेल आउटपुट म्हणून सादर करण्याऐवजी. या वाक्यरचनेच्या समस्ये असूनही संरचनात्मक पुनरावलोकन पास होते.

## 1. एक लहान फोल्डर तयार करा

Python 3.11–3.14 वापरा आणि [virtual environment setup](configuration.md#local-runtime-setup) वापरा. या उदाहरणासाठी वापरलेली आवृत्ती इंस्टॉल करा:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

या फोल्डरमध्ये [README.txt](../../assets/demo/README.txt) आणि [guide.txt](../../assets/demo/guide.txt) डाउनलोड करा आणि त्यांना `README.md` आणि `guide.md` म्हणून जतन करा. हा एक लहान काल्पनिक प्रकल्प दस्तऐवज आहे; कोणतेही अनुप्रयोग इंस्टॉलेशन आवश्यक नाही.

README मध्ये एक कोड ब्लॉक आणि `guide.md` कडे लिंक समाविष्ट आहे. त्याचे शेवटचे वाक्य आहे:

```text
Notes are saved locally.
```

या फोल्डरमध्ये फक्त हे दोन स्रोत दस्तऐवज ठेवा. सर्व पुढील कमांड्स `translation-demo` मध्ये चालविल्या जातील आणि Bash व PowerShell मध्ये काम करतील.

## 2. क्रेडेन्शियल्सशिवाय पूर्वावलोकन

```bash
translate -l "ko" -md --dry-run
```

पूर्वावलोकन मॉडेल कॉल न करता किंवा अनुवाद लिहिले न करता अनुवाद कामाचे अनुमान करते. टोकन अंदाज बिलिंग कोट नावाचे नाहीत. पहिले रन दोन्ही Markdown फाइल्स नवीन काम म्हणून ओळखले पाहिजेत.

## 3. एक प्रदाता निवडा आणि अनुवाद करा

[configuration guide](configuration.md) वापरून एक प्रदाता कॉन्फिगर करा: Azure OpenAI, OpenAI, किंवा Anthropic. OpenAI आणि Anthropic मजकूर अनुवादासाठी Azure खाते आवश्यक नाही. या उदाहरणासाठी इमेज सेवा आवश्यक नाहीत.

जर तुम्ही स्थानिक `.env` फाईल वापरत असाल, तर `.env` या फोल्डरच्या `.gitignore` मध्ये जोडा. अनुवाद कॉल तुमच्या प्रदाता खात्याचा वापर करतात आणि शुल्क लागू होऊ शकतात.

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

Open `translations/ko/README.md` आणि `translations/ko/guide.md`. कोरियन शब्दरचना, कोड ब्लॉक, आणि अनुवादित README मधून अनुवादित guide कडे जाणारी लिंक तपासा. आउटपुटचे शब्दरूप मॉडेलनुसार वेगळे असते.

`co-op-review` ताजेपणा, संरचना, आणि स्थानिक लिंक तपासते. पास झालेले निकाल भाषिक अचूकता प्रमाणित करत नाहीत. पुढे जाण्यापूर्वी अहवालित केलेल्या कोणत्याही त्रुटी सोडवा.

यशस्वी बेसलाईन Git मध्ये नोंदवा (गरज असल्यास प्रथम तुमची Git ओळख कॉन्फिगर करा):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. स्त्रोत बदला

`README.md` मध्ये, `Notes are saved locally.` हे बदलून खालील करा:

```text
Notes are saved locally as Markdown files.
```

`guide.md` अपरिवर्तित ठेवा. नंतर चालवा:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

पुनरावलोकन README अनुवाद जुन्या असल्याची नोंद करेल आणि अपयशीपणे बाहेर पडेल. हा अपेक्षित मध्येरी अवस्थेचा भाग आहे. पूर्वावलोकन बदललेल्या README साठी काम ओळखावे.

## 5. अद्यतन करा आणि diff तपासा

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

वास्तविक diff तपासा: डीफॉल्ट CLI बदललेल्या फाईलचे पुन्हा अनुवाद करते, त्यामुळे मॉडेल त्या फाईलमधील इतर शब्दरचना देखील सुधारू शकते. न बदललेल्या guide मध्ये कोणताही diff असू नये. पुनरावलोकन आता README ला जुना म्हणून नोंदवू नये; इतर निष्कर्षांची तपासणी करा आणि त्यांना दुर्लक्षित करू नका.

मानवी Markdown संपादनांचे ब्लॉक-स्तर संरक्षण [Python API](api.md) मध्ये एक ऐच्छिक अनुवाद स्थिती प्रदात्याची आवश्यकता असते. हे CLI कमांड्सद्वारे सक्षम केलेले नाही.

## 6. बदल न करता पुन्हा चालवा

अपडेट केलेला स्रोत आणि अनुवाद कमिट करा:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

विद्यमान अनुवाद आणि न बदललेल्या कॉन्फिगरेशनसह, अनुवादक फाइल्स वगळतो. अंतिम Git कमांडने कोणताही diff तयार करू नये आणि यशस्वीरित्या बाहेर पडले पाहिजे.
