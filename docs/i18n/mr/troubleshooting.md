# समस्यांचे निवारण

हा पृष्ठ वापरा जेव्हा एखादी भाषांतर रन अनपेक्षितपणे यशस्वी होते, कॉन्फिगरेशन दरम्यान अयशस्वी होते, किंवा असे आउटपुट तयार होते ज्याचे पुनरावलोकन आवश्यक आहे.

## येथून सुरू करा

1. प्रथम लक्ष केंद्रित कमांड चालवा, जसे की `translate -l "ko" -md`.
2. कन्सोल डिबग लॉग्ससाठी `-d` जोडा.
3. डिबग लॉग्स `<root-dir>/logs/` मध्ये जतन करण्यासाठी `-s` जोडा.
4. ताजेपणा, रचना आणि स्थानिक दुवे तपासण्यासाठी भाषांतरानंतर `co-op-review` चालवा.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## कॉन्फिगरेशन त्रुटी

### भाषा मॉडेल प्रदाता नाही

त्रुटी:

```text
No language model configuration found.
```

उपाय:

- Azure OpenAI, OpenAI, किंवा Anthropic कॉन्फिगर करा.
- कमांड ज्या वातावरणात चालते तेथे व्हेरिएबल्स अस्तित्वात आहेत की नाही ते तपासा.
- स्थानिक वापरासाठी, प्रोजेक्ट रूटवर `.env` मध्ये ठेवा.

पाहा [Configuration](configuration.md).

### Azure AI Vision शिवाय प्रतिमा अनुवाद

त्रुटी:

```text
Image translation requested but Azure AI Service is not configured.
```

उपाय:

- `AZURE_AI_SERVICE_API_KEY` जोडा.
- `AZURE_AI_SERVICE_ENDPOINT` जोडा.
- किंवा `translate -l "ko" -md` सारखा फक्त मजकूर कमांड चालवा.

### अवैध की किंवा एन्डपॉइंट

लक्षणांमध्ये `401`, रिडॅक्ट केलेल्या परवानगी त्रुटी किंवा एन्डपॉइंट प्रवेश त्रुटींचा समावेश असू शकतो.

उपाय:

- की एन्डपॉइंटसाठी वापरलेल्या त्याच Azure संसाधनाची आहे याची खात्री करा.
- `-img` वापरताना संसाधन Vision ला समर्थित करते का ते तपासा.
- Azure OpenAI deployment नाव व API आवृत्ती तुमच्या डिप्लॉयमेंटशी जुळत असल्याची खात्री करा.
- डिबग लॉगसह चालवा: `translate -l "ko" -md -d -s`.

## कोणतीही फाइल अनुवादित झाली नाही

साधारण कारणे:

- निवडलेले फ्लॅग्स तुमच्या फाइल्सशी जुळत नाहीत.
- आधीच अनुवादित फाइल्स अस्तित्वात आहेत.
- स्रोत फाइल्स वगळलेल्या निर्देशिकांमध्ये आहेत.
- कमांड चुकीच्या प्रोजेक्ट रूटमधून चालवत आहे.

तपासणी:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

प्रोजेक्ट रूटच्या बाहेर कमांड चालवताना `--root-dir` वापरा.

## अनपेक्षित दुवा वर्तन

दुवा पुन्हा लिहिणे निवडलेल्या सामग्री प्रकारांवर अवलंबून असते:

- `-nb` समाविष्ट: नोटबुक दुवे अनुवादित नोटबुककडे निर्देश करू शकतात.
- `-nb` वगळले: नोटबुक दुवे स्रोत नोटबुककडे राहू शकतात.
- `-img` समाविष्ट: प्रतिमा दुवे अनुवादित प्रतिमांकडे निर्देश करू शकतात.
- `-img` वगळले: प्रतिमा दुवे स्रोत प्रतिमांकडे राहू शकतात.

जेव्हा सर्व अंतर्गत दुवे अनुवादित आउटपुटला प्राधान्य द्यायला हवेत तेव्हा पूर्ण सामग्रीचे भाषांतर चालवा:

```bash
translate -l "ko" -md -nb -img
```

भाषांतरानंतर दुवा पुनरावलोकन चालवा:

```bash
co-op-review -l "ko"
```

## Markdown रेंडरिंग समस्या

जर अनुवादित मार्कडाउन चुकीने रेंडर होत असेल तर:

- तपासा की फ्रंटमॅटर `---` ने सुरू आणि संपते.
- स्रोत आणि अनुवादित फाइल्समधील कोड फेन्सची संख्या जुळते का ते तपासा.
- सामान्य रचना समस्यांसाठी `co-op-review` चालवा.
- जर आउटपुट भ्रष्ट झाले असेल तर संबंधित फाइल पुन्हा अनुवादित करा.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action चालला परंतु कोणताही Pull Request तयार झाला नाही

जर `peter-evans/create-pull-request` अहवाल देत असेल की ब्रांच बेसच्या पुढे नाही, तर वर्कफ्लोला कमिट करण्यास काही फाइल्स सापडल्या नाहीत.

संभाव्य कारणे:

- भाषांतर रनने कोणतेही बदल तयार केले नाहीत.
- `.gitignore` मध्ये `translations/`, `translated_images/` किंवा अनुवादित नोटबुक्स वगळले गेले आहेत.
- `add-paths` जनरेट केलेल्या आउटपुट निर्देशिकांशी जुळत नाही.
- भाषांतर टप्पा लवकर बाहेर पडला.

उपाय:

1. `translations/` किंवा `translated_images/` मध्ये जनरेट झालेल्या फाइल्स आहेत का ते पुष्टी करा.
2. `.gitignore` जनरेट केलेल्या आउटपुटना दुर्लक्षित करत नाही याची खात्री करा.
3. जुळणारे `add-paths` वापरा:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. तात्पुरते translate कमांडमध्ये डिबग फ्लॅग्ज जोडा:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. पुष्टी करा की वर्कफ्लो परवानग्या यामध्ये आहेत:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## भाषांतर गुणवत्ता

मशीन अनुवादांना मानवी पुनरावलोकनाची आवश्यकता असू शकते. `evaluate` फक्त तेव्हा वापरा जेव्हा तुम्हाला प्रयोगात्मक गुणवत्ता स्कोअरिंग आणि कमी-विश्वास सुधारणा वर्कफ्लो हवे असतील.

!!! warning "Experimental"
    `evaluate` नियम-आधारित आणि LLM-आधारित तपासणी वापरू शकते, आणि त्याचे स्कोअरिंग मॉडेल व मेटाडेटा वर्तन बदलू शकते. जर तुमचा वर्कफ्लो बदलांसाठी तयार नसेल तर ते आवश्यक CI गेट्समध्ये ठेऊ नका.

निश्चित CI तपासण्या करण्यासाठी, त्याऐवजी `co-op-review` वापरा.
