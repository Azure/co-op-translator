# ဘာသာစကားတိုးတက်ရေးတွင် ပါဝင်ထောက်ပံ့ခြင်း

သင်၏ ဘာသာစကား ကျွမ်းကျင်မှုက Co-op Translator ကို တိုးတက်စေရန် ကူညီနိုင်သည်။ နမူနာတစ်ခု၊ အကြံပြု ပြင်ဆင်ချက်တစ်ခုနှင့် ရှင်းပြချက်တစ်ခုကို [translation feedback form](https://github.com/Azure/co-op-translator/issues/new?template=translation_feedback.yml) မှတစ်ဆင့် စတင်တင်ပြပါ။ ကုဒ် မရေးရပါ၊ မော်ဒယ် run အတွက် ငွေပေးချေမှု မလိုအပ်ပါ။

## အစီရင်ခံချက်မှ ပူးပေါင်းတိုးတက်မှုဆီ

1. ထောက်ပံ့သူက မူရင်း အပိုဒ်၊ ၎င်း၏ ဘာသာပြန်ချက်နှင့် ကိုက်ညီသော အကြောင်းအရာကို ပေးသည်။
2. ဘာသာစကားဆန်းစစ်သူသည် အဓိပ္ပါယ်၊ သဘာဝကျမှုနှင့် အဆိုပြုချက်သည် သတ်မှတ် ဒေသ သို့မဟုတ် သင်တန်းတစ်ခုနှင့် ဆိုင်သည်/မဆိုင်သည်ကို စစ်ဆေးသည်။
3. အုပ်ချုပ်သူ(maintainer) က ပြင်ဆင်ချက်ကို မူလသင်တန်း၊ ဗဟိုဘာသာစကား ညွှန်ကြားချက်၊ အသုံးအနှုန်း ဖွဲ့စည်းမှု သို့မဟုတ် ဘာသာပြန်ကုဒ်ထဲသို့ ထည့်သင့်/မထည့်သင့်ကို ဆုံးဖြတ်သည်။
4. ပူးပေါင်းစည်းမျဉ်းတစ်ခုအတွက် အုပ်ချုပ်သူသည် အစီရင်ခံထားသော နမူနာပေါ်တွင် ပြောင်းလဲမှုမတိုင်မီနှင့် ပြောင်းလဲပြီးနောက် အထွက်များကို နှိုင်းယှဉ်ကြသည်။ ထောက်ပံ့သူများသည် ကိရိယာကို မစမ်းသပ်ဘဲ အဆိုပါ အထွက်များကို ပြန်လည်သုံးသပ်နိုင်သည်။
5. ထွက်ပေါ်လာသော PR သည် အစီရင်ခံချက်ကို လင့်ခ်ပြပြီး နမူနာများနှင့် စမ်းသပ်သည့်သူများအား ချီးမြှင့် credits ပေးပါမည်။ စတင်တပ်ထဲသို့ ထုတ်ပေးခြင်း (deployment) သို့မဟုတ် အသုံးပြုသည့် repository များတွင် ပြန်လည်ထုတ်လုပ်ခြင်း (regeneration) သည် အခြားခြေလှမ်းတစ်ခုဖြစ်သည်။

အစီရင်ခံချက်တစ်ခုက အလိုအလျှောက် prompt များကို ပြောင်းလဲခြင်း သို့မဟုတ် သင်တန်း ဘာသာပြန်ချက်များကို ပြန်လည်ထုတ်လုပ်ခြင်း မလုပ်ပါ။ သင်တန်း-အထူး ပြင်ဆင်ချက်များကို သင်တန်း repository နဲ့ ဆက်လက်ချိတ်ဆက်ထားသင့်သည်။ လက်မောင်းဖြင့် ပြင်ဆင်ခြင်းသည် နောက်ပိုင်း ပြန်လည်ဘာသာပြန်ရာတွင် ထိန်းသိမ်းမကျန်နိုင်ကြောင်း မယုံကြည်ပါနဲ့ — အလုပ်စဉ်အတွက် အပြုအမူကို အတည်ပြုပါ။

## ရှိပြီးသား နမူနာ: ဂျပန် Markdown လင့်ခ်များ

[ဂျပန်ညွှန်ကြားမှု ဖိုင်](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/templates/language/ja.md) သည် မော်ဒယ်အား Markdown စာဖွဲ့စည်းပုံနှင့် link ရည်ညွှန်းချက်ကို ထိန်းသိမ်းပြီး link စာသားကို ဘာသာပြန်ရန် ညွှန်ကြားသည်။ ဥပမာအားဖြင့် `[text](URL)` ဟုရေးထားသော link ကို `「text」（URL）` သို့ မပြောင်းသင့်ပါ။

ဤသည်မှာ မှန်ကန်/မှားယွင်းသော အထွက်ကို ဥပမာဖြင့် ပြသထားသော ဘာသာစကား စည်းမျဉ်း၏ အာရုံစိုက်ထားသော နမူနာတစ်ခုဖြစ်သည်။ ၎င်းသည် prompt ညွှန်ကြားချက်များတင်လျှင် Markdown ကို မူလတန်းမှ အမြဲတကျ မှန်ကန်စေမည်ဟု အာမခံချက် မဟုတ်ပါ။

[Markdown prompt ဖန်တီးသူ](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/utils/markdown/prompts.py) သည် အက္ခရာအသေးဖြင့် ပြန်ပြင်၍ အနားကွက်များကို ဖယ်ရှားထားသော ဘာသာစကားကုဒ်ကို အသုံးပြုပြီး `templates/language/<language_code>.md` ကို သတ်မှတ်ရာဒေတာမှ သွင်းယူသည်။ ဖိုင်မရှိပါက ပုံမှန်ညွှန်ကြားချက်များကို အသုံးပြုသည်။ ၎င်းသည် Markdown prompt ၏ လမ်းကြောင်းကို ဖော်ပြသည့်အရာဖြစ်သည်; မည်သည့် ပုံ (image) သို့မဟုတ် အခြားဘာသာပြန်လမ်းကြောင်းမဆို တူညီသောညွှန်ကြားချက်များကို အသုံးပြုမည်ဟု မယူဆပါနဲ့။

[prompt tests](https://github.com/Azure/co-op-translator/blob/main/tests/co_op_translator/utils/markdown/test_prompts.py) သည် ဂျပန်ဘာသာ အညွှန်းများ ပါဝင်နေရန် စစ်ဆေးသည်။ ၎င်းက prompt ပြုစုမှုကို အတည်ပြုပေးသော်လည်း ဘာသာပြန်ခြင်း၏ အရည်အသွေးကို မအတည်ပြုပါ။

## ဘာသာစကား စည်းမျဉ်းတွင် ဘာများ ပါဝင်သင့်သလဲ?

နမူနာမူရင်း၊ မျှော်မှန်းထားသော အပြုအမူနှင့် စည်းမျဉ်းအရေးမကျဆုံးသော ဆန့်ကျင်နမူနာတစ်ခုပါသော နောက်ဆက်တွဲ ပြင်ဆင်ချက်တစ်ခုကို အကြံပြုပါ။ အဓိပ္ပါယ်၊ placeholders၊ ကုဒ်၊ URLs နှင့် စာရွက်ဖွဲ့စည်းမှုကို ထိန်းသိမ်းပါ။ တစ်ဦးချင်းစတိုင်နှစ်သက်မှု သို့မဟုတ် သင်တန်းတစ်ခု၏ အသုံးအနှုန်းကို ယေဘူယျစည်းမျဉ်းတစ်ခုအဖြစ် မပြောင်းလဲပါနှင့်။

လက်ရှိ [glossary implementation](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/glossary.py) သည် စကားလုံးများကို ဘာသာပြန်ခြင်းမှ ကာကွယ်ပေးသည်။ ၎င်းသည် မူရင်း→ပစ်လွှတ် သတ်မှတ်ထားသော အသုံးအနှုန်း အဘိဓာန် (source-to-target terminology dictionary) မဟုတ်ပါ။ အသစ်ထည့်မည့် အသုံးအနှုန်းအပြုအမူကို ကတိပေးမီ ဆွေးနွေးပါ။

## လူထု နမူနာ: ဂျပန် ထုတ်ကုန်အမည် အစီရင်ခံချက်

[အစီရင်ခံချက် #527](https://github.com/Azure/co-op-translator/issues/527) တွင် @hyoshioka0128 သည် ထုတ်ကုန်အမည် `Co-op Translator` ကို `Co-op 翻訳` သို့ ပြောင်းလဲသွားသော ဂျပန်ဘာသာပြန်အား ရှာဖွေတွေ့ရှိခဲ့သည်။ ထိုအစီရင်ခံချက်တွင် သက်ရောက်ခဲ့သော စာတမ်းကို ပြသသည့် link တစ်ခုနှင့် screenshot တစ်ပုံပါဝင်သဖြင့် ပြဿနာကို ရှာဖွေတွေ့ရှိရလွယ်ကူခဲ့သည်။

ထည့်သွင်းသူက [ဆက်စပ်သင်တန်း PR](https://github.com/microsoft/AZD-for-beginners/pull/109) ကိုလည်း ဆက်သွယ်ထည့်သွင်းခဲ့သည်။ ပြဿနာဆိုင်ရာ ဆွေးနွေးချက်တွင် စောင့်ရှောက်သူသည် အစီရင်ခံချက်ကို လက်ခံတုံ့ပြန်ပြီး အမည်ပြောင်းလဲမှုကြောင့် ဖြစ်ပေါ်ခဲ့သည့် အကြောင်းရင်းများကို စုံစမ်းစစ်ဆေးရန် အကြံပြုခဲ့သည်။ ၎င်းတွင် သတ်မှတ်ချက် ကာကွယ်မှု၊ အဘိဓာန် အပြုအမူနှင့် ဘာသာပြန်လမ်းကြောင်းတို့ကို ပါဝင်စစ်ဆေးရန် ပြောကြားခဲ့သည်။

ဤသည်က သေးငယ်သည့် အစီရင်ခံချက်တစ်ခုက တစ်ဦးချင်း စကားလုံး ပြင်ဆင်မှုထက် ကျော်လွန်ပြီး စုံစမ်းစစ်ဆေးမှုကို ထောက်ပံ့နိုင်ကြောင်း ပြသသည်။ ဤသည်မှာ အတည်ပြုထားသော မျှော်မှန်းချက်မတိုင်မီ/နောက်ပိုင်းရလဒ် မဟုတ်သောကြောင့် အထက်ဖော်ပြထားသည့် ဂျပန် Markdown-link ညွှန်ကြားချက်များက ထုတ်ကုန်အမည် ပြဿနာကို ဖြေရှင်းပေးခဲ့ကြောင်း သက်သေ မဟုတ်ပါ။

သင်လည်း အတူတူပုံစံဖြင့် ပါဝင်နိုင်သည် — မူရင်းစာသား၊ ယခု ဘာသာပြန်ချက်၊ အကြံပြု ပြင်ဆင်ချက်နှင့် ၎င်းအရေးပါသော အကြောင်းရင်းကို မျှဝေပါ။ မှတ်တမ်းချိတ်ဆက်ချက် သို့မဟုတ် screenshot ကိုလိုအပ်သလို ထည့်ပါ။ အကြောင်းရင်းကို သိရန် သို့မဟုတ် report မတင်မီ prompt တစ်ခုရေးရန် မလိုဘဲ တင်ပြနိုင်ပါသည်။

## စည်းမျဉ်းကို လက်ခံရန်မတိုင်မီ အတည်ပြုခြင်း

baseline နှင့် candidate run များအတွက် မူရင်း စမ်းနမူနာများ၊ ဘာသာပြန်သူ ပြင်ဆင်ချက်၊ provider/model နှင့် generation ချိန်ညှိမှုများကို တူညီစွာ အသုံးပြုပါ၊ အဆိုပြုချက်ကိုသာ ပြောင်းလဲပါ။ အတိအကျ prompt ပြောင်းလဲမှုနှင့် ထုတ်လွှင့်ချက်များကို မှတ်တမ်းတင်ပြီး ထုတ်လွှင့်ချက် မတည်ငြိမ်မှုနှင့် အကျိုးသက်ရောက်မှု တိုကွာခြားနိုင်ရန် လိုအပ်လျှင် နမူနာများကို ထပ်မံပြပါ။ အစီရင်ခံထားသော ဖျက်ချက်၊ ထပ်တူမူများနှင့် ယခင်က မှန်ကန်ပြီးသား နမူနာများကို ပါဝင်စေပါ။

ဖွဲ့စည်းပုံဆိုင်ရာ မပြောင်းလဲနိုင်မှုများကို ဘာသာစကားဆိုင်ရာ အကဲဖြတ်ချက်များနှင့် သီးခြား စစ်ဆေးပါ။ prompt-loading စမ်းသပ်မှု အောင်မြင်ခြင်းသည် အရည်အသွေးအကဲဖြတ်ချက် မဟုတ်သဖြင့် တိတိကျကျ မျှော်မှန်းထားသော စာကြောင်းတစ်ကြောင်း လုံးက တစ်ခုတည်းသော မှန်ကန်သော ဘာသာပြန်ချက် မဟုတ်ပါ။ context၊ model runs သို့မဟုတ် ဘာသာစကားဆန်းစစ်မှု မရှိပါက ထုတ်ပြန်ချက်ကို ပြီးစီးသလို ဆုံးဖြတ်၍ မဆိုဘဲ အဆိုပြုချက်ကို စောင့်ဆိုင်းထားပါ။
