# ပြဿနာဖြေရှင်းခြင်း

ဒီစာမျက်နှာကို ဘာသာပြန်လုပ်ငန်း တစ်ခု မမျှော်လင့်ပဲ အောင်မြင်သွားသည်၊ ဖွဲ့စည်းမှုအတွင်း မအောင်မြင်သွားသည်၊ သို့မဟုတ် ပြန်လည်စစ်ဆေးရန် လိုအပ်သော အထွက်များ ထွက်ရှိသွားသော အခါ အသုံးပြုပါ။

## ဒီနေရာမှ စပါ

1. ပထမဦးစွာ ဂရုစိုက်ထားသော command တစ်ခုကို လည်ပတ်ပါ၊ ဥပမာ `translate -l "ko" -md`။
2. ကွန်ဆိုလ် debug မှတ်တမ်းများအတွက် `-d` ကို ထည့်ပါ။
3. debug မှတ်တမ်းများကို `<root-dir>/logs/` အောက်တွင် သိမ်းရန် `-s` ကို ထည့်ပါ။
4. ဘာသာပြန်ပြီးနောက် freshness၊ ဖွဲ့စည်းမှု၊ နှင့် ဒေသဆိုင်ရာ လင့်ခ်များကို စစ်ဆေးရန် `co-op-review` ကို လည်ပတ်ပါ။

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## ဖွဲ့စည်းမှု အမှားများ

### ဘာသာစကား မော်ဒယ် ပေးသူ မရှိပါ

အမှား:

```text
No language model configuration found.
```

ဖြေရှင်းရန်:

- Azure OpenAI, OpenAI, သို့မဟုတ် Anthropic ကို ဖွဲ့စည်းပါ။
- ကီးတန်ဖိုးများသည် command လည်ပတ်ရာ environment တွင် ရှိကြောင်း အတည်ပြုပါ။
- တိုင်းရင်းအသုံးပြုရန် project root တွင် `.env` ထဲသို့ ထည့်ပါ။

See [ဖွဲ့စည်းမှု](configuration.md).

### Azure AI Vision မပါဘဲ ပုံ/ရုပ်ပုံ ဘာသာပြန်ခြင်း

အမှား:

```text
Image translation requested but Azure AI Service is not configured.
```

ဖြေရှင်းရန်:

- `AZURE_AI_SERVICE_API_KEY` ကို ထည့်ပါ။
- `AZURE_AI_SERVICE_ENDPOINT` ကို ထည့်ပါ။
- ဒါမှမဟုတ် စာသားပဲ ဘာသာပြန်ရန် `translate -l "ko" -md` ကဲဲ့သို့ command ကို လည်ပတ်ပါ။

### အမှန်မဟုတ်သော Key သို့မဟုတ် Endpoint

ရလဒ်များတွင် `401`, ခွင့်ပြုချက်ဆိုင်ရာ ဖျက်ထားထားသော အမှားများ သို့မဟုတ် endpoint သို့ ဝင်ရောက်မရနိုင်ခြင်းကဲ့သို့ ဖြစ်ရပ်များ တွေ့နိုင်သည်။

ဖြေရှင်းရန်:

- key သည် endpoint နှင့် တူညီသော Azure resource ကိုပိုင်ဆိုင်ကြောင်း အတည်ပြုပါ။
- `-img` သုံးသောအခါ resource သည် Vision ကို ထောက်ပံ့ကြောင်း အတည်ပြုပါ။
- Azure OpenAI deployment အမည်နှင့် API ဗားရှင်းသည် သင့် deployment နှင့် ကိုက်ညီကြောင်း အတည်ပြုပါ။
- debug မှတ်တမ်းများနှင့် လည်ပတ်ပါ: `translate -l "ko" -md -d -s`။

## ဘာသာပြန်ထားသော ဖိုင်များ မရှိပါ

ပင်မ အကြောင်းရင်းများ:

- ရွေးချယ်ထားသော flags များသည် သင်၏ ဖိုင်များနှင့် ကိုက်ညီခြင်း မရှိနိုင်ပါ။
- ရှိပြီးသား ဘာသာပြန်ပြီးဖိုင်များ မည်ကို သာ ဖြစ်နေပါသည်။
- မူရင်းဖိုင်များသည် ပယ်ဖျက်ထားသော directory များအောက်တွင် ရှိနေသည်။
- command ကို အမှားသော project root မှ လည်ပတ်နေသည်။

စစ်ဆေးချက်များ:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

command ကို project root ပြင်ပမှ လည်ပတ်သောအခါ `--root-dir` ကို အသုံးပြုပါ။

## မမျှော်လင့်ထားသော လင့်ခ် အပြုအမူ

လင့်ခ် ပြန်ရေးခြင်းသည် ရွေးချယ်ထားသော မီဒီယာ အမျိုးအစားများပေါ် မူတည်ပါသည်။

- `-nb` ပါဝင်ပါက: notebook လင့်ခ်များသည် ဘာသာပြန်ထားသော notebook များသို့ ညွှန်ပြနိုင်သည်။
- `-nb` မပါဝင်ပါက: notebook လင့်ခ်များသည် မူရင်း notebook များကို ဆက်လက် ညွှန်ပြနိုင်သည်။
- `-img` ပါဝင်ပါက: ပုံလင့်ခ်များသည် ဘာသာပြန်ထားသော ပုံများသို့ ညွှန်ပြနိုင်သည်။
- `-img` မပါဝင်ပါက: ပုံလင့်ခ်များသည် မူရင်း ပုံများကို ဆက်လက် ညွှန်ပြနိုင်သည်။

အတွင်းလင့်ခ်အားလုံးသည် ဘာသာပြန်ထားသော အထွက်များကို ဦးစားပေးစေရန်လိုပါက အပြည့်အစုံ content ဘာသာပြန်ခြင်းကို လည်ပတ်ပါ။

```bash
translate -l "ko" -md -nb -img
```

ဘာသာပြန်ပြီးနောက် လင့်ခ် ပြန်လည်သုံးသပ်ပါ။

```bash
co-op-review -l "ko"
```

## Markdown ပြသမှု ပြဿနာများ

ဘာသာပြန်ထားသော Markdown သည် မမှန်ကန်စွာ ဖော်ပြလျှင်:

- frontmatter သည် `---` ဖြင့် စ၍ `---` ဖြင့် အဆုံးသတ်ထားသည်ကို စစ်ပါ။
- code fence အရေအတွက်များသည် မူရင်းနှင့် ဘာသာပြန်ထားသော ဖိုင်များအကြား ကိုက်ညီနေကြောင်း စစ်ပါ။
- ပုံမှန် ဖွဲ့စည်းမှု ပြဿနာများ ကို ဖမ်းဆီးရန် `co-op-review` ကို လည်ပတ်ပါ။
- အထွက်ဖိုင် ပျက်စီးနေပါက သတ်မှတ်ထားသော ဖိုင်ကို ထပ်မံ ဘာသာပြန်ပါ။

```bash
co-op-review -l "ko" --format github
```

## GitHub Action လည်ပတ်ခဲ့သော်လည်း Pull Request မဖန်တီးသေးပါ

အကယ်၍ `peter-evans/create-pull-request` သည် branch သည် base ထက် ရှေ့မရှိကြောင်း ဆိုပါက workflow သည် commit လုပ်ရန် ဖိုင်များ မတွေ့ပါ။

ဖြစ်နိုင်သော အကြောင်းရင်းများ:

- ဘာသာပြန် လည်ပတ်မှုက မည်သည့် ပြောင်းလဲမှုမျှ မဖြစ်ပေါ်စေခဲ့ပါ။
- `.gitignore` သည် `translations/`, `translated_images/`, သို့မဟုတ် ဘာသာပြန်ထားသော notebooks များကို ပယ်ဖျက်ထားနိုင်သည်။
- `add-paths` သည် ထုတ်လုပ်ထားသော output directory များနှင့် ကိုက်ညီခြင်း မရှိပါ။
- ဘာသာပြန် အဆင့်သည် မကြာမီ မှီငင် ထွက်သွားခဲ့သည်။

ဖြေရှင်းနည်းများ:

1. `translations/` သို့မဟုတ် `translated_images/` တွင် ထုတ်လုပ်ထားသော ဖိုင်များ ရှိကြောင်း အတည်ပြုပါ။
2. `.gitignore` သည် ထုတ်လုပ်ထားသော အထွက်များကို မပယ်ဖျက်ကြောင်း အတည်ပြုပါ။
3. ကိုက်ညီသော `add-paths` ကို အသုံးပြုပါ:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. ယာယီအနေနဲ့ translate command တွင် debug flags များ ထည့်ပါ:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. workflow ခွင့်ပြုချက်များတွင် အောက်ပါများ ပါဝင်ကြောင်း အတည်ပြုပါ:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## ဘာသာပြန် အရည်အသွေး

စက်အလိုအလျောက် ဘာသာပြန်ချက်များတွင် လူ့စစ်ဆေးမှုလိုအပ်နိုင်သည်။ စမ်းသပ်အရည်အသွေး အဆင့်သတ်မှတ်ခြင်းနှင့် မအတည်ဖြစ်သော အပိုင်းများ ပြင်ဆင်ရန် workflow များသာ လိုချင်သော အခါ `evaluate` ကိုအသုံးပြုပါ။

!!! warning "စမ်းသပ်မှု"
    `evaluate` သည် rule-based နှင့် LLM-based စစ်ဆေးမှုများကို အသုံးပြုနိုင်ပြီး ၎င်း၏ အမှတ်ပေးမော်ဒယ်နှင့် metadata အပြုအမူများ ပြောင်းလဲနိုင်သည်။ သင့် workflow သည် ပြောင်းလဲမှုများအတွက် ပြင်ဆင်ပြီး မဟုတ်ပါက ၎င်းကို လိုအပ်သော CI gates များထဲသို့ မထည့်ပါ။

ဆုံးဖြတ်ချက်တိကျသော CI စစ်ဆေးမှုများအတွက် `co-op-review` ကို ဖန်တီးအသုံးပြုပါ။
