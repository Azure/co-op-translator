# अनुवाद, सम्पादन, र सानो परियोजनाको समीक्षा

दुई साना Markdown फाइल र एक लक्ष्य भाषा बाट सुरु गर्नुहोस्। तपाईंले कहाँ अनुवादहरू लेखिन्छन्, स्रोत परिवर्तन हुँदा के हुन्छ, र परिणाम कसरी जाँच्ने भन्ने देख्नुस्।

## रेकर्ड गरिएका नतिजा

यो उदाहरण 19 सेप्टेम्बर 2026 मा Co-op Translator 0.21.0 र Azure OpenAI (`gpt-5-mini`) संग चलाइयो। परिवर्तन नगरेको CLI आदेशहरू Click को `CliRunner` मार्फत निर्मित wheel र अवस्थित Python निर्भरताहरू प्रयोग गरी चलाइए।

| चरण | परिणाम |
| --- | --- |
| पूर्वावलोकन | निकास 0; मोडेल अनुवाद अनुरोध गरिएको छैन |
| प्रारम्भिक अनुवाद | निकास 0; 27.36 सेकेन्ड |
| प्रारम्भिक समीक्षा | निकास 0 |
| README सम्पादन र समीक्षा | निकास 1; पुरानो अनुवाद पत्ता लागेको |
| अनुवाद अद्यावधिक | निकास 0; 22.17 सेकेन्ड |
| अद्यावधिक पछि समीक्षा | निकास 0; कुनै त्रुटि वा चेतावनी छैन |
| परिवर्तन नभएको मार्गदर्शक | README अद्यावधिक अघि र पछि बाइटहरू समान |
| पुन: चलाउनुहोस् | निकास 0; सबै अनुवाद फाइलहरूको ह्यासहरू एउटै |

यी व्यक्तिगत रन मापनहरू हुन्, प्रदर्शन ग्यारेन्टी होइनन्। सेटअप समय बाहेक गरिएको छ; प्रदायक बिलिङ मापन गरिएको छैन। परिवर्तन नभएको रनले पनि प्रदायक स्वास्थ्य जाँच गर्न सक्छ।

[प्रारम्भिक अनुवाद](../../assets/demo/before.txt), [अद्यावधिक अनुवाद](../../assets/demo/after.txt), [पूर्ण अनुवाद भिन्नता](../../assets/demo/update.diff), [पुरानो समीक्षा](../../assets/demo/review-stale.txt), [अन्तिम समीक्षा](../../assets/demo/review-after.txt), र [रन विवरण](../../assets/demo/results.json) जाँच गर्नुहोस्। पूर्ण-फाइल अनुवादले अन्य शब्दावली परिवर्तन गर्न सक्छ, जस्तो कि क्याप्चर गरिएको diff ले देखाउँछ। दुवैले जेनेरेट गरिएको अस्वीकरण कायम राख्छन्।

मानव समीक्षाले अझै महत्त्व राख्छ: क्याप्चर गरिएको अपडेटले `[사용 가이드](guide.md)을` प्रयोग गर्छ; कोरियन कण ` [사용 가이드](guide.md)를` हुनुपर्छ। पाठ कलाकृतिले यो आउटपुट ठिकै राख्छन् र मोडेल आउटपुटको रूपमा सम्पादित अनुवाद प्रस्तुत गर्दैन। संरचनात्मक समीक्षा यो शब्दावली समस्याका बाबजुद पास हुन्छ।

## 1. सानो फोल्डर तयार गर्नुहोस्

Python 3.11–3.14 प्रयोग गर्नुहोस् र [भर्चुअल वातावरण सेटअप](configuration.md#local-runtime-setup) प्रयोग गर्नुहोस्। यस उदाहरणका लागि प्रयोग गरिएको संस्करण स्थापना गर्नुहोस्:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

यस फोल्डरमा [README.txt](../../assets/demo/README.txt) र [guide.txt](../../assets/demo/guide.txt) डाउनलोड गर्नुहोस्, र तिनीहरूलाई `README.md` र `guide.md` को रूपमा सुरक्षित गर्नुहोस्। यी साना कल्पनिक परियोजना कागजातहरू हुन्; कुनै एप्लिकेशन स्थापना आवश्यक छैन।

README मा एक कोड ब्लक र `guide.md` तर्फको लिंक समावेश छ। यसको अन्तिम वाक्य हो:

```text
Notes are saved locally.
```

यी दुई स्रोत कागजात मात्र यस फोल्डरमा राख्नुहोस्। सबै निम्न आदेशहरू `translation-demo` भित्र चल्छन् र Bash र PowerShell मा काम गर्छन्।

## 2. प्रमाणपत्र बिना पूर्वावलोकन

```bash
translate -l "ko" -md --dry-run
```

पूर्वावलोकनले मोडेल कल नगरी वा अनुवाद लेख्नु अघि अनुवाद कार्यको अनुमान लगाउँछ। टोकन अनुमान बिलिङ उद्धरण होइन। पहिलो रनले दुबै Markdown फाइलहरूलाई नयाँ कार्यको रूपमा पहिचान गर्नु पर्छ।

## 3. एक प्रदायक छान्नुहोस् र अनुवाद गर्नुहोस्

Azure OpenAI, OpenAI, वा Anthropic मध्ये एक प्रदायक [कन्फिगरेसन गाइड](configuration.md) मा दिइएको अनुसार कन्फिगर गर्नुहोस्। OpenAI र Anthropic पाठ अनुवादका लागि Azure खाता आवश्यक पर्दैन। यस उदाहरणका लागि इमेज सेवाहरू आवश्यक छैनन्।

यदि तपाईं स्थानीय `.env` फाइल प्रयोग गर्नुहुन्छ भने, `.env` लाई यस फोल्डरको `.gitignore` मा थप्नुहोस्। अनुवाद कलहरूले तपाईंको प्रदायक खाताको प्रयोग गर्छन् र चार्ज हुन सक्छन्।

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

`translations/ko/README.md` र `translations/ko/guide.md` खोल्नुहोस्। कोरियन शब्दावली, कोड ब्लक, र अनुवादित README बाट अनुवादित guide तर्फको लिंक जाँच गर्नुहोस्। आउटपुट शब्दावली मोडेल अनुसार फरक हुन सक्छ।

`co-op-review` ले ताजगी, संरचना, र स्थानीय लिंकहरू जाँच गर्छ। उत्तीर्ण परिणामले भाषिक शुद्धता प्रमाणित गर्दैन। जारी राख्नु अघि रिपोर्ट गरिएका कुनै पनि त्रुटिहरू समाधान गर्नुहोस्।

Git सँग सफल बेसलाइन दर्ता गर्नुहोस् (आवश्यक परे पहिले आफ्नो Git पहिचान कन्फिगर गर्नुहोस्):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. स्रोत परिवर्तन गर्नुहोस्

`README.md` मा, `Notes are saved locally.` लाई यससँग प्रतिस्थापन गर्नुहोस्:

```text
Notes are saved locally as Markdown files.
```

`guide.md` लाई अपरिवर्तित छोड्नुहोस्। त्यसपछि चलाउनुहोस्:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

समीक्षाले README अनुवादलाई अप्रचलित भएको रिपोर्ट गर्नु पर्छ र असफलतासाथ बाहिरिनु पर्छ। यो अपेक्षित मध्यवर्ती अवस्था हो। पूर्वावलोकनले परिवर्तन गरिएको README का लागि काम पहिचान गर्नु पर्छ।

## 5. अद्यावधिक गर्नुहोस् र diff जाँच्नुहोस्

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

वास्तविक diff जाँच्नुहोस्: डिफल्ट CLI ले परिवर्तन गरिएको फाइल पुन: अनुवाद गर्छ, त्यसैले मोडेलले त्यो फाइलमा अन्य शब्दावली पनि परिमार्जन गर्न सक्छ। अपरिवर्तित guide मा कुनै diff हुनु हुँदैन। समीक्षा अब README लाई अप्रचलितको रूपमा रिपोर्ट गर्नु हुँदैन; अन्यमाप्त पाइएका कुराहरूलाई बेवास्ता नगरी जाँच्नुहोस्।

मानव Markdown सम्पादनहरूको ब्लक-स्तर संरक्षणको लागि [Python API](api.md) मा वैकल्पिक अनुवाद स्थिति प्रदायक आवश्यक छ। यो CLI आदेशहरूले सक्षम गरेको छैन।

## 6. परिवर्तन बिना फेरि चलाउनुहोस्

अद्यावधिक गरिएको स्रोत र अनुवाद कमिट गर्नुहोस्:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

वर्तमान अनुवादहरू र अपरिवर्तित कन्फिगरेसनको साथ, अनुवादकले फाइलहरू स्किप गर्छ। अन्तिम Git आदेशले कुनै diff नउत्पन्न गर्नु पर्छ र सफलतापूर्वक बाहिरिनु पर्छ।
