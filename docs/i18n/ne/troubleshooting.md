# समस्या निवारण

अनुवाद सञ्चालन अनपेक्षित रूपमा सफल भएपछि, कन्फिगरेसनको क्रममा असफल हुँदा, वा समीक्षा आवश्यक पर्ने आउटपुट उत्पादन हुँदा यो पृष्ठ प्रयोग गर्नुहोस्।

## यहाँबाट सुरु गर्नुहोस्

1. सबैभन्दा पहिले लक्ष्यित कमाण्ड चलाउनुहोस्, जस्तै `translate -l "ko" -md`.
2. कन्सोल डिबग लगहरूका लागि `-d` थप्नुहोस्।
3. डिबग लगहरू `<root-dir>/logs/` अन्तर्गत बचत गर्न `-s` थप्नुहोस्।
4. ताजगी, संरचना, र स्थानीय लिङ्कहरूको जाँच गर्न अनुवादपछि `co-op-review` चलाउनुहोस्।

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## कन्फिगरेसन त्रुटिहरू

### भाषा मोडल प्रदायक छैन

त्रुटि:

```text
No language model configuration found.
```

समाधान:

- Azure OpenAI, OpenAI, वा Anthropic कन्फिगर गर्नुहोस्।
- कमाण्ड चल्ने वातावरणमा भेरिएबलहरू छन् भनी पुष्टि गर्नुहोस्।
- स्थानीय प्रयोगको लागि, तिनीहरूलाई प्रोजेक्ट रुटमा `.env` मा राख्नुहोस्।

हेर्नुहोस् [कन्फिगरेसन](configuration.md).

### Azure AI Vision बिना छवि अनुवाद

त्रुटि:

```text
Image translation requested but Azure AI Service is not configured.
```

समाधान:

- `AZURE_AI_SERVICE_API_KEY` थप्नुहोस्।
- `AZURE_AI_SERVICE_ENDPOINT` थप्नुहोस्।
- वा `translate -l "ko" -md` जस्ता टेक्स्ट-मात्र कमाण्ड चलाउनुहोस्।

### अमान्य कुञ्जी वा एन्डपोइन्ट

लक्षणहरूमा `401`, अनुमतिसम्बन्धी त्रुटिहरू (रेड्याक्ट गरिएको), वा एन्डपोइन्ट पहुँच त्रुटिहरू समावेश हुन सक्छन्।

समाधान:

- कुञ्जी त्यही Azure रिसोर्सको हो जुन एन्डपोइन्टको लागि प्रयोग भइरहेको छ भनी पुष्टि गर्नुहोस्।
- `-img` प्रयोग गर्दा सो रिसोर्स Vision समर्थित छ कि छैन पुष्टि गर्नुहोस्।
- Azure OpenAI deployment नाम र API संस्करण तपाईंको डिप्लोयमेन्टसँग मेल खान्छ कि छैन पुष्टि गर्नुहोस्।
- डिबग लगहरूसँग चलाउनुहोस्: `translate -l "ko" -md -d -s`.

## कुनै फाइल अनुवाद भएन

सामान्य कारणहरू:

- चयन गरिएको फ्ल्यागहरू तपाईंको फाइलहरुसँग मेल खाँदैनन्।
- पहिले नै अनुवादित फाइलहरू उपलब्ध छन्।
- स्रोत फाइलहरू बहिष्कृत निर्देशिकाहरू भित्र छन्।
- कमाण्ड गलत प्रोजेक्ट रुटबाट चलिरहेको छ।

जाँचहरू:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

कमाण्ड प्रोजेक्ट रुट बाहिरबाट चलाउने हो भने `--root-dir` प्रयोग गर्नुहोस्।

## अप्रत्याशित लिङ्क व्यवहार

लिङ्क पुनर्लेखन चयन गरिएका सामग्री प्रकारहरूमा निर्भर गर्दछ:

- `-nb` समावेश: नोटबुक लिङ्कहरू अनुवादित नोटबुकहरू तिर संकेत गर्न सक्छन्।
- `-nb` बहिष्कृत: नोटबुक लिङ्कहरू स्रोत नोटबुकहरूमा नै संकेत रहन सक्छन्।
- `-img` समावेश: छवि लिङ्कहरू अनुवादित छविहरू तिर संकेत गर्न सक्छन्।
- `-img` बहिष्कृत: छवि लिङ्कहरू स्रोत छविहरूमा नै संकेत रहन सक्छन्।

यदि सबै आन्तरिक लिङ्कहरूले अनुवादित आउटपुटलाई प्राथमिकता दिनुपर्छ भने पूर्ण सामग्री अनुवाद चलाउनुहोस्:

```bash
translate -l "ko" -md -nb -img
```

अनुवाद पछि लिङ्क समीक्षा चलाउनुहोस्:

```bash
co-op-review -l "ko"
```

## Markdown रेंडरिङ समस्याहरू

यदि अनुवादित Markdown गलत रूपमा रेंडर हुन्छ भने:

- फ्रन्टम्याटर `---` ले सुरु र समाप्त भएको छ भनी जाँच गर्नुहोस्।
- स्रोत र अनुवादित फाइलहरू बीच कोड फेन्सको संख्या मेल खान्छ कि छैन जाँच गर्नुहोस्।
- साधारण संरचनागत समस्या भेट्टाउन `co-op-review` चलाउनुहोस्।
- आउटपुट भ्रष्ट भएको खण्डमा सो विशिष्ट फाइल पुन:अनुवाद गर्नुहोस्।

```bash
co-op-review -l "ko" --format github
```

## GitHub Action चले तर कुनै Pull Request सिर्जना भएन

यदि `peter-evans/create-pull-request` रिपोर्ट गर्छ कि ब्रान्च बेसभन्दा अगाडि छैन भने, वर्कफ्लोले कमिट गर्ने कुनै फाइल फेला पारेन।

सम्भावित कारणहरू:

- अनुवाद रनले कुनै परिवर्तन उत्पादन गरेन।
- `.gitignore` ले `translations/`, `translated_images/`, वा अनुवादित नोटबुकहरूलाई बहिष्कृत गरेको छ।
- `add-paths` ले उत्पन्न आउटपुट निर्देशिकासँग मेल खाँदैन।
- अनुवाद चरण छिट्टै सकियो।

समाधानहरू:

1. उत्पन्न फाइलहरू `translations/` वा `translated_images/` मा अवस्थित छन् भनी पुष्टि गर्नुहोस्।
2. `.gitignore` ले उत्पन्न आउटपुटहरूलाई इग्नोर नगरेको छ भनी पुष्टि गर्नुहोस्।
3. मेल खाने `add-paths` प्रयोग गर्नुहोस्:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. अस्थायी रूपमा translate कमाण्डमा डिबग फ्ल्यागहरू थप्नुहोस्:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. वर्कफ्लो अनुमतिहरूमा निम्न समावेश छन् भनी पुष्टि गर्नुहोस्:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## अनुवाद गुणस्तर

मेसिन अनुवादहरूले मानव समीक्षा आवश्यक पर्न सक्छ। केवल तब मात्र `evaluate` प्रयोग गर्नुहोस् जब तपाईं परीक्षणात्मक गुणस्तर स्कोरिङ र कम-विश्वासी मरम्मत वर्कफ्लोहरू चाहनुहुन्छ।

!!! warning "Experimental"
    `evaluate` ले नियम-आधारित र LLM-आधारित जाँचहरू प्रयोग गर्न सक्छ, र यसको स्कोरिङ मोडेल तथा मेटाडेटा व्यवहार परिवर्तन हुन सक्छ। तपाईंको वर्कफ्लो परिवर्तनहरूको लागि तयार नभएसम्म यसलाई आवश्यक CI गेटहरूबाट बाहिर राख्नुहोस्।

डिटर्मिनिस्टिक CI जाँचहरूको लागि, यसको सट्टा `co-op-review` प्रयोग गर्नुहोस्।
