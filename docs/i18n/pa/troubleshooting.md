# ਸਮੱਸਿਆ ਨਿਵਾਰਣ

ਜਦੋਂ ਇੱਕ ਅਨੁਵਾਦ ਪ੍ਰਕਿਰਿਆ ਅਣਉਮੀਦ ਤੌਰ 'ਤੇ ਸਫਲ ਹੋ ਜਾਂਦੀ ਹੈ, ਕੰਫ਼ਿਗਰੇਸ਼ਨ ਦੌਰਾਨ ਫੇਲ ਹੁੰਦੀ ਹੈ, ਜਾਂ ਆਉਟਪੁੱਟ ਦੀ ਸਮੀਖਿਆ ਲੋੜੀਂਦੀ ਹੈ ਤਾਂ ਇਸ ਪੰਨੇ ਨੂੰ ਵਰਤੋ।

## ਇੱਥੋਂ ਸ਼ੁਰੂ ਕਰੋ

1. ਪਹਿਲਾਂ ਇੱਕ ਕੇਂਦਰਿਤ ਕਮਾਂਡ ਚਲਾਓ, ਉਦਾਹਰਨ ਵਜੋਂ `translate -l "ko" -md`.
2. ਕਨਸੋਲ ਡੀਬੱਗ ਲੌਗ ਲਈ `-d` ਜੋੜੋ।
3. ਡੀਬੱਗ ਲੌਗ ਸੇਵ ਕਰਨ ਲਈ `-s` ਜੋੜੋ; ਲੌਗ `<root-dir>/logs/` ਹੇਠਾਂ ਸੇਵ ਹੋਣਗੇ।
4. ਤਾਜ਼ਗੀ, ਢਾਂਚਾ, ਅਤੇ ਸਥਾਨਕ ਲਿੰਕ ਜਾਂਚਣ ਲਈ ਅਨੁਵਾਦ ਤੋਂ ਬਾਅਦ `co-op-review` ਚਲਾਓ।

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## ਕਨਫ਼ਿਗਰੇਸ਼ਨ ਦੀਆਂ ਗਲਤੀਆਂ

### ਭਾਸ਼ਾ ਮਾਡਲ ਪ੍ਰਦਾਤਾ ਨਹੀਂ ਹੈ

ਗਲਤੀ:

```text
No language model configuration found.
```

ਹੱਲ:

- Azure OpenAI, OpenAI, ਜਾਂ Anthropic ਨੂੰ ਕਨਫ਼ਿਗਰ ਕਰੋ।
- ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਵੇਰੀਏਬਲ ਉਸ ਵਾਤਾਵਰਣ ਵਿੱਚ ਹਨ ਜਿੱਥੇ ਕਮਾਂਡ ਚਲਦੀ ਹੈ।
- ਲੋਕਲ ਵਰਤੋਂ ਲਈ, ਇਨ੍ਹਾਂ ਨੂੰ ਪ੍ਰੋਜੈਕਟ ਰੂਟ 'ਤੇ `.env` ਵਿੱਚ ਪਾਓ।

ਵੇਖੋ [ਕਨਫ਼ਿਗਰੇਸ਼ਨ](configuration.md).

### Azure AI Vision ਦੇ ਬਿਨਾਂ ਚਿੱਤਰਾਂ ਦਾ ਅਨੁਵਾਦ

ਗਲਤੀ:

```text
Image translation requested but Azure AI Service is not configured.
```

ਹੱਲ:

- `AZURE_AI_SERVICE_API_KEY` ਸ਼ਾਮਲ ਕਰੋ।
- `AZURE_AI_SERVICE_ENDPOINT` ਸ਼ਾਮਲ ਕਰੋ।
- ਜਾਂ `translate -l "ko" -md` ਵਰਗੀ ਸਿਰਫ ਟੈਕਸਟ ਕਮਾਂਡ ਚਲਾਓ।

### ਅਵੈਧ ਕੀ ਜਾਂ ਐਂਡਪਾਈਂਟ

ਲੱਛਣਾਂ ਵਿੱਚ `401`, ਪਰਮੀਸ਼ਨ ਦੀਆਂ ਗਲਤੀਆਂ ਜਿਹਨਾਂ ਵਿੱਚ ਜਾਣਕਾਰੀ ਹਟਾਈ ਗਈ ਹੋਵੇ, ਜਾਂ ਐਂਡਪਾਇੰਟ ਐਕਸੈਸ ਗਲਤੀਆਂ ਸ਼ਾਮਲ ਹੋ ਸਕਦੀਆਂ ਹਨ।

ਹੱਲ:

- ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਕੀ ਉਸੇ Azure ਰਿਸੋਰਸ ਦਾ ਹੈ ਜੋ ਐਂਡਪਾਇੰਟ ਨਾਲ ਸੰਬੰਧਿਤ ਹੈ।
- `-img` ਵਰਤਦੇ ਸਮੇਂ ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਰਿਸੋਰਸ Vision ਨੂੰ ਸਪੋਰਟ ਕਰਦਾ ਹੈ।
- ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ Azure OpenAI ਡਿਪਲੋਇਮੈਂਟ ਦਾ ਨਾਮ ਅਤੇ API ਵਰਜ਼ਨ ਤੁਹਾਡੇ ਡਿਪਲੋਇਮੈਂਟ ਨਾਲ ਮੇਲ ਖਾਂਦੇ ਹਨ।
- ਡੀਬੱਗ ਲੌਗ ਨਾਲ ਚਲਾਓ: `translate -l "ko" -md -d -s`.

## ਕੋਈ ਫਾਇਲਾਂ ਅਨੁਵਾਦ ਨਹੀਂ ਹੋਈਆਂ

ਆਮ ਕਾਰਨ:

- ਚੁਣੇ ਗਏ ਫਲੈਗ ਤੁਹਾਡੀਆਂ ਫਾਇਲਾਂ ਨਾਲ ਮੇਲ ਨਹੀਂ ਖਾਂਦੇ।
- ਹੁਣੋਂ ਹੀ ਅਨੁਵਾਦ ਕੀਤੀਆਂ ਫਾਇਲਾਂ ਮੌਜੂਦ ਹਨ।
- ਸੋਰਸ ਫਾਇਲਾਂ ਉਹਨਾਂ ਡਾਇਰੈਕਟਰੀਜ਼ ਵਿੱਚ ਹਨ ਜੋ ਛੱਡੀਆਂ ਗਈਆਂ ਹਨ।
- ਕਮਾਂਡ ਗਲਤ ਪ੍ਰੋਜੈਕਟ ਰੂਟ ਤੋਂ ਚਲ ਰਹੀ ਹੈ।

ਜਾਂਚਾਂ:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

ਜਦੋਂ ਕਮਾਂਡ ਪ੍ਰੋਜੈਕਟ ਰੂਟ ਤੋਂ ਬਾਹਰ ਚਲਾਈ ਜਾ ਰਹੀ ਹੋਵੇ ਤਾਂ `--root-dir` ਵਰਤੋਂ।

## ਅਣਉਮੀਦ ਲਿੰਕ ਵਿਹਾਰ

ਲਿੰਕ ਮੁੜ ਲਿਖਣਾ ਚੁਣੇ ਗਏ ਸਮੱਗਰੀ ਦੇ ਕਿਸਮਾਂ 'ਤੇ ਨਿਰਭਰ ਕਰਦਾ ਹੈ:

- `-nb` ਸ਼ਾਮਲ: ਨੋਟਬੁੱਕ ਲਿੰਕ ਅਨੁਵਾਦ ਕੀਤੀਆਂ ਨੋਟਬੁੱਕਾਂ ਵੱਲ ਇਸ਼ਾਰਾ ਕਰ ਸਕਦੇ ਹਨ।
- `-nb` ਛੱਡਿਆ ਗਿਆ: ਨੋਟਬੁੱਕ ਲਿੰਕ ਸੋਰਸ ਨੋਟਬੁੱਕਾਂ ਵੱਲ ਹੀ ਰਹਿ ਸਕਦੇ ਹਨ।
- `-img` ਸ਼ਾਮਲ: ਚਿੱਤਰ ਲਿੰਕ ਅਨੁਵਾਦ ਕੀਤੀਆਂ ਚਿੱਤਰਾਂ ਵੱਲ ਇਸ਼ਾਰਾ ਕਰ ਸਕਦੇ ਹਨ।
- `-img` ਛੱਡਿਆ ਗਿਆ: ਚਿੱਤਰ ਲਿੰਕ ਸੋਰਸ ਚਿੱਤਰਾਂ ਵੱਲ ਰਹਿ ਸਕਦੇ ਹਨ।

ਜਦੋਂ ਸਾਰੇ ਅੰਦਰੂਨੀ ਲਿੰਕ ਅਨੁਵਾਦ ਕੀਤੇ ਨਿਕਾਸ ਨੂੰ ਤਰਜੀਹ ਦੇਣੇ ਚਾਹੀਦੇ ਹਨ ਤਾਂ ਪੂਰੀ ਸਮੱਗਰੀ ਦਾ ਅਨੁਵਾਦ ਚਲਾਓ:

```bash
translate -l "ko" -md -nb -img
```

Run link review after translation:

```bash
co-op-review -l "ko"
```

## ਮਾਰਕਡਾਊਨ ਰੈਂਡਰਿੰਗ ਸਮੱਸਿਆਵਾਂ

ਜੇ ਅਨੁਵਾਦਿਤ ਮਾਰਕਡਾਊਨ ਗਲਤ ਰੂਪ ਵਿੱਚ ਰੈਂਡਰ ਹੋ ਰਿਹਾ ਹੈ:

- ਜਾਂਚੋ ਕਿ ਫਰੰਟਮੈਟਰ `---` ਨਾਲ ਸ਼ੁਰੂ ਅਤੇ ਖਤਮ ਹੁੰਦਾ ਹੈ।
- ਜਾਂਚੋ ਕਿ ਕੋਡ ਫੈਨਸ ਦੀ ਗਿਣਤੀ ਸਰੋਤ ਅਤੇ ਅਨੁਵਾਦ ਕੀਤੀਆਂ ਫਾਇਲਾਂ ਵਿੱਚ ਮੇਲ ਖਾਂਦੀ ਹੈ।
- ਆਮ ਢਾਂਚਾਗਤ ਸਮੱਸਿਆਵਾਂ ਫੜਨ ਲਈ `co-op-review` ਚਲਾਓ।
- ਜੇ ਆਉਟਪੁੱਟ ਖਰਾਬ ਹੋਇਆ ਹੋਵੇ ਤਾਂ ਉਸ ਖ਼ਾਸ ਫਾਇਲ ਨੂੰ ਮੁੜ ਅਨੁਵਾਦ ਕਰੋ।

```bash
co-op-review -l "ko" --format github
```

## GitHub Action ਚਲਿਆ ਪਰ ਕੋਈ Pull Request ਨਹੀਂ ਬਣੀ

ਜੇ `peter-evans/create-pull-request` ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ ਕਿ ਬ੍ਰਾਂਚ ਬੇਸ ਤੋਂ ਅੱਗੇ ਨਹੀਂ ਹੈ ਤਾਂ ਵਰਕਫਲੋ ਨੇ ਕੰਮਿਟ ਕਰਨ ਲਈ ਕੋਈ ਫਾਇਲ ਨਹੀਂ ਲੱਭੀ।

ਸੰਭਵ ਕਾਰਨ:

- ਅਨੁਵਾਦ ਚਲਾਉਣ ਨਾਲ ਕੋਈ ਤਬਦੀਲੀ ਨਹੀਂ ਹੋਈ।
- `.gitignore` `translations/`, `translated_images/`, ਜਾਂ ਅਨੁਵਾਦ ਕੀਤੀਆਂ ਨੋਟਬੁੱਕਾਂ ਨੂੰ ਬਾਹਰ ਰੱਖ ਰਿਹਾ ਹੈ।
- `add-paths` ਬਨਾਈਆਂ ਗਈਆਂ ਆਉটਪੁੱਟ ਡਾਇਰੈਕਟਰੀਜ਼ ਨਾਲ ਮੇਲ ਨਹੀਂ ਖਾਂਦਾ।
- ਅਨੁਵਾਦ ਕਦਮ ਜਲਦੀ ਬੰਦ ਹੋ ਗਿਆ।

ਹੱਲ:

1. ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ `translations/` ਜਾਂ `translated_images/` ਵਿੱਚ ਬਨਾਈਆਂ ਗਈਆਂ ਫਾਇਲਾਂ ਮੌਜੂਦ ਹਨ।
2. ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ `.gitignore` ਬਣਾਈਆਂ ਗਈਆਂ ਆਉਟਪੁੱਟ ਨੂੰ ਇਗਨੋਰ ਨਹੀਂ ਕਰ ਰਿਹਾ।
3. ਮਿਲਦੇ ਜੁਲਦੇ `add-paths` ਵਰਤੋਂ:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. ਅਸਥਾਈ ਤੌਰ 'ਤੇ translate ਕਮਾਂਡ ਵਿੱਚ ਡੀਬੱਗ ਫਲੈਗ ਸ਼ਾਮਲ ਕਰੋ:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਵਰਕਫਲੋ ਅਨੁਮਤੀਆਂ ਵਿੱਚ ਇਹ ਸ਼ਾਮਲ ਹਨ:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## ਅਨੁਵਾਦ ਦੀ ਗੁਣਵੱਤਾ

ਮਸ਼ੀਨੀ ਅਨੁਵਾਦਾਂ ਨੂੰ ਮਨੁੱਖੀ ਸਮੀਖਿਆ ਦੀ ਲੋੜ ਪੈ ਸਕਦੀ ਹੈ। `evaluate` ਨੂੰ ਸਿਰਫ਼ ਉਸ ਵੇਲੇ ਵਰਤੋ ਜਦੋਂ ਤੁਸੀਂ ਪ੍ਰਯੋਗਾਤਮਕ ਗੁਣਵੱਤਾ ਸਕੋਰਿੰਗ ਅਤੇ ਘੱਟ-ਭਰੋਸੇ ਵਾਲੇ ਸੁਧਾਰ ਵਰਕਫਲੋਜ਼ ਚਾਹੁੰਦੇ ਹੋ।

!!! warning "Experimental"
    `evaluate` rule-based ਅਤੇ LLM-ਅਧਾਰਿਤ ਚੈੱਕ ਵਰਤ ਸਕਦਾ ਹੈ, ਤੇ ਇਸਦਾ ਸਕੋਰਿੰਗ ਮਾਡਲ ਅਤੇ ਮੈਟਾ ਡੇਟਾ ਦਾ ਵਿਹਾਰ ਬਦਲ ਸਕਦਾ ਹੈ। ਇਸਨੂੰ ਲਾਜ਼ਮੀ CI ਗੇਟਾਂ ਵਿੱਚ ਨਾ ਰੱਖੋ ਜੇ ਤੱਕ ਤੁਹਾਡਾ ਵਰਕਫਲੋ ਬਦਲਾਅਾਂ ਲਈ ਤਿਆਰ ਨਾ ਹੋਵੇ।

ਨਿਰਧਾਰਤ CI ਜਾਂਚਾਂ ਲਈ ਬਦਲੇ ਵਿੱਚ `co-op-review` ਵਰਤੋਂ।
