# Перевести, отредактировать и проверить небольшой проект

Начните с двух коротких файлов в формате Markdown и одного целевого языка. Вы увидите, куда записываются переводы, что происходит при изменении исходника и как проверить результат.

## Зафиксированные результаты

Пример был выполнен 19 сентября 2026 года с помощью Co-op Translator 0.21.0 и Azure OpenAI (`gpt-5-mini`). Немодифицированные команды CLI были вызваны через Click's `CliRunner`, используя собранный wheel и существующие зависимости Python.

| Шаг | Результат |
| --- | --- |
| Предпросмотр | Код выхода 0; перевод модели не запрашивался |
| Первоначальный перевод | Код выхода 0; 27.36 секунд |
| Первичная проверка | Код выхода 0 |
| Редактирование README и проверка | Код выхода 1; обнаружен устаревший перевод |
| Обновление перевода | Код выхода 0; 22.17 секунд |
| Проверка после обновления | Код выхода 0; ошибок и предупреждений нет |
| Неизменённое руководство | Байты идентичны до и после обновления README |
| Повторный запуск | Код выхода 0; идентичные хеши для всех файлов перевода |

Это результаты отдельных запусков, а не гарантия производительности. Время настройки не учтено; выставление счетов провайдера не измерялось. При неизменном запуске всё ещё может выполняться проверка работоспособности провайдера.

Просмотрите [первоначальный перевод](../../assets/demo/before.txt), [обновлённый перевод](../../assets/demo/after.txt), [полный diff перевода](../../assets/demo/update.diff), [устаревшую проверку](../../assets/demo/review-stale.txt), [окончательную проверку](../../assets/demo/review-after.txt) и [подробности запуска](../../assets/demo/results.json). Перевод всего файла может изменить другие формулировки, как показывает зафиксированный diff. Оба текстовых артефакта сохраняют сгенерированное уведомление об отказе от ответственности.

Человеческая проверка по‑прежнему важна: зафиксированное обновление использует `[사용 가이드](guide.md)을`; корейский падежный показатель должен быть `[사용 가이드](guide.md)를`. Текстовые артефакты сохраняют этот вывод без правок, а не представляют отредактированный перевод как вывод модели. Структурная проверка пройдена, несмотря на эту проблему с формулировкой.

## 1. Подготовьте небольшую папку

Используйте Python 3.11–3.14 и [настройку виртуального окружения](configuration.md#local-runtime-setup). Установите версию, использованную в этом примере:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

Скачайте [README.txt](../../assets/demo/README.txt) и [guide.txt](../../assets/demo/guide.txt) в эту папку, сохранив их как `README.md` и `guide.md`. Это небольшие вымышленные документы проекта; установка приложений не требуется.

README содержит блок кода и ссылку на `guide.md`. Его последнее предложение:

```text
Notes are saved locally.
```

Держите в этой папке только эти два исходных документа. Все последующие команды выполняются внутри `translation-demo` и работают в Bash и PowerShell.

## 2. Предпросмотр без учётных данных

```bash
translate -l "ko" -md --dry-run
```

Предпросмотр оценивает объём перевода без вызова модели и без записи переводов. Оценки токенов не являются расчётом для биллинга. Первый запуск должен определить оба Markdown-файла как новую работу.

## 3. Выберите провайдера и выполните перевод

Настройте одного провайдера, используя [руководство по конфигурации](configuration.md): Azure OpenAI, OpenAI или Anthropic. Перевод текста с помощью OpenAI и Anthropic не требует аккаунта Azure. Службы для изображений для этого примера не нужны.

Если вы используете локальный файл `.env`, добавьте `.env` в `.gitignore` этой папки. Вызовы перевода используют ваш аккаунт провайдера и могут вызвать списание средств.

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

Откройте `translations/ko/README.md` и `translations/ko/guide.md`. Проверьте корейские формулировки, блок кода и ссылку из переведённого README на переведённый guide. Формулировки вывода зависят от модели.

`co-op-review` проверяет актуальность, структуру и локальные ссылки. Успешный результат не гарантирует лингвистическую точность. Исправьте все указанные ошибки до продолжения.

Зафиксируйте успешную эталонную версию с помощью Git (при необходимости сначала настройте свою идентичность Git):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. Измените исходник

В `README.md` замените `Notes are saved locally.` на:

```text
Notes are saved locally as Markdown files.
```

Оставьте `guide.md` без изменений. Затем выполните:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

Проверка должна отозваться, что перевод README устарел, и завершиться с ошибкой. Это ожидаемое промежуточное состояние. Предпросмотр должен выявить работу по изменённому README.

## 5. Обновите и просмотрите diff

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

Просмотрите реальный diff: CLI по умолчанию повторно переводит изменённый файл, поэтому модель может также пересмотреть другие формулировки в этом файле. Для неизменённого guide не должно быть diff. Проверка больше не должна отмечать README как устаревший; исследуйте любые другие замечания, а не игнорируйте их.

Сохранение изменений в Markdown на уровне блоков требует опционального провайдера состояния перевода в [Python API](api.md). Он не включён в этих командах CLI.

## 6. Запустите снова без изменений

Зафиксируйте обновлённый исходник и перевод:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

При текущих переводах и неизменённой конфигурации транслятор пропускает файлы. Конечная команда Git не должна давать diff и должна завершиться успешно.
