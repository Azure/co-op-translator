# Устранение неполадок

Используйте эту страницу, когда запуск перевода неожиданно завершается успешно, прерывается на этапе конфигурации или генерирует выходные данные, требующие проверки.

## Начните здесь

1. Сначала запустите целевую команду, например `translate -l "ko" -md`.
2. Добавьте `-d` для отладочных логов в консоли.
3. Добавьте `-s`, чтобы сохранять отладочные логи в `<root-dir>/logs/`.
4. Выполните `co-op-review` после перевода, чтобы проверить актуальность, структуру и локальные ссылки.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## Ошибки конфигурации

### Отсутствует провайдер языковой модели

Ошибка:

```text
No language model configuration found.
```

Решение:

- Настройте Azure OpenAI, OpenAI или Anthropic.
- Убедитесь, что переменные присутствуют в окружении, где выполняется команда.
- Для локального использования поместите их в файл `.env` в корне проекта.

См. [Конфигурация](configuration.md).

### Перевод изображений без Azure AI Vision

Ошибка:

```text
Image translation requested but Azure AI Service is not configured.
```

Решение:

- Добавьте `AZURE_AI_SERVICE_API_KEY`.
- Добавьте `AZURE_AI_SERVICE_ENDPOINT`.
- Или выполните команду только для текста, например `translate -l "ko" -md`.

### Неверный ключ или конечная точка

Симптомы могут включать `401`, скрытые ошибки разрешений или ошибки доступа к конечной точке.

Решение:

- Убедитесь, что ключ принадлежит тому же ресурсу Azure, что и конечная точка.
- Убедитесь, что ресурс поддерживает Vision при использовании `-img`.
- Убедитесь, что имя развертывания Azure OpenAI и версия API совпадают с вашим развертыванием.
- Запустите с отладочными логами: `translate -l "ko" -md -d -s`.

## Ни один файл не был переведен

Распространенные причины:

- Выбранные флаги не соответствуют вашим файлам.
- Уже существуют переведенные файлы.
- Исходные файлы находятся в исключенных директориях.
- Команда выполняется не из корня проекта.

Проверки:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

Используйте `--root-dir`, если команда запускается вне корня проекта.

## Неожиданное поведение ссылок

Переписывание ссылок зависит от выбранных типов контента:

- `-nb` включён: ссылки на ноутбуки могут указывать на переведенные ноутбуки.
- `-nb` исключён: ссылки на ноутбуки могут оставаться указывающими на исходные ноутбуки.
- `-img` включён: ссылки на изображения могут указывать на переведённые изображения.
- `-img` исключён: ссылки на изображения могут оставаться указывающими на исходные изображения.

Выполните полный перевод содержимого, если все внутренние ссылки должны предпочитать переведенные варианты:

```bash
translate -l "ko" -md -nb -img
```

Выполните проверку ссылок после перевода:

```bash
co-op-review -l "ko"
```

## Проблемы с рендерингом Markdown

Если переведённый Markdown отображается некорректно:

- Проверьте, что frontmatter начинается и заканчивается `---`.
- Проверьте, что количество ограждений кода совпадает между исходными и переведёнными файлами.
- Запустите `co-op-review`, чтобы обнаружить распространённые проблемы со структурой.
- Переведите заново конкретный файл, если выход был повреждён.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action выполнился, но Pull Request не был создан

Если `peter-evans/create-pull-request` сообщает, что ветка не опережает базовую, рабочий процесс не нашёл файлов для коммита.

Возможные причины:

- Запуск перевода не привёл к изменениям.
- В `.gitignore` исключены `translations/`, `translated_images/` или переведённые ноутбуки.
- `add-paths` не соответствует сгенерированным выходным директориям.
- Шаг перевода завершился преждевременно.

Исправления:

1. Убедитесь, что сгенерированные файлы существуют в `translations/` или `translated_images/`.
2. Убедитесь, что `.gitignore` не игнорирует сгенерированные файлы.
3. Используйте соответствующие `add-paths`:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. Временно добавьте флаги отладки к команде translate:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. Убедитесь, что разрешения рабочего процесса включают:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## Качество перевода

Машинные переводы могут требовать проверки человеком. Используйте `evaluate` только если вам нужны экспериментальные метрики качества и процессы исправления с низкой уверенностью.

!!! warning "Экспериментально"
    `evaluate` может использовать проверку на основе правил и на основе LLM, а его модель оценки и поведение с метаданными могут измениться. Не включайте его в обязательные CI-проверки, если ваш рабочий процесс не готов к изменениям.

Для детерминированных CI-проверок используйте вместо этого `co-op-review`.
