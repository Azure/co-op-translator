# Решавање проблема

Користите ову страницу када покретање превода неочекивано успе, не успе током конфигурације, или произведе излаз који захтева преглед.

## Почните овде

1. Прво покрените фокусирану команду, као што је `translate -l "ko" -md`.
2. Додајте `-d` за конзолне логове отклањања грешака.
3. Додајте `-s` да бисте сачували логове отклањања грешака у `<root-dir>/logs/`.
4. Покрените `co-op-review` након превођења да бисте проверили свежину, структуру и локалне везе.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## Грешке конфигурације

### Није доступан провајдер језичког модела

Грешка:

```text
No language model configuration found.
```

Решење:

- Конфигуришите Azure OpenAI, OpenAI или Anthropic.
- Проверите да ли су променљиве у окружењу у којем команда ради.
- За локалну употребу, ставите их у `.env` у корену пројекта.

Погледајте [Конфигурација](configuration.md).

### Превођење слика без Azure AI Vision

Грешка:

```text
Image translation requested but Azure AI Service is not configured.
```

Решење:

- Додајте `AZURE_AI_SERVICE_API_KEY`.
- Додајте `AZURE_AI_SERVICE_ENDPOINT`.
- Или покрените команду само за текст, на пример `translate -l "ko" -md`.

### Неважећи кључ или ендпоинт

Симптоми могу бити `401`, поруке о дозволама означене као 'redacted', или грешке приступа ендпоинту.

Решење:

- Потврдите да кључ припада истом Azure ресурсу као и ендпоинт.
- Потврдите да ресурс подржава Vision када користите `-img`.
- Потврдите да име Azure OpenAI деплоја и верзија API-ја одговарају вашој деплоји.
- Покрените са логовима отклањања грешака: `translate -l "ko" -md -d -s`.

## Ниједан фајл није преведен

Чести разлози:

- Одабрани флагови не одговарају вашим фајловима.
- Постојећи преведени фајлови су већ присутни.
- Изворни фајлови су у искљученим директоријумима.
- Команда се покреће из погрешног корена пројекта.

Провере:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

Користите `--root-dir` када се команда покреće ван корена пројекта.

## Неочекивано понашање веза

Преписивање веза зависи од одабраних типова садржаја:

- `-nb` укључено: везе ка notebook фајловима могу упућивати на преведене notebook фајлове.
- `-nb` искључено: везе ка notebook фајловима могу остати усмерене на изворне notebook фајлове.
- `-img` укључено: везе ка сликама могу упућивати на преведене слике.
- `-img` искључено: везе ка сликама могу остати усмерене на изворне слике.

Покрените комплетан превод садржаја када све интерне везе треба да претпочитају преведене резултате:

```bash
translate -l "ko" -md -nb -img
```

Покрените преглед веза након превођења:

```bash
co-op-review -l "ko"
```

## Проблеми са рендеровањем Markdown-а

Ако се преведени Markdown приказује нетачно:

- Проверите да frontmatter почиње и завршава са `---`.
- Проверите да се бројеви кодних ограда подударају између изворних и преведених фајлова.
- Покрените `co-op-review` да ухватите уобичајене проблеме структуре.
- Поново преведите конкретан фајл ако је излаз оштећен.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action је покренут али није креиран Pull Request

Ако `peter-evans/create-pull-request` пријави да грана није испред базе, workflow није пронашао фајлове за комитовање.

Веројатни узроци:

- Покретање превода није произвело промене.
- `.gitignore` искључује `translations/`, `translated_images/` или преведене notebook фајлове.
- `add-paths` се не поклапа са генерисаним директоријумима излаза.
- Фаза превођења је прекинута раније.

Решења:

1. Потврдите да генерисани фајлови постоје у `translations/` или `translated_images/`.
2. Потврдите да `.gitignore` не игнорише генерисане излазне фајлове.
3. Користите одговарајући `add-paths`:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. Привремено додајте debug флагове у translate команду:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. Потврдите да дозволе workflow-а укључују:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## Квалитет превода

Машински преводи могу захтевати људски преглед. Користите `evaluate` само када желите експериментално оцењивање квалитета и токове рада за поправке ниског поверења.

!!! warning "Експериментално"
    `evaluate` може користити провере засноване на правилима и на LLM, а његов модел оцењивања и понашање метаподатака могу се променити. Не укључујте га у обавезне CI контроле ако ваш ток рада није припремљен на промене.

За детерминистичке CI провере, користите уместо тога `co-op-review`.
