# மொழி மேம்பாடுகளில் பங்களிப்பு

உங்கள் மொழி அறிவு Co-op Translator-ஐ மேம்படுத்த உதவும். ஒரு எடுத்துக்காட்டு, ஒரு பரிந்துரை செய்யப்பட்ட திருத்தம் மற்றும் ஒரு விளக்கத்துடன் [மொழிபெயர்ப்பு கருத்து படிவம்](https://github.com/Azure/co-op-translator/issues/new?template=translation_feedback.yml) மூலம் தொடங்குங்கள். நீங்கள் குறியீட்டை எழுத தேவையில்லை அல்லது மாடல் இயக்கத்திற்கு கட்டணம் செலுத்த தேவையில்லை.

## அறிக்கையிலிருந்து பகிரப்பட்ட மேம்பாட்டிற்கு

1. ஒரு பங்களிப்பாளர் ஒரு மூல உரை பகுதியை, அதன் மொழிபெயர்ப்பை மற்றும் அதன் சூழலை வழங்குகிறார்.
2. ஒரு மொழி மதிப்பாளர் பொருள், இயல்புத்தன்மை மற்றும் பரிந்துரை குறிப்பிட்ட பிராந்தியத்திற்கோ அல்லது பாடத்திற்கோ சார்ந்ததா என்பதை பரிசீலிக்கிறார்.
3. ஒரு பராமரிப்பாளர் அந்த திருத்தம் மூலப் பாடத்தில் இருக்க வேண்டுமா, பகிரப்பட்ட மொழி வழிகாட்டலுக்கு சொந்தமா, சொல் வரையறை அமைப்பில் சேர்க்கப்பட வேண்டுமா அல்லது மொழிபெயர்ப்பு குறியீட்டில் இருக்க வேண்டுமா என்று தீர்மானிக்கிறார்.
4. பகிரப்பட்ட விதிக்கு, பராமரிப்பாளர் தெரிவிக்கப்பட்ட எடுத்துக்காட்டில் மற்றும் தொடர்பற்ற எடுத்துக்காடுகளில் மாற்றத்திற்கு முன் மற்றும் மாற்றத்திற்கு பின்பு வெளியீடுகளை ஒப்பிடுகிறார். பங்களிப்பாளர்கள் இத்தெரிவுகளை கருவியை நேரடியாக இயக்காமலேயே மதிப்பாய்வதற்கு பார்க்கலாம்.
5. உருவாகிய PR அறிக்கையை இணைக்கிறது மற்றும் உதாரணங்கள் வழங்கிய மற்றும் மதிப்பாய்வு செய்தவர்களுக்கு கடன் நீட்டுகிறது. பயன்படும் रिपொசிடரியங்களில் 배포 அல்லது மறுபிறந்தமைப்பு ஒரு தனித்தடமாக இருக்கும்.

ஒரு அறிக்கை தானாகவே prompts-ஐ மாற்றவோ அல்லது பாட மொழிபெயர்ப்புகளை மறுபிறப்படுத்தவோ செய்யாது. பாட-சொந்த திருத்தங்கள் பாடகுறுந்தொகுப்பு (course repository) உடன் இணைந்து இருக்க வேண்டும். ஒரு கையேடு திருத்தம் பின்னர் மறுபெயர்ப்பில் நீடித்திருப்பதாக கருதிக்கொளவேண்டாம்; அந்த வேலைநடத்தை எப்படி நடைபெறுகின்றதென்பதை உறுதிப்படுத்துங்கள்.

## உள்ளடக்க举 எடுத்துக்காட்டு: ஜப்பானிய Markdown இணைப்புகள்

[ஜப்பானிய வழிமுறைக் கோப்பு](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/templates/language/ja.md) மாதிரிக்கு இணைப்பு உரையை மொழிபெயர்க்கும்படி உத்தரவிடுகிறது, Markdown வடிவத்தை மற்றும் இணைப்பு இலக்கினை பேணினால். உதாரணமாக, `[text](URL)` என எழுதப்பட்ட இணைப்பு `「text」（URL）` ஆக மாறக்கூடாது.

இது சரியான மற்றும் தவறான வெளியீடுகளின் விளக்கத்துடன் ஆதரிக்கப்படும் ஒரு கவனிக்கப்பட்ட மொழி விதியின் எடுத்துக்காட்டாகும். இது ஒரே prompt அறிவுறுத்தல்கள் மட்டுமே சரியான Markdown-ஐ உறுதிசெய்யும் என்கிற சான்றாகக் கொள்ளப்படக்கூடாது.

[Markdown prompt builder](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/utils/markdown/prompts.py) `templates/language/<language_code>.md`ஐ கடைசித் எழுத்து சிறிய எழுத்தாகவும் சுற்று வெற்றிடங்கள் அகற்றப்பட்ட மொழி குறியீட்டை பயன்படுத்தி ஏற்றுகிறது. கோப்பு காணப்படாவிடில், அது பொதுவான வழிமுறைகளை பயன்படுத்தும். இது Markdown prompt பாதையை விவரிக்கிறது; ஒவ்வொரு படம் அல்லது மற்ற மொழிபெயர்ப்பு பாதையும் அதே அறிவுறுத்தல்களை பயன்படுத்தும் என்று கருதாதீர்கள்.

[prompt tests](https://github.com/Azure/co-op-translator/blob/main/tests/co_op_translator/utils/markdown/test_prompts.py) ஜப்பானிய வழிமுறைகள் சேர்க்கப்பட்டுள்ளதா என்பதை சரிபார்க்கின்றன. அது prompt தொகுப்பை உறுதிப்படுத்துகிறது, மொழிபெயர்ப்பு தரத்தை அல்ல.

## ஒரு மொழி விதியில் என்ன சேர்க்கப்பட வேண்டும்?

ஒரு குறுகிய, மீண்டும் பயன்படுத்தக்கூடிய திருத்தத்தைக் கூர்ந்து முன்மொழியுங்கள் — ஒரு மூல எடுத்துக்காட்டு, எதிர்பார்க்கப்படும் நடத்தை மற்றும் அந்த விதி பொருந்தக் கூடக்கூடாத ஒரு எதிர்-உதாரணத்துடன். பொருள், இடநிரப்பிகள், குறியீடு, URL-கள் மற்றும் ஆவண கட்டமைப்பை பாதுகாத்திருங்கள். ஒருவரின் ஸ்டைல் விருப்பம் அல்லது ஒரு பாடத்தின் சொற்பயன்பாடு அனைத்துக்கும் பொதுவான விதியாக மாறாமலிருக்கவும்.

தற்போது உள்ள [பேரகருத்து செயல்பாடு](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/glossary.py) சொற்களை மொழிபெயர்ப்பில் இருந்து பாதுகாக்கிறது. அது மூலத்திலிருந்துகொண்டு இலக்கில் சொற்களை நேரடியாக ஒப்படைப்பு செய்யும் ஒரு 용ரியல் அகராதி அல்ல. பங்களிப்பாளர்களுக்கு நிச்சயமாக கூறுவதற்கு முன் புதிய 용ரியல் நடத்தை பற்றி விவாதியுங்கள்.

## சமூக எடுத்துக்காட்டு: ஒரு ஜப்பானிய தயாரிப்பு-பெயர் அறிக்கை

[report #527](https://github.com/Azure/co-op-translator/issues/527)-இல், @hyoshioka0128 ஜப்பானிய மொழிபெயர்ப்பில் தயாரிப்பு பெயர் `Co-op Translator` `Co-op 翻訳` ஆக மாற்றப்பட்டதைக் கண்டுபிடித்தார். அறிக்கையில் பாதிக்கப்பட்ட ஆவணத்திற்கு ஒரு இணைப்பு மற்றும் ஒரு ஸ்க்ரீன்ஷாட் இருந்தன, இதனால் பிரச்சினையை எளிதாக கண்டுபிடிக்க முடிந்தது.

பங்களிப்பாளர் தொடர்புடைய [course PR](https://github.com/microsoft/AZD-for-beginners/pull/109)-ஐவும் இணைத்தார். பிரச்சினை விவாதத்தில், பராமரிப்பாளர் அறிக்கையை ஏற்றுக்கொண்டார் மற்றும் பெயர் ஏன் மாறியது என்பதை ஆராய பரிந்துரைத்தார் — இதில் சொற்களை பாதுகாப்பது, பேரகருத்து நடத்தை மற்றும் மொழிபெயர்ப்பு பாதை ஆகியவையும் உள்ளன.

இது ஒரு சிறிய அறிக்கை தனித்த சொற்தொடர் திருத்தத்தைக் கடந்தும் விசாரணைக்கு உதவக்கூடியது என்பதை காட்டுகிறது. இது verified முன்/பின் விளைவு அல்லது மேல் கூறியுள்ள ஜப்பானிய Markdown-இணைப்பு வழிமுறைகள் இந்த தயாரிப்பு-பெயர் பிரச்சினையை சரிசெய்ததாக சான்று அல்ல.

நீங்கள் இதே விதமாக உதவலாம்: மூல உரையை, தற்போதைய மொழிபெயர்ப்பை, பரிந்துரைக்கப்பட்ட திருத்தத்தையும் அது முக்கியமான காரணத்தையும் பகிருங்கள். தேவைப்பட்டால் ஆவண இணைப்பு அல்லது ஸ்க்ரீன்ஷாட் சேர்க்கவும். காரணத்தை கண்டறிய அல்லது அறிக்கை செய்யுமுன் prompt எழுத தேவையில்லை.

## ஒரு விதியை ஏற்றுமுன் சரிபார்ப்பு

அடிப்படை மற்றும் מועמד ரன்களுக்கு அதே மூல மாதிரிகள், மொழிபெயர்ப்பு திருத்தம், வழங்குநர்/மாடல் மற்றும் உற்பத்தியின் அமைப்புகளை பயன்படுத்துங்கள்; மட்டும் பரிந்துரைக்கப்படும் அறிவுரையை மாற்றுங்கள். இயல்பான prompt மாற்றத்தையும் வெளியீடுகளையும் பதிவு செய்யுங்கள்; ஒரே தொடர்சியான விளைவுத்தன்மையிலிருந்து வெளியீட்டுத் தள்ளுபடிகளை வேறுபடுத்த தேவையான போது எடுத்துக்காட்டுகளை மீண்டும் செய்யுங்கள். தகவமைப்பு, மாடல் ரன்கள் அல்லது மொழி மதிப்பீடு இல்லையெனில், பிரச்சினை தீர்ந்திடப்பட்டதாக சொல்லாமைப்டு பரிந்துரையை காத்திருக்க விடுங்கள்.

கட்டமைப்பு மாறாத तत्वங்களை மொழி மதிப்பீடுகளிலிருந்து தனியாகச் சரிபார்க்கவும். ஒரு வெற்றிகரமான கோரிக்கை ஏற்றல் சோதனை என்பது தரத் தரமதிப்பீடு அல்ல, மேலும் ஒரு சரியாகக் காணப்படும் ஒரு வாக்கியம் மட்டுமே செல்லுபடியான மொழிபெயர்ப்பல்ல. சூழல், மாடல் இயக்கங்கள் அல்லது மொழி மதிப்பீடு இல்லையெனில், பிரச்சினை தீர்ந்துவிட்டதாகக் குறிப்பதைப் பதிலாக பரிந்துரையை காத்திருக்க விடுங்கள்.
