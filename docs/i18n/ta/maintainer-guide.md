# பராமரிப்பு வழிகாட்டி

இந்த பக்கம் API, CLI மற்றும் ஆவண தளம் ஒன்றாக எவ்வாறு இணைக்கப்பட்டுள்ளன என்பதைக் சுருக்கமாக விளக்குகிறது.

## பொது API எல்லை

நிலையான Python API இதிலிருந்து ஏற்றுமதி செய்யப்படுகிறது:

```python
co_op_translator.api
```

பொதுப் API உள்ளடக்க மொழிபெயர்ப்பு உதவிகள், பாதை மறுவழி எழுதுதல் உதவிகள், திட்ட ஒழுங்கமைப்பு மற்றும் மதிப்பீடு ஆகியவையாக ஒழுங்குபடுத்தப்பட்டுள்ளது:

```python
from co_op_translator.api import (
    ImageTranslationOptions,
    MarkdownTranslationOptions,
    NotebookTranslationOptions,
    TranslationBaseline,
    TranslationStateProvider,
    TranslationUpdate,
    run_review,
    run_translation,
    rewrite_markdown_paths,
    rewrite_notebook_paths,
    translate_image_content,
    translate_markdown_content,
    translate_notebook_content,
    translate_project,
)
```

`TranslationStateProvider` என்பது ஹோஸ்ட் செய்யப்பட்ட ஒருங்கிணைப்புகளுக்கான நிலைத்தன்மை எல்லை ஆகும்.
இது உருவாக்கப்பட்ட வேட்பாளர்களை ஏற்றுக்கொள்ளப்பட்ட அடிப்படைகளிலிருந்து பிரித்து வைத்திருக்க வேண்டும், இதனால்
ஒன்றாக இணைக்கப்படாத மொழிபெயர்ப்பு உண்மையின் மூலமாக மாறக்கூடாது.

புதிய பொது APIகளைச் சேர்க்கும் போது, இதைகளை புதுப்பிக்கவும்:

- `src/co_op_translator/api/__init__.py`
- `docs/api.md`
- தொடர்புடைய API சோதனைகள் `tests/co_op_translator/` இல், உதாரணமாக `test_api.py` அல்லது `test_review_api.py`

திட்டம் அவற்றை நேரடியாக ஆதரிக்க நினைக்கவில்லையெனில், கீழ்தர `core` மொட்யூல்களை நிலையான API என்று ஆவணப்படுத்த வேண்டாம்.

## CLI நுழைவு புள்ளிகள்

பேக்கேஜ் இவை போன்ற Poetry ஸ்கிரிப்டுகளை வரையறுக்கிறது:

```toml
[tool.poetry.scripts]
translate = "co_op_translator.__main__:main"
evaluate = "co_op_translator.__main__:main"
migrate-links = "co_op_translator.__main__:main"
co-op-review = "co_op_translator.__main__:main"
co-op-translator-mcp = "co_op_translator.mcp.server:main"
```

`src/co_op_translator/__main__.py` ஸ்கிரிப்ட் பெயரின்படி ஒதுக்கப்படுகிறது:

- `translate` அழைக்கிறது `co_op_translator.cli.translate.translate_command`
- `evaluate` அழைக்கிறது `co_op_translator.cli.evaluate.evaluate_command`
- `migrate-links` அழைக்கிறது `co_op_translator.cli.migrate_links.migrate_links_command`
- `co-op-review` அழைக்கிறது `co_op_translator.cli.review.review_command`

`co-op-translator-mcp` `__main__.py` ஐ மீறுகிறது மற்றும் நேரடியாக `co_op_translator.mcp.server:main` ஐ அழைக்கிறது.

CLI விருப்பங்களைச் சேர்க்கும் அல்லது மாற்றும் போது, இதைகளை புதுப்பிக்கவும்:

- தொடர்புடைய `src/co_op_translator/cli/*.py` கட்டளை
- `docs/cli.md`
- நடத்தை மாற்றப்பட்டால் CLI-க்கு தொடர்புடைய சோதனைகள்

## MCP server

MCP சர்வர் இங்கே செயல்படுத்தப்பட்டுள்ளது:

```python
co_op_translator.mcp.server
```

சர்வர் குறைந்த நிலை `core` மொட்யூல்களை நேரடியாக அழைக்காமல் நோக்கமாக பொது Python API-ஐ சுற்றி மூடுகிறது. MCP கிளையன்டுகள், Python அழைப்பாளர்கள், மற்றும் CLI ஒரே நெறியினைப் பகிர்ந்துகொள்ள இந்த எல்லையை மாற்றாமல் வைத்திருங்கள்.

MCP கருவிகளைச் சேர்ந்தவையாக சேர்க்கும்போது அல்லது மாற்றும்போது, புதுப்பிக்கவும்:

- `src/co_op_translator/mcp/server.py`
- `tests/co_op_translator/test_mcp_server.py`
- `docs/mcp.md`
- `docs/api.md` - பொது API மேற்பரப்பு மாற்றப்பட்டால்

சேமக்களஞ்சிய மொழிபெயர்ப்பு கருவிகள் MCP மூலம் மாடல்-அழைக்கக்கூடியவையாகும் மற்றும் பல கோப்புகளை எழுத முடியும். `dry_run=True` ஐ இயல்பாக வைத்திருங்கள் மற்றும் dry_run அல்லாத திட்ட மொழிபெயர்ப்புக்கு முன் `confirm_write=True` தேவைப்பட வேண்டும்.

## மொழிபெயர்ப்பு ஓட்டம்

மேல்நிலை திட்ட மொழிபெயர்ப்பு ஓட்டம்:

1. CLI வாதங்கள் அல்லது API பராமீட்டர்களை பகுப்பாய்வு செய்க.
2. `LLMConfig` உடன் LLM கட்டமைப்பைப் சரிபார்க்கவும்.
3. பட மொழிபெயர்ப்பு தேர்ந்தெடுக்கப்பட்டால் Azure AI Vision ஐ சரிபார்க்கவும்.
4. மொழி குறியீடுகளை சீரமைக்கவும்.
5. பழைய மொழி கோப்புறை மாற்றுப்பெயர்களை கண்டறியவும்.
6. மொழிபெயர்ப்பு அளவை மதிப்பிடவும்.
7. பொருந்துமானால் README மொழி/பாடத்திட்ட பகுதிகளை புதுப்பிக்கவும்.
8. திட்ட மொழிபெயர்ப்பை `ProjectTranslator` க்கு ஒப்படைக்கவும்.
9. `ProjectTranslator` கோப்பு செயலாக்கத்தை `TranslationManager` க்கு ஒப்படுக்கிறது.

`TranslationManager` குறிப்பிட்ட கோப்பு வகை மிக்சின்களால் அமைந்துள்ளது:

- `ProjectMarkdownTranslationMixin` Markdown கோப்புகளின் வாசிப்பு, உள்ளடக்க மொழிபெயர்ப்பு, பாதை மறுவழியாக எழுதுதல், மேட்டாடேட்டா, மறுப்புரைகள் மற்றும் எழுதுதல் ஆகியவற்றை கையாள்கிறது.
- `ProjectNotebookTranslationMixin` நோட்புக் கோப்பு வாசிப்புகள், Markdown-செல் மொழிபெயர்ப்பு, பாதை மறுவழி, மேட்டாடேட்டா, மறுப்புரைகள் மற்றும் எழுதுதல்கள் ஆகியவற்றை கையாள்கிறது.
- `ProjectImageTranslationMixin` படங்களைக் கண்டறிதல், உரை பிரித்தெடுதல்/மொழிபெயர்ப்பு, உருவாக்கப்பட்ட படங்களை எழுதுதல், மற்றும் மேட்டாடேட்டாவை கையாள்கிறது.

தாழ்நிலை உள்ளடக்க APIகள் திட்ட வேலைவழியைத் தவிர்க்கின்றன:

1. `translate_markdown_content` மற்றும் `translate_notebook_content` மெமரியில் உள்ள உள்ளடக்கத்தை மட்டுமே மொழிபெயர்க்கின்றன.
2. `translate_image_content` ஒரு ஒற்றை படத்தில் உள்ள உரையை மொழிபெயர்த்து ஒரு ரெண்டர் செய்யப்பட்ட படப் பொருளை திருப்பிக் கொடுக்கும்.
3. `rewrite_markdown_paths` மற்றும் `rewrite_notebook_paths` தற்செயலான பின்னர்-செயலாக்க உதவிகள். இவை எந்த மொழிபெயர்ப்பையும் மற்றும் எந்த திட்ட எழுத்தையும் செய்யாது.

## மீளாய்வு ஓட்டம்

முன்நிர்ணயமான மதிப்பீட்டு ஓட்டம்:

1. CLI வாதங்கள் அல்லது API பராமீட்டர்களை பகுப்பாய்வு செய்க.
2. கோரப்பட்ட மொழி குறியீடுகளை சீரமைக்கவும்.
3. `root_dir`, `root_dirs`, அல்லது `groups` இருந்து ஒன்று அல்லது அதற்கு மேற்பட்ட மதிப்பீட்டு இலக்குகளை உருவாக்கவும்.
4. விரும்பினால் `--changed-from` மூலம் மூலக் கோப்புகளை வரையறுக்கவும்.
5. கட்டமைப்பு, மொழிபெயர்ப்பு புதுமை, Markdown முழுமைத்தன்மை மற்றும் உள்ளூர் இணைப்பு/பட பாதைகளுக்கான தீர்மான அடிப்படையிலான சோதனைகளை இயக்கவும்.
6. உரை வெளியீடு அல்லது GitHub-பண்புடைய Markdown ஒன்றை அச்சிடவும்.
7. மதிப்பீட்டு பிழைகள் கண்டறியும் போது தோல்வியுடன் வெளியேறவும்.

மதிப்பீட்டு ஓட்டத்திற்கு API விசைகள் தேவையில்லை மற்றும் இது உள்ளூரில் சோதனை அல்லது விருப்பம் இணைக்கும் நுகர்வோர் CI க்காக கிடைப்பாக இருக்கும். இந்த நிரல்நிலையகம் ஒவ்வொரு pull request இலும் தானாக `co-op-review` ஐ இயக்காது.

## ஆவண தளம்

ஆவண தளம் கீழ்காணும் அமைப்புகளால் கட்டமைக்கப்பட்டுள்ளது:

```text
mkdocs.yml
requirements-docs.txt
docs/
```

`docs/` அடைவு அங்கீகரிக்கப்பட்ட ஆவண மூலமாகும். திட்டம் திட்டமிடாமல் மற்றொரு வெளியிடப்பட்ட ஆவண மேற்பரப்பை அறிமுகப்படுத்தவில்லை என்றால், இந்த அடைவின் வெளியே புதிய இறுதி-பயனர் வழிகாட்டிகளை சேர்க்க வேண்டாம்.

உள்ளூரில் கட்டவும்:

```bash
python -m pip install -r requirements-docs.txt
python -m mkdocs build --strict
```

உள்ளூரில் முன்னோட்டம்:

```bash
python -m mkdocs serve
```

உருவாக்கப்பட்ட தளம் `site/` எனும் இடத்திற்கு எழுதப்படுகிறது, இது git மூலம் புறக்கணிக்கப்படுகிறது.

## GitHub Pages ஓட்டம்

`.github/workflows/docs.yml` pull request-களில் தளத்தை கட்டுகிறது மற்றும் `main` கிளையில் push உறுப்பினரின் போது அதை deploy செய்கிறது.

வேலைநிரல் நிறுவுகிறது:

```bash
pip install -r requirements-docs.txt
```

ஆவண வேலைநிரல் ஆவண கருவிச்சட்டத்தை மட்டுமே நிறுவுகிறது. `mkdocs.yml` `mkdocstrings` ஐ `src/` நோக்கிச் சுட்டுகிறது என்பதால் பொது API பக்கங்களை முழு runtime சார்பு தொகுப்பை நிறுவாமல் ஆதார மரத்திலிருந்து (source tree) உருவாக்கக்கூடும். எதிர்காலத்தில் API ஆவணங்களுக்கு கட்டுப்பாட்டின் போது விருப்பமான runtime வழங்குநர்களை இறக்குமதி செய்ய தேவையாயின், `.github/workflows/docs.yml` மற்றும் இந்த வழிகாட்டியையும் ஒன்றாக புதுப்பிக்கவும்.

## ஆவணக் தரநிலை

ஆவண மாற்றங்களை இணைக்கும் முன்பு, இயக்கவும்:

```bash
python -m mkdocs build --strict
git diff --check
```

கடுமையான கட்டமைப்புகளைப் பயன்படுத்தவும்; அதனால் உடைந்த இணைப்புகள், செல்லாத வழிசெலுத்தல் நுழைவுகள் மற்றும் API உருவாக்க சிக்கல்கள் ஆரம்ப கட்டத்திலேயே தோல்வியாகும்.
