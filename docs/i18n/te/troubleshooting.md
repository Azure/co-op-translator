# సమస్య పరిష్కారం

ఈ పేజీని అనువాద రన్ అనూహ్యంగా విజయవంతమైతే, కాన్ఫిగరేషన్ సమయంలో విఫలమైతే, లేదా సమీక్ష అవసరమయ్యే అవుట్‌పుట్ ఉత్పత్తి జరిగినప్పుడు ఉపయోగించండి.

## ఇక్కడ ప్రారంభించండి

1. మొదట ఒక ప్రత్యేక కమాండ్ నడపండి, ఉదాహరణకు `translate -l "ko" -md`.
2. కన్సోల్ డీబగ్ లాగ్ల కోసం `-d`ని చేర్చండి.
3. డీబగ్ లాగ్లను `<root-dir>/logs/`లో సేవ్ చేయాలంటే `-s`ని జత చేయండి.
4. అనువాదం తర్వాత తాజాదనం, నిర్మాణం, మరియు స్థానిక లింకులను తనిఖీ చేయడానికి `co-op-review` ను నడపండి.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## కాన్ఫిగరేషన్ లోపాలు

### భాషా మోడల్ ప్రొవైడర్ yoxdur

లోపం:

```text
No language model configuration found.
```

పరిష్కారం:

- Azure OpenAI, OpenAI లేదా Anthropic ను కాన్ఫిగర్ చేయండి.
- కమాండ్ నడుచుకునే ఎన్విరాన్‌మెంట్‌లో వేరియబుల్స్ ఉన్నాయేనని నిర్ధారించండి.
- లోకల్ ఉపయోగానికి, ప్రాజెక్ట్ రూట్‌లోని `.env`లో వాటిని పెట్టండి.

చూడండి [Configuration](configuration.md).

### Azure AI Vision లేకుండా ఇమేజ్ అనువాదం

లోపం:

```text
Image translation requested but Azure AI Service is not configured.
```

పరిష్కారం:

- `AZURE_AI_SERVICE_API_KEY` జోడించండి.
- `AZURE_AI_SERVICE_ENDPOINT` జోడించండి.
- లేదా `translate -l "ko" -md` వంటి టెక్స్ట్-మాత్రమైన కమాండ్ నడపండి.

### చెల్లని కీ లేదా ఎండ్పాయింట్

లక్షణాలు `401`, అనుమతి సంబంధిత లోపాలు, లేదా ఎండ్పాయింట్ యాక్సెస్ లోపాలను కలిగి ఉండవచ్చు.

పరిష్కారం:

- కీ ఎండ్పాయింట్ ఉన్న అదే Azure రిసోర్సుకే చెందుతోందా అనేది నిర్ధారించండి.
- `-img` ఉపయోగించే సమయంలో రిసోర్సు Vision ను మద్దతిస్తున్నదని నిర్ధారించండి.
- Azure OpenAI డిప్లాయ్‌మెంట్ పేరు మరియు API వెర్షన్ మీ డిప్లాయ్‌మెంట్‌కు సరిపోతాయో నిర్ధారించండి.
- డీబగ్ లాగ్స్‌తో నడపండి: `translate -l "ko" -md -d -s`.

## ఏ ఫైళ్లు అనువదించబడలేదు

సాధారణ కారణాలు:

- ఎంపిక చేసిన ఫ్లాగ్‌లు మీ ఫైళ్లకు సరిపోదు.
- ఇప్పటికే అనువదించిన ఫైళ్లు ఉండవచ్చు.
- మూల ఫైళ్ళు బహిష్కృత డైరెక్టరీలలో ఉన్నాయి.
- కమాండ్ తప్పు ప్రాజెక్ట్ రూట్ నుండి నడుస్తోంది.

తనిఖీలు:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

కమాండ్ ప్రాజెక్ట్ రూట్ వెలుపల నడుస్తున్నప్పుడు `--root-dir` ఉపయోగించండి.

## అనూహ్య లింక్ ప్రవర్తన

లింక్ తిరిగి రాయడం ఎంపిక చేసిన కంటెంట్ రకాలపై ఆధారపడి ఉంటుంది:

- `-nb` చేర్చబడిన: నోట్‌బుక్ లింకులు అనువదించిన నోట్‌బుక్స్‌కి సూచించవచ్చు.
- `-nb` బహిష్కృత: నోట్‌బుక్ లింకులు మూల నోట్‌బుక్స్‌ను సూచించనే ఉండవచ్చు.
- `-img` చేర్చబడిన: ఇమేజ్ లింకులు అనువదించిన చిత్రాలను చూపించవచ్చు.
- `-img` బహిష్కృత: ఇమేజ్ లింకులు మూల చిత్రాలకే సూచించనే ఉండవచ్చు.

అంతర్గత అన్ని లింకులు అనువదించిన అవుట్‌పుట్‌ను ప్రాధాన్యంగా ఉపయోగించాలనుకుంటే పూర్తి కంటెంట్ అనువాదం నడపండి:

```bash
translate -l "ko" -md -nb -img
```

అనువాదం తర్వాత లింక్ సమీక్ష నిర్వహించండి:

```bash
co-op-review -l "ko"
```

## మార్క్‌డౌన్ రెండరింగ్ సమస్యలు

అనువదించిన Markdown తప్పుగా రెండర్ అయితే:

- frontmatter `---`తో ప్రారంభమై `---`తో ముగుస్తుందో తనిఖీ చేయండి.
- కోడ్ ఫెన్స్ లెక్కలు మూల మరియు అనువదించిన ఫైళ్లలో ఒకేలా ఉన్నాయా టెస్టు చేయండి.
- సామాన్య నిర్మాణ సమస్యలను పట్టుకోవడానికి `co-op-review` ని నడపండి.
- అవుట్‌పుట్ దెబ్బతిన్నట్లయితే నిర్దిష్ట ఫైల్‌ను మళ్లీ అనువదించండి.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action నడిచింది కానీ పుల్ రిక్వెస్ట్ సృష్టించబడలేదు

`peter-evans/create-pull-request` బ్రాంచ్ బేస్‌కి ముందు లేదని నివేదిస్తే, వర్క్‌ఫ్లో కమిట్ చేయడానికి ఎలాంటి ఫైళ్ళను కనుగొనలేదు.

సాధ్యమైన కారణాలు:

- అనువాద రన్ నుండి ఎలాంటి మార్పులు రాలేదు.
- `.gitignore` `translations/`, `translated_images/`, లేదా అనువదించిన నోట్‌బుక్స్‌ను బహిష్కరిస్తుంది.
- `add-paths` రూపొందించిన అవుట్పుట్ డైరెక్టరీలకు సరిపోలడం లేదు.
- అనువాద దశ ముందుగానే ముగిసింది.

పరిష్కారాలు:

1. రూపొందించిన ఫైళ్లు `translations/` లేదా `translated_images/` లో ఉన్నాయో నిర్ధారించండి.
2. `.gitignore` రూపొందించిన అవుట్పుట్‌లను నిర్లక్ష్యం చేయడం లేదో నిర్ధారించండి.
3. సరిపడే `add-paths` ఉపయోగించండి:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. తాత్కాలికంగా అనువాద కమాండ్‌కు డీబగ్ ఫ్లాగ్‌లను జోడించండి:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. వర్క్‌ఫ్లో అనుమతులు క్రింది విధంగా ఉన్నాయో నిర్ధారించండి:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## అనువాద నాణ్యత

మెషీన్ అనువాదాలకు మానవ సమీక్ష అవసరం ఉండవచ్చు. ప్రయోగాత్మక నాణ్యత స్కోరింగ్ మరియు తక్కువ-నమ్మకమైన రిపేర్ వర్క్‌ఫ్లో కోసం మాత్రమే `evaluate` ఉపయోగించండి.

!!! warning "ప్రయోగాత్మక"
    `evaluate` నియమాల-ఆధారిత మరియు LLM-ఆధారిత తనిఖీలను ఉపయోగించగలదు, మరియు దాని స్కోరింగ్ మోడల్ మరియు మెటాడేటా ప్రవర్తన మారవచ్చు. మీ వర్క్‌ఫ్లో మార్పులకు సిద్ధంగా లేకపోతే దీన్ని అవసరమైన CI గేట్లలోకి ఉంచరాదు.

నిర్ధారిత CI తనిఖీల కోసం బదులుగా `co-op-review` ఉపయోగించండి.
