# แปล แก้ไข และตรวจทานโครงการขนาดเล็ก

เริ่มด้วยไฟล์ Markdown สั้น ๆ สองไฟล์และภาษาปลายทางหนึ่งภาษา คุณจะเห็นที่ที่การแปลถูกเขียน สิ่งที่จะเกิดขึ้นเมื่อแหล่งที่มาเปลี่ยนแปลง และวิธีตรวจสอบผลลัพธ์

## ผลลัพธ์ที่บันทึกไว้

ตัวอย่างนี้ถูกรันเมื่อวันที่ 19 กันยายน 2026 ด้วย Co-op Translator 0.21.0 และ Azure OpenAI (`gpt-5-mini`) คำสั่ง CLI ที่ไม่ได้แก้ไขถูกเรียกผ่าน Click's `CliRunner` โดยใช้ wheel ที่สร้างขึ้นและการพึ่งพา Python ที่มีอยู่แล้ว.

| ขั้นตอน | ผลลัพธ์ |
| --- | --- |
| พรีวิว | Exit 0; ไม่มีการร้องขอการแปลจากโมเดล |
| การแปลเริ่มต้น | Exit 0; 27.36 วินาที |
| การตรวจทานเริ่มต้น | Exit 0 |
| แก้ไข README และตรวจทาน | Exit 1; พบการแปลที่ล้าสมัย |
| อัปเดตการแปล | Exit 0; 22.17 วินาที |
| ตรวจทานหลังการอัปเดต | Exit 0; ไม่มีข้อผิดพลาดหรือคำเตือน |
| ไกด์ที่ไม่เปลี่ยนแปลง | ไบต์เหมือนกันก่อนและหลังการอัปเดต README |
| รันอีกครั้ง | Exit 0; แฮชเหมือนกันสำหรับไฟล์การแปลทั้งหมด |

ข้อมูลเหล่านี้เป็นการวัดจากการรันแต่ละครั้ง ไม่ใช่การรับประกันประสิทธิภาพ เวลาการตั้งค่าไม่ถูกนับอยู่; การเรียกเก็บค่าบริการผู้ให้บริการไม่ได้ถูกวัด การรันที่ไม่เปลี่ยนแปลงก็ยังสามารถทำการตรวจสุขภาพของผู้ให้บริการได้

ตรวจสอบ [การแปลเริ่มต้น](../../assets/demo/before.txt), [การแปลที่อัปเดต](../../assets/demo/after.txt), [diff การแปลทั้งหมด](../../assets/demo/update.diff), [การตรวจทานที่ล้าสมัย](../../assets/demo/review-stale.txt), [การตรวจทานขั้นสุดท้าย](../../assets/demo/review-after.txt), และ [รายละเอียดการรัน](../../assets/demo/results.json). การแปลทั้งไฟล์อาจเปลี่ยนถ้อยคำอื่น ๆ ตามที่ diff ที่จับได้แสดง ทั้งสองชิ้นงานข้อความยังคงคำปฏิเสธที่สร้างขึ้นไว้

การตรวจทานโดยมนุษย์ยังสำคัญ: การอัปเดตที่จับได้ใช้ `[사용 가이드](guide.md)을`; ควรจะเป็น `[사용 가이드](guide.md)를`. ผลงานข้อความยังคงผลลัพธ์นี้ไว้โดยไม่แก้ไขแล้วนำเสนอเป็นผลลัพธ์ของโมเดล การตรวจทานเชิงโครงสร้างผ่านแม้จะมีปัญหาด้านถ้อยคำนี้

## 1. เตรียมโฟลเดอร์ขนาดเล็ก

ใช้ Python 3.11–3.14 และ [การตั้งค่าสภาพแวดล้อมเสมือน](configuration.md#local-runtime-setup). ติดตั้งเวอร์ชันที่ใช้ในตัวอย่างนี้:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

ดาวน์โหลด [README.txt](../../assets/demo/README.txt) และ [guide.txt](../../assets/demo/guide.txt) ลงในโฟลเดอร์นี้ แล้วบันทึกเป็น `README.md` และ `guide.md` เอกสารโครงการสมมติเหล่านี้มีขนาดเล็ก; ไม่จำเป็นต้องติดตั้งแอปพลิเคชัน

README ประกอบด้วยบล็อกโค้ดและลิงก์ไปยัง `guide.md` ประโยคสุดท้ายคือ:

```text
Notes are saved locally.
```

เก็บเฉพาะเอกสารต้นทางสองฉบับนี้ไว้ในโฟลเดอร์นี้ คำสั่งทั้งหมดต่อไปนี้ทำงานภายใน `translation-demo` และใช้งานได้ทั้งใน Bash และ PowerShell

## 2. พรีวิวโดยไม่ใช้ข้อมูลรับรอง

```bash
translate -l "ko" -md --dry-run
```

พรีวิวประมาณการงานแปลโดยไม่เรียกใช้โมเดลหรือเขียนการแปล การประมาณโทเค็นไม่ใช่ใบเสนอราคาการคิดค่าบริการ การรันครั้งแรกควรระบุว่าไฟล์ Markdown ทั้งสองเป็นงานใหม่

## 3. เลือกผู้ให้บริการและแปล

กำหนดค่าผู้ให้บริการหนึ่งรายโดยใช้ [คำแนะนำการกำหนดค่า](configuration.md): Azure OpenAI, OpenAI, หรือ Anthropic การแปลข้อความของ OpenAI และ Anthropic ไม่ต้องการบัญชี Azure บริการภาพไม่จำเป็นสำหรับตัวอย่างนี้

หากคุณใช้ไฟล์ `.env` ในเครื่อง ให้เพิ่ม `.env` ลงใน `.gitignore` ของโฟลเดอร์นี้ การเรียกแปลใช้บัญชีผู้ให้บริการของคุณและอาจมีค่าใช้จ่าย

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

เปิด `translations/ko/README.md` และ `translations/ko/guide.md` ตรวจสอบถ้อยคำเกาหลี บล็อกโค้ด และลิงก์จาก README ที่แปลไปยังไกด์ที่แปล ถ้อยคำเอาต์พุตจะแตกต่างกันตามโมเดล

`co-op-review` ตรวจสอบความสดใหม่ โครงสร้าง และลิงก์ภายในเครื่อง ผลลัพธ์ที่ผ่านไม่ได้รับรองความถูกต้องทางภาษาศาสตร์ แก้ไขข้อผิดพลาดที่รายงานก่อนดำเนินการต่อ

บันทึก baseline ที่สำเร็จด้วย Git (กำหนดค่าตัวตน Git ของคุณก่อนถ้าจำเป็น):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. เปลี่ยนแหล่งที่มา

ใน `README.md` ให้แทนที่ `Notes are saved locally.` ด้วย:

```text
Notes are saved locally as Markdown files.
```

ปล่อยให้ `guide.md` ไม่เปลี่ยนแปลง แล้วรัน:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

การตรวจทานควรรายงานว่าการแปล README ล้าสมัยและออกสถานะไม่สำเร็จ นี่คือสถานะระหว่างกลางที่คาดหวัง พรีวิวควรระบุงานสำหรับ README ที่ถูกเปลี่ยนแปลง

## 5. อัปเดตและตรวจสอบ diff

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

ตรวจสอบ diff จริง: CLI เริ่มต้นจะแปลไฟล์ที่เปลี่ยนใหม่อีกครั้ง ดังนั้นโมเดลอาจแก้ไขถ้อยคำอื่น ๆ ในไฟล์นั้นด้วย ไกด์ที่ไม่เปลี่ยนแปลงไม่ควรมี diff การตรวจทานไม่ควรรายงานว่า README ล้าสมัยอีกต่อไป; ให้ตรวจสอบผลอื่น ๆ แทนที่จะเพิกเฉย

การรักษาบล็อกระดับบล็อกของการแก้ไข Markdown โดยมนุษย์ต้องการผู้ให้บริการสถานะการแปลที่เป็นทางเลือกใน [Python API](api.md) ซึ่งไม่ได้เปิดใช้งานโดยคำสั่ง CLI เหล่านี้

## 6. รันอีกครั้งโดยไม่เปลี่ยนแปลง

commit แหล่งที่มาและการแปลที่อัปเดต:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

ด้วยการแปลปัจจุบันและการกำหนดค่าที่ไม่เปลี่ยนแปลง ตัวแปลจะข้ามไฟล์ คำสั่ง Git สุดท้ายควรไม่สร้าง diff และออกสถานะสำเร็จ
