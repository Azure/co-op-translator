# การมีส่วนร่วมในการปรับปรุงภาษา

ความรู้ด้านภาษาของคุณสามารถช่วยปรับปรุง Co-op Translator เริ่มด้วยตัวอย่าง การแก้ไขที่แนะนำ และคำอธิบายโดยใช้ [แบบฟอร์มความคิดเห็นการแปล](https://github.com/Azure/co-op-translator/issues/new?template=translation_feedback.yml). คุณไม่จำเป็นต้องเขียนโค้ดหรือจ่ายค่าใช้งานโมเดล

## จากรายงานสู่การปรับปรุงร่วมกัน

1. ผู้ร่วมเสนอส่งข้อความต้นฉบับ ชิ้นส่วนการแปล และบริบท
2. ผู้ตรวจภาษาตรวจสอบความหมาย ความเป็นธรรมชาติ และว่าข้อเสนอขึ้นอยู่กับท้องถิ่นหรือหลักสูตรใดโดยเฉพาะหรือไม่
3. ผู้ดูแลตัดสินใจว่าการแก้ไขควรอยู่ในหลักสูตรต้นทาง คำสั่งภาษาแบบใช้ร่วมกัน การตั้งค่าศัพท์เฉพาะ หรือโค้ดการแปล
4. สำหรับกฎที่ใช้ร่วมกัน ผู้ดูแลเปรียบเทียบผลลัพธ์ก่อนและหลังการเปลี่ยนแปลงในตัวอย่างที่ถูกรายงานและตัวอย่างที่ไม่เกี่ยวข้อง ผู้ร่วมสามารถทบทวนผลลัพธ์เหล่านี้ได้โดยไม่ต้องรันเครื่องมือด้วยตัวเอง
5. PR ที่ได้จะเชื่อมโยงกับรายงานและให้เครดิตคนที่ให้ตัวอย่างและการตรวจทาน การปรับใช้หรือการสร้างใหม่ในที่เก็บที่ใช้งานเป็นขั้นตอนแยกต่างหาก

รายงานจะไม่เปลี่ยนพรอมต์โดยอัตโนมัติหรือสร้างการแปลของหลักสูตรใหม่ การแก้ไขที่เฉพาะกับหลักสูตรควรยังคงเชื่อมโยงกับที่เก็บหลักสูตร อย่าสมมติว่าการแก้ไขด้วยมือจะคงอยู่เมื่อมีการแปลใหม่ในภายหลัง; ยืนยันพฤติกรรมสำหรับเวิร์กโฟลว์นั้น

## ตัวอย่างที่มีอยู่: ลิงก์ Markdown ภาษาญี่ปุ่น

[ไฟล์คำแนะนำภาษาญี่ปุ่น](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/templates/language/ja.md) แจ้งให้โมเดลแปลข้อความลิงก์โดยรักษาไวยากรณ์ Markdown และจุดหมายของลิงก์ไว้ ตัวอย่างเช่น ลิงก์ที่เขียนเป็น `[text](URL)` ต้องไม่กลายเป็น `「text」（URL）`

นี่คือตัวอย่างเฉพาะด้านของกฎภาษา ซึ่งสนับสนุนด้วยภาพประกอบของผลลัพธ์ที่ถูกและผิด มันไม่ใช่หลักฐานว่าคำสั่งพรอมต์เพียงอย่างเดียวจะรับประกัน Markdown ที่ถูกต้อง

[ตัวสร้างพรอมต์ Markdown](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/utils/markdown/prompts.py) โหลด `templates/language/<language_code>.md` โดยใช้รหัสภาษาที่เป็นตัวพิมพ์เล็กและตัดช่องว่าง หากไม่มีไฟล์ จะใช้คำแนะนำทั่วไป นี่อธิบายเส้นทางพรอมต์ Markdown; อย่าสมมติว่าทุกภาพหรือเส้นทางการแปลอื่นจะใช้คำแนะนำเดียวกัน

[การทดสอบพรอมต์](https://github.com/Azure/co-op-translator/blob/main/tests/co_op_translator/utils/markdown/test_prompts.py) ตรวจสอบว่าคำแนะนำภาษาญี่ปุ่นถูกรวมอยู่ นั่นยืนยันการประกอบพรอมต์ ไม่ใช่คุณภาพการแปล

## อะไรควรอยู่ในกฎภาษา?

เสนอกฎการแก้ไขที่เจาะจงและทำซ้ำได้ พร้อมตัวอย่างต้นฉบับ พฤติกรรมที่คาดหวัง และตัวอย่างที่ขัดแย้งที่กฎต้องไม่ใช้ รักษาความหมาย ตัวแทนตำแหน่ง โค้ด URL และโครงสร้างเอกสารไว้ หลีกเลี่ยงการเปลี่ยนความชอบสไตล์ของบุคคลหนึ่งหรือศัพท์เฉพาะของหลักสูตรหนึ่งให้เป็นกฎสากล

[การใช้งานพจนานุกรมคำศัพท์](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/glossary.py) ปัจจุบันปกป้องคำศัพท์จากการแปล มันไม่ใช่พจนานุกรมคำศัพท์จากต้นทางถึงเป้าหมาย โปรดหารือพฤติกรรมศัพท์ใหม่ก่อนสัญญากับผู้ร่วม

## ตัวอย่างจากชุมชน: รายงานชื่อผลิตภัณฑ์ภาษาญี่ปุ่น

ใน [รายงาน #527](https://github.com/Azure/co-op-translator/issues/527), @hyoshioka0128 ระบุการแปลภาษาญี่ปุ่นที่เปลี่ยนชื่อผลิตภัณฑ์ `Co-op Translator` เป็น `Co-op 翻訳` รายงานรวมลิงก์ไปยังเอกสารที่ได้รับผลกระทบและสกรีนช็อต ทำให้ปัญหาเป็นเรื่องง่ายที่จะค้นหา

ผู้ร่วมยังเชื่อมลิงก์ไปยัง [PR หลักสูตรที่เกี่ยวข้อง](https://github.com/microsoft/AZD-for-beginners/pull/109) ในการอภิปรายประเด็น ผู้ดูแลรับทราบรายงานและเสนอให้ตรวจสอบสาเหตุที่ชื่อเปลี่ยน รวมถึงการปกป้องศัพท์ พฤติกรรมพจนานุกรมคำศัพท์ และเส้นทางการแปล

สิ่งนี้แสดงให้เห็นว่า รายงานเล็กๆ สามารถสนับสนุนการสอบสวนที่กว้างกว่าการแก้ไขคำแต่ละคำ มันไม่ใช่ผลก่อน/หลังที่ยืนยันแล้วหรือหลักฐานว่าคำแนะนำลิงก์ Markdown ภาษาญี่ปุ่นด้านบนแก้ปัญหาชื่อผลิตภัณฑ์นี้ได้

คุณสามารถมีส่วนร่วมในลักษณะเดียวกัน: แชร์ข้อความต้นฉบับ การแปลปัจจุบัน การแก้ไขที่แนะนำ และเหตุผลว่าทำไมมันสำคัญ เพิ่มลิงก์เอกสารหรือสกรีนช็อตเมื่อจำเป็น คุณไม่จำเป็นต้องวินิจฉัยสาเหตุหรือเขียนพรอมต์ก่อนรายงาน

## การตรวจสอบก่อนยอมรับกฎ

ใช้ตัวอย่างต้นฉบับเดียวกัน การแก้ไขโดยผู้แปล ผู้ให้บริการ/โมเดล และการตั้งค่าการสร้างเดียวกันสำหรับการรันฐานและผู้สมัคร โดยเปลี่ยนเพียงคำสั่งที่เสนอ บันทึกการเปลี่ยนพรอมต์จริงและผลลัพธ์; ทำซ้ำตัวอย่างเมื่อจำเป็นเพื่อแยกความแตกต่างระหว่างผลกระทบที่สม่ำเสมอกับความแปรปรวนของผลลัพธ์ รวมทั้งความล้มเหลวที่ถูกรายงาน บริบทที่แตกต่าง และตัวอย่างที่แปลได้ถูกต้องอยู่แล้ว

| ตัวอย่าง | แหล่งที่มา/บริบท | ผลลัพธ์ฐาน | ผลลัพธ์ผู้สมัคร | การประเมินโดยผู้ตรวจ |
| --- | --- | --- | --- | --- |
| ความล้มเหลวที่ถูกรายงาน | กำลังรวบรวม | ยังไม่ได้รัน | ยังไม่ได้รัน | รอดำเนินการ |
| ตัวอย่างที่ขัดแย้ง | กำลังรวบรวม | ยังไม่ได้รัน | ยังไม่ได้รัน | รอดำเนินการ |
| ตัวอย่างที่ไม่เกี่ยวข้อง | กำลังรวบรวม | ยังไม่ได้รัน | ยังไม่ได้รัน | รอดำเนินการ |

ตรวจสอบความคงที่เชิงโครงสร้างแยกจากการตัดสินเชิงภาษา การทดสอบการโหลดพรอมต์ที่ผ่านไม่ใช่การประเมินคุณภาพ และประโยคที่คาดหวังเพียงประโยคเดียวไม่ได้เป็นการแปลที่ถูกต้องเพียงอย่างเดียว หากขาดบริบท การรันโมเดล หรือการตรวจทานภาษา ให้เก็บข้อเสนอไว้ในสถานะรอดำเนินการ แทนที่จะอ้างว่าปัญหาได้รับการแก้ไข
