# การแก้ปัญหา

ใช้หน้านี้เมื่อการรันการแปลสำเร็จโดยไม่คาดคิด, ล้มเหลวระหว่างการกำหนดค่า หรือสร้างเอาต์พุตที่ต้องมีการตรวจทาน.

## เริ่มที่นี่

1. รันคำสั่งที่เจาะจงก่อน เช่น `translate -l "ko" -md`.
2. เพิ่ม `-d` สำหรับบันทึกดีบักในคอนโซล.
3. เพิ่ม `-s` เพื่อบันทึกบันทึกดีบักไว้ที่ `<root-dir>/logs/`.
4. รัน `co-op-review` หลังการแปลเพื่อตรวจสอบความสดใหม่ โครงสร้าง และลิงก์ภายในเครื่อง.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## ข้อผิดพลาดในการกำหนดค่า

### ไม่มีผู้ให้บริการโมเดลภาษา

ข้อผิดพลาด:

```text
No language model configuration found.
```

การแก้ไข:

- กำหนดค่า Azure OpenAI, OpenAI, หรือ Anthropic.
- ตรวจสอบว่าตัวแปรอยู่ในสภาพแวดล้อมที่คำสั่งทำงานอยู่.
- สำหรับการใช้งานในเครื่อง ให้ใส่ไว้ใน `.env` ที่รูตของโปรเจกต์.

ดู [การกำหนดค่า](configuration.md).

### การแปลรูปภาพโดยไม่มี Azure AI Vision

ข้อผิดพลาด:

```text
Image translation requested but Azure AI Service is not configured.
```

การแก้ไข:

- เพิ่ม `AZURE_AI_SERVICE_API_KEY`.
- เพิ่ม `AZURE_AI_SERVICE_ENDPOINT`.
- หรือรันคำสั่งเฉพาะข้อความ เช่น `translate -l "ko" -md`.

### คีย์หรือเอนด์พอยต์ไม่ถูกต้อง

อาการอาจรวมถึง `401`, ข้อผิดพลาดสิทธิ์ที่ถูกปิดบัง หรือข้อผิดพลาดการเข้าถึงเอนด์พอยต์.

การแก้ไข:

- ยืนยันว่าคีย์เป็นของทรัพยากร Azure เดียวกับเอนด์พอยต์
- ยืนยันว่าทรัพยากรรองรับ Vision เมื่อใช้ `-img`.
- ยืนยันว่าชื่อการปรับใช้ Azure OpenAI และเวอร์ชัน API ตรงกับการปรับใช้ของคุณ.
- รันพร้อมบันทึกดีบัก: `translate -l "ko" -md -d -s`.

## ไม่มีไฟล์ใดถูกแปล

สาเหตุทั่วไป:

- ตัวเลือกที่ระบุไม่ตรงกับไฟล์ของคุณ.
- มีไฟล์ที่แปลแล้วอยู่แล้ว.
- ไฟล์ต้นทางอยู่ภายใต้ไดเรกทอรีที่ถูกยกเว้น.
- คำสั่งกำลังรันจากรูตของโปรเจกต์ที่ไม่ถูกต้อง.

การตรวจสอบ:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

ใช้ `--root-dir` เมื่อคำสั่งถูกรันนอกรูตของโปรเจกต์.

## พฤติกรรมลิงก์ที่ไม่คาดคิด

การเขียนทับลิงก์ขึ้นอยู่กับประเภทเนื้อหาที่เลือก:

- `-nb` ถูกรวม: ลิงก์สมุดบันทึก (notebook) อาจชี้ไปยังสมุดบันทึกที่แปลแล้ว.
- `-nb` ถูกยกเว้น: ลิงก์สมุดบันทึกอาจยังคงชี้ไปยังสมุดบันทึกต้นฉบับ.
- `-img` ถูกรวม: ลิงก์รูปภาพอาจชี้ไปยังรูปภาพที่แปลแล้ว.
- `-img` ถูกยกเว้น: ลิงก์รูปภาพอาจยังคงชี้ไปยังรูปภาพต้นฉบับ.

เรียกใช้การแปลเนื้อหาแบบเต็มเมื่อคุณต้องการให้ลิงก์ภายในทั้งหมดชี้ไปยังผลลัพธ์ที่แปลแล้ว:

```bash
translate -l "ko" -md -nb -img
```

รันการตรวจสอบลิงก์หลังการแปล:

```bash
co-op-review -l "ko"
```

## ปัญหาการเรนเดอร์ Markdown

หาก Markdown ที่แปลแล้วเรนเดอร์ไม่ถูกต้อง:

- ตรวจสอบว่า frontmatter เริ่มต้นและสิ้นสุดด้วย `---`.
- ตรวจสอบว่าจำนวนรั้วโค้ด (code fence) ตรงกันระหว่างไฟล์ต้นทางและไฟล์ที่แปลแล้ว.
- รัน `co-op-review` เพื่อตรวจจับปัญหาโครงสร้างทั่วไป.
- แปลไฟล์นั้นซ้ำหากเอาต์พุตถูกทำให้เสียหาย.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action ถูกเรียกใช้งาน แต่ไม่มีการสร้าง Pull Request

หาก `peter-evans/create-pull-request` รายงานว่าสาขาไม่อยู่หน้า base แสดงว่าเวิร์กโฟลว์ไม่พบไฟล์ที่จะคอมมิต.

สาเหตุที่เป็นไปได้:

- การรันการแปลไม่สร้างการเปลี่ยนแปลงใดๆ.
- `.gitignore` ยกเว้น `translations/`, `translated_images/` หรือสมุดบันทึกที่แปลแล้ว.
- `add-paths` ไม่ตรงกับไดเรกทอรีเอาต์พุตที่สร้างขึ้น.
- ขั้นตอนการแปลออกก่อนกำหนด.

การแก้ไข:

1. ยืนยันว่าไฟล์ที่สร้างมีอยู่ใน `translations/` หรือ `translated_images/`.
2. ยืนยันว่า `.gitignore` ไม่ได้ละเว้นเอาต์พุตที่สร้างขึ้น.
3. ใช้ `add-paths` ที่ตรงกัน:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. เพิ่มแฟล็กดีบักชั่วคราวไปยังคำสั่ง translate:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. ยืนยันว่าสิทธิ์ของเวิร์กโฟลว์รวมถึง:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## คุณภาพการแปล

การแปลด้วยเครื่องอาจต้องการการตรวจทานโดยมนุษย์ ใช้ `evaluate` เฉพาะเมื่อคุณต้องการการให้คะแนนคุณภาพเชิงทดลองและเวิร์กโฟลว์ซ่อมแซมเมื่อมีความเชื่อมั่นต่ำ.

!!! warning "Experimental"
    `evaluate` สามารถใช้การตรวจสอบแบบกฎและแบบ LLM และแบบจำลองการให้คะแนนรวมถึงพฤติกรรมเมตาดาต้าอาจมีการเปลี่ยนแปลง. อย่าใส่ไว้ในเกต CI ที่ต้องผ่าน เว้นแต่เวิร์กโฟลว์ของคุณเตรียมพร้อมสำหรับการเปลี่ยนแปลง.

สำหรับการเช็ก CI ที่ต้องการความแน่นอน ให้ใช้ `co-op-review` แทน.
