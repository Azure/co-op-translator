# Перекласти, відредагувати та переглянути невеликий проект

Почніть з двох коротких Markdown-файлів і однієї цільової мови. Ви побачите, куди записуються переклади, що відбувається при зміні джерела та як перевірити результат.

## Зареєстровані результати

Приклад був виконаний 19 вересня 2026 року з Co-op Translator 0.21.0 та Azure OpenAI (`gpt-5-mini`). Незмінені CLI-команди були викликані через Click's `CliRunner`, використовуючи зібраний wheel та наявні залежності Python.

| Крок | Результат |
| --- | --- |
| Попередній перегляд | Вихід 0; не було запиту перекладу моделі |
| Початковий переклад | Вихід 0; 27.36 секунд |
| Початковий огляд | Вихід 0 |
| Змінити README і переглянути | Вихід 1; виявлено застарілий переклад |
| Оновити переклад | Вихід 0; 22.17 секунд |
| Перегляд після оновлення | Вихід 0; без помилок або попереджень |
| Незмінений посібник | Байти ідентичні до і після оновлення README |
| Запустити знову | Вихід 0; однакові хеші для всіх файлів перекладу |

Це індивідуальні вимірювання запусків, не гарантії продуктивності. Час налаштування не включено; оплата провайдера не вимірювалася. Навіть незмінений прогін може виконати перевірку працездатності провайдера.

Перегляньте [початковий переклад](../../assets/demo/before.txt), [оновлений переклад](../../assets/demo/after.txt), [повний diff перекладу](../../assets/demo/update.diff), [застарілий огляд](../../assets/demo/review-stale.txt), [кінцевий огляд](../../assets/demo/review-after.txt), і [деталі запуску](../../assets/demo/results.json). Повний переклад файлу може змінити інші формулювання, як показує зафіксований diff. Обидва текстові артефакти зберігають згенероване застереження.

Огляд людиною все ще важливий: захоплене оновлення використовує `[사용 가이드](guide.md)을`; корейська частка має бути `[사용 가이드](guide.md)를`. Текстові артефакти зберігають цей вивід без змін замість подання відредагованого перекладу як вивід моделі. Структурний огляд пройшов незважаючи на цю проблему з формулюванням.

## 1. Підготуйте невелику папку

Використовуйте Python 3.11–3.14 та [налаштування віртуального середовища](configuration.md#local-runtime-setup). Встановіть версію, використану в цьому прикладі:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

Завантажте [README.txt](../../assets/demo/README.txt) та [guide.txt](../../assets/demo/guide.txt) у цю папку, зберігши їх як `README.md` та `guide.md`. Це невеликі вигадані документи про проєкт; встановлення застосунку не потрібне.

README містить блок коду та посилання на `guide.md`. Його останнє речення:

```text
Notes are saved locally.
```

Залиште в цій папці лише ці два вихідні документи. Усі подальші команди виконуються всередині `translation-demo` і працюють у Bash та PowerShell.

## 2. Попередній перегляд без облікових даних

```bash
translate -l "ko" -md --dry-run
```

Попередній перегляд оцінює обсяг роботи з перекладу без звернення до моделі або запису перекладів. Оцінки токенів не є квотою для виставлення рахунків. Перший прогін має визначити обидва Markdown-файли як нову роботу.

## 3. Виберіть провайдера та перекладіть

Налаштуйте одного провайдера, використовуючи [керівництво з конфігурації](configuration.md): Azure OpenAI, OpenAI або Anthropic. Текстовий переклад через OpenAI та Anthropic не потребує облікового запису Azure. Служби для зображень не потрібні для цього прикладу.

Якщо ви використовуєте локальний файл `.env`, додайте `.env` до `.gitignore` цієї папки. Виклики перекладу використовують ваш обліковий запис провайдера і можуть спричиняти витрати.

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

Відкрийте `translations/ko/README.md` та `translations/ko/guide.md`. Перевірте корейські формулювання, блок коду та посилання з перекладеного README на перекладений guide. Формулювання виводу варіюється залежно від моделі.

`co-op-review` перевіряє свіжість, структуру та локальні посилання. Прохідний результат не підтверджує лінгвістичну точність. Виправте будь-які виявлені помилки перед продовженням.

Зафіксуйте успішну базову версію в Git (за потреби спочатку налаштуйте свою ідентичність Git):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. Змініть джерело

У `README.md` замініть `Notes are saved locally.` на:

```text
Notes are saved locally as Markdown files.
```

Залиште `guide.md` без змін. Потім виконайте:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

Огляд повинен повідомити, що переклад README застарів, і завершитися з помилкою. Це очікуваний проміжний стан. Попередній перегляд має визначити роботу для зміненого README.

## 5. Оновіть та перегляньте diff

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

Перегляньте реальний diff: стандартний CLI повторно перекладає змінений файл, тож модель також може переглянути інші формулювання в цьому файлі. Незмінений guide не повинен мати diff. Огляд більше не має повідомляти, що README застарів; дослідіть будь-які інші виявлення замість того, щоб ігнорувати їх.

Збереження змін у Markdown на рівні блоків вимагає необов'язкового провайдера стану перекладу в [Python API](api.md). Він не ввімкнений цими CLI-командами.

## 6. Запустіть знову без змін

Зафіксуйте оновлене джерело та переклад:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

При наявних перекладах і незмінній конфігурації перекладач пропускає файли. Остаточна команда Git не повинна виробляти diff і має завершитися успішно.
