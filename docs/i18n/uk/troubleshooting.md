# Усунення неполадок

Використовуйте цю сторінку, коли запуск перекладу виконується несподівано успішно, зазнає невдачі під час конфігурації або створює результати, які потребують перегляду.

## Почніть тут

1. Спочатку запустіть сфокусовану команду, наприклад `translate -l "ko" -md`.
2. Додайте `-d` для відлагоджувальних журналів у консолі.
3. Додайте `-s`, щоб зберегти журнали відлагодження у `<root-dir>/logs/`.
4. Запустіть `co-op-review` після перекладу, щоб перевірити актуальність, структуру та локальні посилання.

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## Помилки конфігурації

### Немає постачальника мовної моделі

Помилка:

```text
No language model configuration found.
```

Виправлення:

- Налаштуйте Azure OpenAI, OpenAI або Anthropic.
- Переконайтеся, що змінні присутні в середовищі, де виконується команда.
- Для локального використання помістіть їх у `.env` в корені проекту.

Див. [Налаштування](configuration.md).

### Переклад зображень без Azure AI Vision

Помилка:

```text
Image translation requested but Azure AI Service is not configured.
```

Виправлення:

- Додайте `AZURE_AI_SERVICE_API_KEY`.
- Додайте `AZURE_AI_SERVICE_ENDPOINT`.
- Або запустіть команду тільки для тексту, наприклад `translate -l "ko" -md`.

### Неправильний ключ або кінцева точка

Симптоми можуть включати код `401`, приховані помилки дозволів або помилки доступу до кінцевої точки.

Виправлення:

- Переконайтеся, що ключ належить тому самому ресурсу Azure, що й кінцева точка.
- Переконайтеся, що ресурс підтримує Vision при використанні `-img`.
- Переконайтеся, що ім'я розгортання Azure OpenAI та версія API відповідають вашому розгортанню.
- Запустіть із журналами відлагодження: `translate -l "ko" -md -d -s`.

## Жодні файли не були перекладені

Типові причини:

- Обрані параметри не відповідають вашим файлам.
- Існуючі перекладені файли вже присутні.
- Файли-джерела знаходяться в виключених директоріях.
- Команда запущена не з кореневого каталогу проекту.

Перевірки:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

Використовуйте `--root-dir`, коли команда запускається поза кореневим каталогом проекту.

## Непередбачена поведінка посилань

Переписування посилань залежить від обраних типів контенту:

- `-nb` включено: посилання на ноутбуки можуть вказувати на перекладені ноутбуки.
- `-nb` виключено: посилання на ноутбуки можуть залишатися спрямованими на вихідні ноутбуки.
- `-img` включено: посилання на зображення можуть вказувати на перекладені зображення.
- `-img` виключено: посилання на зображення можуть залишатися спрямованими на вихідні зображення.

Запустіть повний переклад контенту, коли всі внутрішні посилання повинні віддавати перевагу перекладеним версіям:

```bash
translate -l "ko" -md -nb -img
```

Запустіть перевірку посилань після перекладу:

```bash
co-op-review -l "ko"
```

## Проблеми з відображенням Markdown

Якщо перекладений Markdown відображається неправильно:

- Перевірте, що frontmatter починається і закінчується `---`.
- Перевірте, що кількість маркерів блоків коду збігається між вихідними та перекладеними файлами.
- Запустіть `co-op-review` для виявлення поширених проблем зі структурою.
- Перекладіть конкретний файл повторно, якщо вихід було пошкоджено.

```bash
co-op-review -l "ko" --format github
```

## GitHub Action запущено, але пул-реквест не було створено

Якщо `peter-evans/create-pull-request` повідомляє, що гілка не випереджає базову, робочий процес не знайшов файлів для коміту.

Можливі причини:

- Запуск перекладу не дав змін.
- `.gitignore` виключає `translations/`, `translated_images/` або перекладені ноутбуки.
- `add-paths` не відповідає згенерованим каталогам вихідних файлів.
- Крок перекладу завершився раніше.

Виправлення:

1. Переконайтеся, що згенеровані файли існують у `translations/` або `translated_images/`.
2. Переконайтеся, що `.gitignore` не ігнорує згенеровані вихідні файли.
3. Використовуйте відповідні `add-paths`:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. Тимчасово додайте прапорці відлагодження до команди translate:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. Переконайтеся, що дозволи робочого процесу включають:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## Якість перекладу

Машинні переклади можуть потребувати людської перевірки. Використовуйте `evaluate` лише якщо вам потрібне експериментальне оцінювання якості та робочі процеси для виправлення сегментів з низькою довірою.

!!! warning "Експериментальний"
    `evaluate` може використовувати перевірки на основі правил і LLM, а його модель оцінювання та поведінка з метаданими можуть змінюватися. Не включайте його в обов'язкові CI-ворота, якщо ваш робочий процес не готовий до змін.

Для детермінованих перевірок у CI замість цього використовуйте `co-op-review`.
