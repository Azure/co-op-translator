# ایک چھوٹے منصوبے کا ترجمہ، ترمیم اور جائزہ لیں

دو مختصر Markdown فائلوں اور ایک ہدفی زبان سے شروع کریں۔ آپ دیکھیں گے کہ ترجمے کہاں لکھے جاتے ہیں، جب ماخذ تبدیل ہوتا ہے تو کیا ہوتا ہے، اور نتیجہ کیسے جانچا جائے۔

## ریکارڈ شدہ نتائج

یہ مثال 19 ستمبر 2026 کو Co-op Translator 0.21.0 اور Azure OpenAI (`gpt-5-mini`) کے ساتھ چلائی گئی۔ بغیر تبدیل کیے گئے CLI کمانڈز Click کے `CliRunner` کے ذریعے بنائے گئے wheel اور موجود Python انحصارات استعمال کرتے ہوئے بلائے گئے۔

| مرحلہ | نتیجہ |
| --- | --- |
| پیش نظارہ | Exit 0; ماڈل ترجمہ درخواست نہیں کی گئی |
| ابتدائی ترجمہ | Exit 0; 27.36 سیکنڈ |
| ابتدائی جائزہ | Exit 0 |
| README میں ترمیم اور جائزہ | Exit 1; پرانا ترجمہ معلوم ہوا |
| ترجمہ اپ ڈیٹ | Exit 0; 22.17 سیکنڈ |
| اپ ڈیٹ کے بعد جائزہ | Exit 0; کوئی غلطیاں یا انتباہات نہیں |
| غیر تبدیل شدہ گائیڈ | README اپ ڈیٹ سے پہلے اور بعد میں بائٹس یکساں تھیں |
| دوبارہ چلائیں | Exit 0; تمام ترجمہ فائلوں کے لیے ہیش یکساں تھے |

یہ الگ الگ رنز کے ماپ ہیں، کارکردگی کی ضمانتیں نہیں۔ سیٹ اپ وقت شامل نہیں ہے؛ فراہم کنندہ کی بلنگ ماپی نہیں گئی۔ بغیر تبدیلی کے رن پھر بھی فراہم کنندہ کی صحت کی جانچ کر سکتا ہے۔

جائزہ لیں [ابتدائی ترجمہ](../../assets/demo/before.txt)، [اپ ڈیٹ شدہ ترجمہ](../../assets/demo/after.txt)، [مکمل ترجمہ فرق](../../assets/demo/update.diff)، [پرانا جائزہ](../../assets/demo/review-stale.txt)، [حتمی جائزہ](../../assets/demo/review-after.txt)، اور [رن کی تفصیلات](../../assets/demo/results.json)۔ مکمل فائل کے ترجمے سے دیگر الفاظ بدل سکتے ہیں، جیسا کہ حاصل شدہ فرق دکھاتا ہے۔ دونوں متنی اشیاء جنریٹ شدہ ڈس کلیمر کو برقرار رکھتی ہیں۔

انسانی جائزہ اب بھی اہم ہے: حاصل شدہ اپ ڈیٹ میں `[사용 가이드](guide.md)을` استعمال ہوا؛ کوریائی حرفِ ربط کو `[사용 가이드](guide.md)를` ہونا چاہیے۔ متنی اشیاء اس آؤٹ پٹ کو بغیر ترمیم برقرار رکھتی ہیں، بجائے اس کے کہ ماڈل کے آؤٹ پٹ کو ایک ترمیم شدہ ترجمہ کے طور پر پیش کیا جائے۔ اس ساختی جائزے نے اس الفاظی مسئلے کے باوجود پاس کر لیا۔

## 1. ایک چھوٹا فولڈر تیار کریں

Python 3.11–3.14 استعمال کریں اور [ورچوئل ماحول کی ترتیب](configuration.md#local-runtime-setup)۔ اس مثال کے لیے استعمال شدہ ورژن انسٹال کریں:

```bash
python -m pip install co-op-translator==0.21.0
mkdir translation-demo
cd translation-demo
git init
```

اس فولڈر میں [README.txt](../../assets/demo/README.txt) اور [guide.txt](../../assets/demo/guide.txt) کو ڈاؤن لوڈ کریں، انہیں `README.md` اور `guide.md` کے طور پر محفوظ کریں۔ یہ چھوٹے خیالی پروجیکٹ دستاویزات ہیں; کسی ایپلیکیشن کی تنصیب کی ضرورت نہیں ہے۔

README میں ایک کوڈ بلاک اور `guide.md` کا لنک شامل ہے۔ اس کا آخری جملہ ہے:

```text
Notes are saved locally.
```

صرف یہ دو ماخذ دستاویزات اسی فولڈر میں رکھیں۔ تمام مندرجہ ذیل کمانڈز `translation-demo` کے اندر چلیں گی اور Bash اور PowerShell میں کام کریں گی۔

## 2. کریڈینشلز کے بغیر پیش نظارہ

```bash
translate -l "ko" -md --dry-run
```

پریویو بغیر ماڈل کو کال کیے یا ترجمے لکھے ترجمہ کے کام کا اندازہ لگاتا ہے۔ ٹوکن اندازے بلنگ کوٹ نہیں ہیں۔ پہلی بار چلانے پر دونوں Markdown فائلوں کو نئی کام کے طور پر شناخت ہونا چاہیے۔

## 3. ایک فراہم کنندہ منتخب کریں اور ترجمہ کریں

ایک فراہم کنندہ [کنفیگریشن گائیڈ](configuration.md) کے مطابق ترتیب دیں: Azure OpenAI، OpenAI، یا Anthropic۔ OpenAI اور Anthropic متن کے ترجمے کے لیے Azure اکاؤنٹ کی ضرورت نہیں ہے۔ اس مثال کے لیے امیج سروسز درکار نہیں ہیں۔

اگر آپ لوکل `.env` فائل استعمال کرتے ہیں تو `.env` کو اس فولڈر کے `.gitignore` میں شامل کریں۔ ترجمہ کالز آپ کے فراہم کنندہ اکاؤنٹ استعمال کرتی ہیں اور چارجز لاگو ہو سکتے ہیں۔

```bash
translate -l "ko" -md
co-op-review -l "ko"
```

کھولیں `translations/ko/README.md` اور `translations/ko/guide.md`۔ کوریائی الفاظ، کوڈ بلاک، اور ترجمہ شدہ README سے ترجمہ شدہ گائیڈ کی طرف لنک چیک کریں۔ آؤٹ پٹ کی عبارت ماڈل کے حساب سے مختلف ہوتی ہے۔

`co-op-review` تازگی، ساخت، اور لوکل لنکس چیک کرتا ہے۔ پاس ہونے والا نتیجہ لسانی درستگی کی ضمانت نہیں دیتا۔ جاری رکھنے سے پہلے رپورٹ شدہ کسی بھی غلطی کو حل کریں۔

کامیاب بنیادی حالت کو Git کے ساتھ ریکارڈ کریں (ضرورت ہو تو پہلے اپنی Git شناخت ترتیب دیں):

```bash
git add README.md guide.md translations
git commit -m "Record initial Korean translation"
```

## 4. ماخذ تبدیل کریں

`README.md` میں `Notes are saved locally.` کو اس کے ساتھ تبدیل کریں:

```text
Notes are saved locally as Markdown files.
```

`guide.md` کو بغیر تبدیلی کے چھوڑ دیں۔ پھر چلائیں:

```bash
co-op-review -l "ko"
translate -l "ko" -md --dry-run
```

جائزے کو README کے ترجمے کو پرانا ظاہر کرنا چاہیے اور ناکامی کے ساتھ ایگزٹ کرنا چاہیے۔ یہ متوقع عبوری حالت ہے۔ پریویو کو تبدیل شدہ README کے لیے کام کی نشاندہی کرنی چاہیے۔

## 5. اپ ڈیٹ کریں اور فرق کا معائنہ کریں

```bash
translate -l "ko" -md
git diff -- README.md translations/ko/README.md
git diff -- translations/ko/guide.md
co-op-review -l "ko"
```

حقیقی فرق کا معائنہ کریں: ڈیفالٹ CLI تبدیل شدہ فائل کو دوبارہ ترجمہ کرتا ہے، لہٰذا ماڈل اس فائل کے دیگر الفاظ بھی درست کر سکتا ہے۔ غیر تبدیل شدہ گائیڈ میں کوئی فرق نہیں ہونا چاہیے۔ جائزہ اب README کو پرانا رپورٹ نہیں کرنا چاہیے؛ کسی بھی دوسرے دریافت شدہ مسائل کی تفتیش کریں بجائے کہ انہیں نظرانداز کریں۔

انسانى Markdown ترمیمات کا بلاک سطح پر تحفظ [Python API](api.md) میں ایک اختیاری translation state provider کا تقاضہ کرتا ہے۔ یہ CLI کمانڈز کے ذریعے فعال نہیں ہے۔

## 6. بغیر تبدیلیوں کے دوبارہ چلائیں

اپ ڈیٹ شدہ ماخذ اور ترجمہ کو Commit کریں:

```bash
git add README.md translations
git commit -m "Update Korean translation after source edit"
translate -l "ko" -md
git diff --exit-code -- translations
```

موجودہ تراجم اور غیر تبدیل شدہ کنفیگریشن کے ساتھ، مترجم فائلوں کو اسکپ کرتا ہے۔ آخری Git کمانڈ کو کوئی فرق پیدا نہیں کرنا چاہیے اور کامیابی کے ساتھ ایگزٹ ہونا چاہیے۔
