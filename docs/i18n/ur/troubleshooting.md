# خرابیوں کا ازالہ

اس صفحے کو استعمال کریں جب ترجمہ کا عمل غیر متوقع طور پر کامیاب ہو جائے، کنفیگریشن کے دوران ناکام ہو، یا ایسی آؤٹ پٹ پیدا کرے جس کا جائزہ درکار ہو۔

## یہاں سے شروع کریں

1. پہلے ایک ہدف شدہ کمانڈ چلائیں، جیسے `translate -l "ko" -md`.
2. کنسول ڈیبگ لاگز کے لیے `-d` شامل کریں۔
3. ڈیبگ لاگز کو `<root-dir>/logs/` کے تحت محفوظ کرنے کے لیے `-s` شامل کریں۔
4. تازگی، ساخت، اور مقامی لنکس کی جانچ کے لیے ترجمے کے بعد `co-op-review` چلائیں۔

```bash
translate -l "ko" -md -d -s
co-op-review -l "ko"
```

## کنفیگریشن کی غلطیاں

### کوئی زبان کا ماڈل فراہم کنندہ نہیں

خرابی:

```text
No language model configuration found.
```

حل:

- Azure OpenAI، OpenAI، یا Anthropic کو کنفیگر کریں۔
- تصدیق کریں کہ وہ متغیرات اسی ماحول میں ہیں جہاں کمانڈ چل رہی ہے۔
- مقامی استعمال کے لیے انہیں پراجیکٹ روٹ میں `.env` میں رکھیں۔

دیکھیں [کنفیگریشن](configuration.md).

### Azure AI Vision کے بغیر امیج کا ترجمہ

خرابی:

```text
Image translation requested but Azure AI Service is not configured.
```

حل:

- `AZURE_AI_SERVICE_API_KEY` شامل کریں۔
- `AZURE_AI_SERVICE_ENDPOINT` شامل کریں۔
- یا ایک صرف متن وار کمانڈ چلائیں جیسے `translate -l "ko" -md`.

### غیر معتبر کلید یا اینڈپوائنٹ

علامات میں `401`، اجازت سے متعلق ریڈیکٹڈ غلطیاں، یا اینڈپوائنٹ تک رسائی کی غلطیاں شامل ہو سکتی ہیں۔

حل:

- تصدیق کریں کہ کلید اسی Azure ریسورس سے متعلق ہے جو اینڈپوائنٹ کے لیے ہے۔
- جب `-img` استعمال کر رہے ہوں تو تصدیق کریں کہ ریسورس Vision کو سپورٹ کرتا ہو۔
- تصدیق کریں کہ Azure OpenAI کی ڈیپلائمنٹ کا نام اور API ورژن آپ کی ڈیپلائمنٹ سے میل کھاتے ہوں۔
- ڈیبگ لاگز کے ساتھ چلائیں: `translate -l "ko" -md -d -s`.

## کوئی فائلیں ترجمہ نہیں ہوئیں

عام وجوہات:

- منتخب کردہ فلیگز آپ کی فائلوں سے مطابقت نہیں رکھتے۔
- پہلے سے ترجمہ شدہ فائلیں موجود ہیں۔
- ماخذ فائلیں مستثنیٰ ڈائریکٹریز کے تحت ہیں۔
- کمانڈ غلط پراجیکٹ روٹ سے چل رہی ہے۔

تصدیق:

```bash
translate -l "ko" -md --dry-run
translate -l "ko" -nb --dry-run
translate -l "ko" -img --dry-run
```

جب کمانڈ پراجیکٹ روٹ کے باہر چلائی جائے تو `--root-dir` استعمال کریں۔

## غیر متوقع لنک کا رویہ

لنک ری رائٹنگ منتخب شدہ مواد کی اقسام پر منحصر ہوتی ہے:

- `-nb` شامل ہے: نوٹ بک لنکس ترجمہ شدہ نوٹ بکس کی طرف اشارہ کر سکتے ہیں۔
- `-nb` خارج ہے: نوٹ بک لنکس ماخذ نوٹ بکس کی طرف رہ سکتے ہیں۔
- `-img` شامل ہے: امیج لنکس ترجمہ شدہ تصاویر کی طرف اشارہ کر سکتے ہیں۔
- `-img` خارج ہے: امیج لنکس ماخذ تصاویر کی طرف رہ سکتے ہیں۔

جب تمام اندرونی لنکس ترجیحاً ترجمہ شدہ آؤٹ پٹس کی طرف ہونے چاہئیں تو مکمل مواد کا ترجمہ چلائیں:

```bash
translate -l "ko" -md -nb -img
```

ترجمے کے بعد لنک کا جائزہ لیں:

```bash
co-op-review -l "ko"
```

## Markdown رینڈرنگ کے مسائل

اگر ترجمہ شدہ Markdown غلط طور پر رینڈر ہو رہا ہو:

- چیک کریں کہ فرنٹ میٹر `---` سے شروع اور ختم ہوتا ہے۔
- چیک کریں کہ کوڈ فینس کی گنتی ماخذ اور ترجمہ شدہ فائلوں میں میل کھاتی ہو۔
- عام ساختی مسائل پکڑنے کے لیے `co-op-review` چلائیں۔
- اگر آؤٹ پٹ خراب ہو گیا ہو تو مخصوص فائل کو دوبارہ ترجمہ کریں۔

```bash
co-op-review -l "ko" --format github
```

## GitHub Action چل گیا لیکن کوئی Pull Request نہیں بنائی گئی

اگر `peter-evans/create-pull-request` رپورٹ کرتا ہے کہ برانچ بیس کے مقابلے میں آگے نہیں ہے، تو ورک فلو نے کمٹ کرنے کے لیے کوئی فائلیں نہیں پائیں۔

ممکنہ وجوہات:

- ترجمہ کے دوران کوئی تبدیلیاں پیدا نہیں ہوئیں۔
- `.gitignore` `translations/`, `translated_images/`، یا ترجمہ شدہ نوٹ بکس کو خارج کرتا ہے۔
- `add-paths` جنریٹڈ آؤٹ پٹ ڈائریکٹریز کے ساتھ میل نہیں کھاتا۔
- ترجمہ کا مرحلہ قبل از وقت ختم ہو گیا۔

حل:

1. تصدیق کریں کہ جنریٹڈ فائلیں `translations/` یا `translated_images/` میں موجود ہیں۔
2. تصدیق کریں کہ `.gitignore` جنریٹڈ آؤٹ پٹس کو نظر انداز نہیں کرتا۔
3. مطابقت رکھنے والا `add-paths` استعمال کریں:

   ```yaml
   with:
     add-paths: |
       translations/
       translated_images/
   ```

4. عارضی طور پر ترجمہ کمانڈ میں ڈیبگ فلیگز شامل کریں:

   ```bash
   translate -l "ko" -md -d -s
   ```

5. تصدیق کریں کہ ورک فلو کی اجازتوں میں شامل ہیں:

   ```yaml
   permissions:
     contents: write
     pull-requests: write
   ```

## ترجمہ کا معیار

مشین کے ترجموں کو انسانی جائزے کی ضرورت ہو سکتی ہے۔ `evaluate` کا استعمال صرف اس وقت کریں جب آپ تجرباتی معیار اسکورنگ اور کم اعتماد والی مرمت کے ورک فلو چاہتے ہوں۔

!!! warning "Experimental"
    `evaluate` قواعد پر مبنی اور LLM پر مبنی چیکس استعمال کر سکتا ہے، اور اس کا اسکورنگ ماڈل اور میٹا ڈیٹا رویہ تبدیل ہو سکتا ہے۔ اسے ضروری CI گیٹس میں شامل نہ کریں جب تک کہ آپ کا ورک فلو تبدیلیوں کے لیے تیار نہ ہو۔

متعین CI چیکس کے لیے، اس کی بجائے `co-op-review` استعمال کریں۔
