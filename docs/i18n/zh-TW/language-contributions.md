# 貢獻語言改進

你的語言知識可以幫助改進 Co-op Translator。請從一個範例、建議的修正與說明開始，使用 [翻譯回饋表單](https://github.com/Azure/co-op-translator/issues/new?template=translation_feedback.yml)。你不需要撰寫程式碼或付費執行模型。

## 從報告到共同改善

1. 貢獻者提供原文摘錄、其翻譯，以及上下文。
2. 語言審閱者檢查意思、自然度，以及建議是否依賴特定地區或課程。
3. 維護者決定該修正應放在來源課程、共用語言說明、術語配置或翻譯程式碼中。
4. 對於共用規則，維護者會在被回報的範例及無關範例上比較變更前後的輸出。貢獻者可以在不自行執行工具的情況下檢閱這些輸出。
5. 所產生的 PR 會連結該報告並表彰提供範例與審閱的人員。部署或在使用該成果的倉庫中重新產生則為另一個步驟。

一份報告不會自動更改提示或重新生成課程翻譯。課程特定的修正應保持與該課程倉庫的連結。不要假設手動編輯會在日後重新翻譯時保留；請確認該工作流程的行為。

## 現有範例：日語 Markdown 連結

該 [日語說明檔](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/templates/language/ja.md) 指示模型翻譯連結文字，同時保留 Markdown 語法與連結目的地。例如，寫成 `[text](URL)` 的連結不得變成 `「text」（URL）`。

這是一個以正誤輸出範例為基礎的特定語言規則範例。它並不表示僅靠提示指示就能保證 Markdown 絕對正確。

該 [Markdown 提示生成器](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/utils/markdown/prompts.py) 使用小寫且修剪過的語言代碼載入 `templates/language/<language_code>.md`。若沒有對應檔案，則使用通用指示。這描述了 Markdown 提示的路徑；不要假設每個圖片或其他翻譯路徑都使用相同的指示。

該 [提示測試](https://github.com/Azure/co-op-translator/blob/main/tests/co_op_translator/utils/markdown/test_prompts.py) 檢查日語指示是否包含在內。那是驗證提示組裝，而非翻譯品質。

## 語言規則應包含什麼？

提出一個明確且可重複的修正，附上來源範例、預期行為，以及該規則不應套用的反例。保留原意、占位符、程式碼、URL 與文件結構。避免將某個人的風格偏好或某一課程的術語變成普遍適用的規則。

目前的 [詞彙表實作](https://github.com/Azure/co-op-translator/blob/main/src/co_op_translator/glossary.py) 會保護術語免於被翻譯。它不是一個源到目標的術語詞典。在向貢獻者承諾之前，先討論新的術語行為。

## 社群範例：日語產品名稱回報

在 [report #527](https://github.com/Azure/co-op-translator/issues/527) 中，@hyoshioka0128 指出一個日語翻譯將產品名稱 `Co-op Translator` 改為 `Co-op 翻訳`。該回報包含受影響文件的連結和截圖，讓問題容易定位。

貢獻者也連結了 [相關課程的 PR](https://github.com/microsoft/AZD-for-beginners/pull/109)。在議題討論中，維護者已經確認該回報，並建議調查名稱為何會改變，包括術語保護、詞彙表行為和翻譯路徑。

這顯示小型回報如何支援超越單一用詞修正的調查。這並非經驗證的前後結果，也不是證據顯示上述日語 Markdown 連結指示已修正此產品名稱問題。

你也可以用相同方式貢獻：分享原文、目前翻譯、建議修正，以及其重要性。必要時附上文件連結或截圖。你不需要在回報前診斷原因或撰寫提示。

## 採用規則前的驗證

在基準與候選執行中使用相同的來源範例、翻譯器版本、提供者/模型與生成設定，僅改變被提議的指示。記錄實際的提示變更與輸出；在需要時重複範例以區分一致效果與輸出變異。包含被回報的失敗案例、對比情境，以及已正確翻譯的範例。

| 範例 | 來源/情境 | 基準輸出 | 候選輸出 | 審閱者評估 |
| --- | --- | --- | --- | --- |
| 被回報的失敗 | 待收集 | 尚未執行 | 尚未執行 | 待處理 |
| 反例 | 待收集 | 尚未執行 | 尚未執行 | 待處理 |
| 不受影響的範例 | 待收集 | 尚未執行 | 尚未執行 | 待處理 |

將結構不變項與語言判斷分開檢查。成功的提示載入測試不是品質評估，而且一個精確的預期句子並非唯一有效的翻譯。如果缺少上下文、模型執行或語言審查，請讓提案維持待決狀態，而非聲稱問題已解決。
